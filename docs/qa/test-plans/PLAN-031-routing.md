# PLAN-031 — API routing and contract reachability

## Scope

Whether a route that exists in the source can actually be reached by a
request. Covers declaration order across all 109 API controllers.

Deliberately excludes what a route *does* once reached — authorization,
validation and tenant scoping each have their own plan. This plan asks only
the prior question: does the request arrive at the handler the author
intended?

## Risks

1. **A static route declared after a parameterised sibling is unreachable.**
   Express matches in declaration order. The request lands on the earlier
   handler with the literal bound to the parameter, and a `ParseUUIDPipe`
   answers `400 Validation failed (uuid is expected)`.

   Three properties make this expensive: it is invisible to the compiler, it
   is invisible in review (both decorators read correctly in isolation), and
   the symptom points at *validation* rather than at routing. BUG-2461 sat
   undetected because nothing called the dead route yet.

2. **A frontend calls a path the API does not serve.** Distinct from the
   above and not currently automated; it surfaces as a `404` in the
   monitoring queue rather than as a test failure.

## Preconditions

None. The check reads controller sources and does not boot Nest — which is
deliberate: booting would need the whole `AppModule` and a database, and
would only test the handlers that exist rather than the rule that must hold
for handlers not written yet.

## Test Types

- **UNIT** — the source-level invariant across every controller. Covered.
- **API** — asserting a specific route answers. Partial, and per-module
  rather than owned here.
- **E2E / BROWSER_E2E / SECURITY / PERFORMANCE** — not applicable.

## Data Requirements

None.

## Security Cases

None owned directly, but one adjacency is worth naming: a shadowed route
means requests arrive at a *different* handler than the author intended, and
that handler carries different `@Permissions` and `@RequirePermission`
decorators. The observed case failed closed (a `400` from the pipe), but the
general shape need not — two handlers whose guards differ and whose paths
overlap is an authorization question, not only a routing one.

## Negative Cases

The invariant must also fail correctly. Its own suite asserts it finds more
than 100 controllers, because the classic way a source-scanning check goes
quietly green is a broken directory traversal — it then reports zero findings
and passes for ever.

The scanner must blank comments before parsing. This codebase's house style
is substantial explanatory comments, and a fix comment that quotes the
offending decorator will otherwise be read as a real declaration.
