# QA-REPORTING-002 — Reporting scope sanitiser fails closed on an unverifiable predicate

## Preconditions

A reporting data source that does not name `businessUnitIdField`, and one whose root model has no `ownerTeamId` column.

## Steps

1. Resolve a scope for a BUSINESS_UNIT reader against the source that omits the field name.
2. Resolve a scope for a source whose model lacks `ownerTeamId`.
3. Read the resulting `where` in both cases.

## Expected Result

The business-unit term survives, because the sanitiser mirrors the defaults `buildScopedAccessWhere` applies rather than only the options a source declares. The `ownerTeamId` term is dropped inside its `OR` while the three real ownership terms remain. An unverifiable predicate is **replaced** with the poison pill, never removed.

## Notes

Dropping a term from an `AND` widens rather than fails closed. Replacing narrows in an `OR` and fails closed in an `AND`. Test at a scope narrower than TENANT: at TENANT this bug is invisible, which is how it first shipped.
