# QA-PLATFORM-013 — The unread notification count does not depend on who asks

## Preconditions

At least one notifiable failure — a failed provisioning run, billing operation
or webhook — followed by enough routine platform events that more than twenty
exist since it.

## Steps

1. `npm --workspace api run test -- notification-count`
2. Sign in to Platform Admin and look at the bell **before touching it**.
3. Click the bell.
4. Compare the badge before and after.
5. Call `/api/platform/events/notifications?limit=1` and `?limit=50` and compare
   `unreadCount`.

## Expected Result

Automated: the scan takes a fixed limit and never a multiple of the page size;
the page is still sliced from it; a truncated scan is reported.

Steps 2–4: the badge shows the same count before and after clicking. The act of
looking must not create the news.

Step 5: both responses carry the same `unreadCount`.

## Notes

Step 5 is the one that reproduces the original defect directly and takes ten
seconds. The badge polls with `limit=1`; the popover asks for six. The old scan
was `limit * 20`, so the same reader was counted over twenty events and then a
hundred and twenty.

Consideration: with fewer than twenty events since the notifiable one, the old
code passed too. The precondition is the test.
