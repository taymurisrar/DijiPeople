# QA-SETTINGS-033 — Customization package moves DEV to UAT: release, export, staged import, upgrade, re-import, rollback, uninstall

## Preconditions

A throwaway PostgreSQL database at the current migration. Two workspaces of one
customer — DEV (DEVELOPMENT) and UAT (UAT) — and an unrelated third tenant, each
with an administrator holding the customization package keys.

## Steps

1. DEV: create package mis_customizations (publisher MIS, 1.0.0); create module
   misAsset, field mis_grade, field mis_employeeGrade on Employees, view
   seniorAssets — all in the package.
2. DEV: release 1.0.0; export it twice.
3. UAT: analyze the file; execute the import.
4. UAT: analyze and execute the same file again.
5. DEV: change a field label, add a field, release 1.1.0; UAT: analyze and import.
6. UAT: analyze the 1.0.0 file again.
7. Third tenant: create misAsset.mis_grade as a number in a local package, then
   analyze 1.1.0.
8. Analyze a tampered, a truncated and a format-4 copy of the file.
9. Import a crafted package whose two fields both claim the primary name.
10. Add a required URL environment variable and a secret, release 1.2.0, import
    without and then with a UAT value.
11. Install a package that depends on mis_customizations; try to uninstall
    mis_customizations; add a record to misAsset; uninstall the dependent.
12. As the third tenant, read, export, execute and list against DEV/UAT ids.

## Expected Result

- 2: both exports are byte-identical and contain no tenant, user or row ids.
- 3: plan INSTALL, nothing changes until execute; afterwards the module, fields
  and view exist in UAT, the package is Installed 1.0.0, and the published
  snapshot includes misAsset.
- 4: REINSTALL with no created or updated components; no rows duplicated.
- 5: UPGRADE; the new field NEW, the edited field UPDATE, the view MATCHING;
  UAT ends at 1.1.0 with the new label.
- 6: BLOCKED as a downgrade; executing is refused; UAT stays at 1.1.0.
- 7: BLOCKED with a conflict naming the owning package; nothing written.
- 8: each refused with a reason naming the checksum, the JSON or the format.
- 9: the import fails, is rolled back, names the failing field; nothing written.
- 10: the DEV value and secret are not in the file; import is blocked until the
  UAT value is given; each environment resolves its own value.
- 11: uninstall is refused naming "MIS Payroll → depends on → MIS
  Customizations" and the records; the dependent uninstalls.
- 12: every call answers not found.
