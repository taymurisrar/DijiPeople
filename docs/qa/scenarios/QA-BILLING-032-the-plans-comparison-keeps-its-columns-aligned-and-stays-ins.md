# QA-BILLING-032 — The plans comparison keeps its columns aligned and stays inside the viewport

## Preconditions

The plans screen with at least three plans and a feature catalog spanning
several categories, viewed at 390px, 768px, 1024px and 1180px.

## Steps

1. Open `/settings/subscription/plans` at 390px and attempt to scroll the
   document horizontally.
2. Repeat at 768px and 1024px.
3. At 1180px, count the columns the plan cards render in.
4. Scroll the feature comparison and check where each plan's column starts in
   each category block.

## Expected Result

The document's scroll width equals the viewport width at 390px, 768px and
1024px. The plan cards render in more than one column at 1180px rather than
stacking into a single column of roughly 1,400px of vertical scroll.

Every plan column in the comparison has the same left offset in every category,
because the comparison is one table with category header rows rather than one
table per category. It scrolls in one place, not six, and its header row stays
visible over the feature rows.

## Notes

Partially automated, and the split matters. The spec is source-level: it pins
the grid breakpoints, the containment chain and the single-table structure.
`apps/web` has no jsdom, so the scroll-width measurement itself cannot be
asserted there and still needs a live-browser pass — which did not happen when
this landed, because the browser server was unavailable that session.

The containment half repeats BUG-1960's lesson in a different screen: the
minimum-width reset has to be applied at every layer between a wide child and the
constrained grid track, not only on the child's own wrapper.
