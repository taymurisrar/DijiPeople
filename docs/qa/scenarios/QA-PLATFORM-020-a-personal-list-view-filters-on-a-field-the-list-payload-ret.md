# QA-PLATFORM-020 — A personal list view filters on a field the list payload returns

## Preconditions

A platform operator who has created at least one tenant and one plan.

## Steps

1. Open Tenants in Platform Admin and select the "Created by me" view.
2. Open Plans and select the same view.
3. For every module offering a personal view, compare the field
   `PLATFORM_MODULE_VIEW_RULES` filters on against the fields the module's list
   payload actually returns.

## Expected Result

- Both views list the records that operator created, rather than nothing.
- Every field a view rule filters on is present in the corresponding list
  payload. A rule naming an absent field silently matches no row, which renders
  as a working control that selects nothing.

## Notes

The list and detail mappers differed: `mapTenantDetail` returned `createdById`
and `mapTenantSummary` did not, so the record page never showed the symptom and
the list was empty for everyone.

Same shape as the "Active" view that once matched a status a module never used.
The registry already carried a comment warning about this class of defect, which
is the useful part of the lesson: naming the pattern did not prevent the next
instance — only a check that resolves rule fields against payloads does.
