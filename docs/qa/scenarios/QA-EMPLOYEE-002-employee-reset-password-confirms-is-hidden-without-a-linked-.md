# QA-EMPLOYEE-002 — Employee Reset Password confirms, is hidden without a linked user and reports a refusal in place

## Preconditions

- An administrator with employee account-action rights.
- Employee X with no linked user (demo tenant: EMP-0001).
- Employee Y with a linked user who has signed in.
- Employee Z with a linked user who has never signed in.
- Tenant email delivered to a controlled mailbox only.

## Steps

1. Open employee X's record and read the command bar.
2. Open employee Y's record, click Reset Password, then Cancel.
3. Click Reset Password again and confirm with Send link.
4. Force a refusal: intercept `POST /api/employees/{id}/send-reset-password-link`
   to return 400 with the API error envelope, and click Send link.
5. Intercept the same request to return 500, and click Send link.
6. Open employee Z's record and read the command bar.

## Expected Result

- Step 1: Reset Password is not offered.
- Step 2: a confirmation opens; Cancel sends no request.
- Step 3: one request is sent and a success notice appears.
- Step 4: the API's message appears in place, exactly once; no
  `POST /api/error-logs/client` is sent.
- Step 5: the technical error path appears and the error is logged.
- Step 6: Send Invitation is offered.
