# QA-PLATFORM-010 — Previewing sample data cannot change the template

## Preconditions

Platform Admin, and a contract template with at least one placeholder and one
saved version.

## Steps

1. `npm --workspace admin run test -- template-preview`
2. Manual: open the template, note the exact document text.
3. Press **Preview sample data**. Observe the *first* paint.
4. Press **Return to editing**. Observe the first paint.
5. Repeat steps 3–4 three times.
6. Press **Preview sample data**, then press **Save** without returning to
   editing.
7. Reload the page and read the document.

## Expected Result

Steps 3–5: each toggle is correct on its first paint. No frame shows the
previous content.

Step 7: the document still contains `{{...}}` placeholders. It does **not**
contain "Gulf Horizon", "Amal Hassan" or any other sample value.

The preview renders collections as lists and percentages with their sign — the
same as the generated document, because it substitutes the API's `exampleHtml`.

## Notes

Step 6 is the one that matters and the one a casual test skips: the old
implementation kept the real template in a second state variable and restored it
on exit, so the template survived only as long as that path ran.

Consideration: the automated half is structural — assertions over the component
source, because `apps/admin` jest has no jsdom ([[ITEM-0001]]). It pins the two
shapes that caused the faults and cannot observe a paint. Steps 3–7 are the only
real verification and are manual on purpose.
