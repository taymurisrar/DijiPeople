# QA-BILLING-012 — A self-service customer record carries what the customer bought

## Preconditions

None. `resolveCustomer` is driven directly with a recording transaction client.

## Steps

1. Resolve a customer for a submission that matches no existing account.
2. Resolve one for an existing account whose commercial columns are null.
3. Resolve one for an existing account that already holds a plan and cycle.

## Expected Result

Case 1 creates the account with `selectedPlanId`, `preferredBillingCycle` and
`originChannel` set from the order's price, alongside the trimmed company name,
country, contact identity and the organization profile the wizard collected.

Case 2 fills the three empty columns.

Case 3 writes none of them. `openOnboarding` is what states the plan
authoritatively, at payment; a later abandoned checkout must not rewrite what a
paying customer actually bought.

## Notes

The comparison that matters is against
`PlatformLifecycleService.convertLeadToCustomer`, which writes twenty-two
columns for the sales-assisted funnel. Any new commercial column added there
should be considered for here in the same change — the two paths producing
different records is the defect, not the specific three columns.

`originChannel` is `WEBSITE` and never `PARTNER_REFERRAL`: the subscribe flow
captures no referral code ([[BUG-0281]]), so the latter would be a guess about
who earned a commission.
