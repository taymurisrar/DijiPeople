# QA-PLATFORM-014 — Every monitoring metric names what it counts and narrows the table

## Preconditions

Platform Admin with incidents recorded, ideally several thousand.

## Steps

1. `npm --workspace admin run test -- monitoring-metrics`
2. Click **Monitoring** in the sidebar.
3. Read the five tiles above the incident table.
4. Click **Critical**. Click it again.
5. Click **Not yet triaged**, then **Resolved**.
6. Change the time window and re-read the tiles.

## Expected Result

Step 2: you land on **Overview**, not on the incident queue. The sidebar item
stays highlighted on every monitoring page.

Step 3: each tile names what it counts and states the window it counted over. No
tile is labelled with a column name. No two tiles show the same figure under
different names without that being genuinely true.

Step 4: the first click filters to critical incidents and the tile is marked as
the filter in force — in text, not colour alone. The second click clears it.

Step 6: every tile's stated window changes with it.

## Notes

The default window is deliberately **unchanged** by this work. "All time" over
12,005 incidents is a firehose rather than a queue, and narrowing it would make
the page open on less than everything — a product decision about what the queue
is for, not a UX repair. If you think it should change, raise it as an ITEM.

Consideration: step 3's "no two tiles show the same figure" is a judgement, not
an assertion. "Not yet triaged" equalling the total is *correct* when nothing
has been triaged. What was wrong before was calling it "Open investigations" and
placing it beside "Matching incidents" so neither said which was the queue.
