# QA-RUNTIME-043 — A section hosting a self-titling widget shows its name once

## Preconditions

`apps/web` builds and its jest project runs.

## Why This Scenario Exists

`section.labelVisible` exists on `FormSectionMetadata` for exactly one
reason — suppressing a section's own heading when its only content already
draws one — and `runtime-metadata-form-renderer.tsx` honoured it in only one
of the three branches that render a section heading. The employee record's
Profile, Timeline, Reporting Hierarchy and Agent Desktop sections each have
`fields: []` and a single self-titling system widget as their only content,
so each printed its name twice; the profile pair used two different words
for the same control ("Profile Image" from the section, "Profile Photo" —
rendered uppercase — from the widget).

## Steps

1. `npm --workspace web run test -- --testPathPatterns labelvisible`

Within that suite: `runtime-metadata-form-renderer.tsx`'s source is checked
for `section.labelVisible !== false` appearing in all three heading-rendering
branches (not just the one that already had it), and that the custom-content
branch keeps its guard against an empty label. `mapEmployeeForms([])`'s
built-in system form is checked directly: each of the four self-titling-
widget sections carries `labelVisible: false` and a specific label, a section
with no self-titling widget is untouched, and the profile control's name
("Profile Photo") matches between the section metadata and
`runtime-profile-image-card.tsx`'s own heading.

## Expected Result

No section renders its heading twice. `labelVisible: false` sections
(`profile-image`, `timeline`, `reporting-hierarchy`, `agent-desktop`) render
no section-level heading, letting the widget's own heading stand alone. Every
other section keeps its heading exactly as before. The profile control has
one name, used identically by the section and the widget.

## Negative Case

Reverting either of the two fixed branches in
`runtime-metadata-form-renderer.tsx` to ignore `labelVisible`, or removing
`labelVisible: false` from any of the four sections in
`employee-metadata.adapter.ts`, fails the corresponding assertion — the
occurrence-count check catches the branch reverted to unconditional
rendering, and the per-section `it.each` catches a section metadata revert.

## Notes

Not verified in a browser — `apps/web`'s jest has no jsdom, so "no heading
appears twice" is asserted at the source and metadata level rather than by
counting rendered `<h4>` elements the way [[BUG-3412]]'s own evidence did.
This repo's own knowledge base flags a `replace(..., 1)`-style edit landing
on the wrong one of two near-identical lines as a known failure mode here;
the occurrence-count assertion exists specifically so a fix aimed at the
wrong branch fails loudly rather than passing by accident.

`agent-desktop` was fixed alongside the three sections [[BUG-3412]] named,
found by applying the same rule rather than patching only the reported
cases — it is not the default tab, so it did not appear in that bug's
original heading count.
