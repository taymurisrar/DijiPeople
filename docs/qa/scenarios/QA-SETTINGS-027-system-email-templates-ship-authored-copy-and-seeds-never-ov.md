# QA-SETTINGS-027 — System email templates ship authored copy and seeds never overwrite edited or tenant templates

## Preconditions

- A throwaway database restored with the pre-release template state: SYSTEM
  templates with placeholder bodies, and per-tenant `AUTH_*` rows with
  `isSystem = true` at tenant scope.
- One tenant-owned template edited by a person.
- Email delivered to a controlled mailbox only.

## Steps

1. Run `npm --workspace api run seed:config`.
2. Run it a second time.
3. Query `EmailTemplate` for SYSTEM rows, the per-tenant auth rows and the
   tenant-owned template.
4. Request a password reset for a user on the tenant.
5. As a tenant administrator, Customize the Password reset template.
6. Put placeholder wording into one ACTIVE SYSTEM row by hand and run
   `seed:config` again.

## Expected Result

- Step 1-2: no verification error; the second run logs 0 created, 11 refreshed,
  0 left unchanged.
- Step 3: every SYSTEM row matches
  `docs/tasks/TASK-0031-streams/email-copy-for-owner-review.md`; ACTIVE for
  activation, password reset, invoice, payslip, scheduled report and support
  case; DRAFT for the other five. Per-tenant `AUTH_*` rows carry key
  `…retired-tenant-default` and status ARCHIVED. The tenant-owned template is
  unchanged.
- Step 4: the email arrives with the authored copy.
- Step 5: a DRAFT tenant copy is created with the same key; no unique-constraint
  error.
- Step 6: the seed fails verification naming the row.
