# QA-ATTENDANCE-001 — Attendance coordinates never leak through the day payload

## Preconditions

A tenant with an employee, a shift and a work site. Location evidence recorded
for the day with known coordinates — the suite plants `latitude: 25.3,
longitude: 51.6`. The reader is an **HR** user, who holds the ordinary
attendance permission and *not* the separate location-evidence permission.

## Steps

1. Record location evidence for the day with the planted coordinates.
2. Punch in and out, and reconcile the day.
3. Read the day back as the HR user: `engine.getDay(hrUser(), employeeId, DAY)`.
4. Walk the returned object — every key and every numeric value, at any depth,
   including inside arrays.

## Expected Result

- No key anywhere in the payload matches
  `/latitude|longitude|accuracy|coordinate/i`.
- No numeric value anywhere equals `25.3` or `51.6`.

Coordinates live behind their own permission. The ordinary attendance view shows
the business result — minutes, sessions, work mode — and a reader who lacks the
location permission must not receive coordinates as a side effect of asking for
a day.

**Assert over the parsed object, never over `JSON.stringify` output.** That is
not a style preference: the payload carries `lastReconciledAt`, generated at run
time, so a substring scan for `51.6` matches a reconciliation at `…:51.6`41Z and
fails reporting a leak that never happened. That was BUG-1364, and it failed a
CI run on a branch that changed nothing in attendance.
