# QA-ATTENDANCE-004 — Attendance check-in omits the user agent when storeUserAgent is off

## Preconditions

- A tenant whose attendance policy has `storeUserAgent: false`. Confirm it from
  `GET /api/attendance/runtime-context` rather than from the settings form — the
  form shows what was typed, the runtime context shows what the server serves.
- Location capture working (QA-ATTENDANCE-002).

## Steps

1. `GET /api/attendance/runtime-context` and confirm
   `policy.storeUserAgent` is `false`.
2. Open `/attendance` and press **Check In** with the Network tab open.
3. Read the `POST /api/attendance/check-in` request body.
4. Set `storeUserAgent` to `true` in Settings → People → Attendance, save,
   reload, and repeat steps 2-3.

## Expected Result

- Step 3: the body contains **no** `userAgent` field.
- Step 4: the body contains `userAgent`.

Both directions matter. Asserting only the "off" case would pass against a build
that had simply stopped sending the field at all, which is a different bug.
