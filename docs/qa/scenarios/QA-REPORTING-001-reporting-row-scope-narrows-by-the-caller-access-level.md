# QA-REPORTING-001 — Reporting row scope narrows by the caller access level

## Preconditions

A tenant with employees in more than one business unit, and a reader whose `employees` privilege is scoped narrower than TENANT.

## Steps

1. Resolve a reporting scope for the same data source at each `SecurityAccessLevel`: SELF, USER, TEAM, BUSINESS_UNIT, PARENT_CHILD_BUSINESS_UNIT(S), ORGANIZATION, TENANT and NONE.
2. Inspect the `where` each one produces.
3. Run a metric through the engine as a BUSINESS_UNIT reader and compare the number against the tenant-wide total.

## Expected Result

Every level below TENANT narrows the `where`; NONE yields the poison-pill id and a count of 0. No level returns `{}`. The business-unit reader sees fewer rows than the tenant total.

A scoped reader's numbers are **smaller** than they were before this fix. That is the correction, not a regression.

## Notes

The row scope comes from each data source's own `rbacEntityKey`, not from `reports`. `reports.read` opens the workspace; the data's owning entity decides the rows.
