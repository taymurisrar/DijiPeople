# QA-SECURITY-004 — Error log redaction covers national-id, bank-account and free-text secrets

## Preconditions

None — pure unit-level input construction against `sanitizeForErrorLog`.

## Steps

1. Pass an object containing `cnic`, `nationalId`, `ssn`, `taxIdentifier`,
   `bankAccountNumber`, `accountNumber`, `routingNumber`, `cardNumber`, `cvv`
   and `signingKey` fields, alongside unrelated fields `accountId` and
   `accountStatus`.
2. Pass `{ stack: 'Authorization: Bearer sk_live_abcdefghijklmnop' }`.
3. Pass a Postgres connection string containing a `user:pass@` segment.
4. Pass a Luhn-valid card number and a real IBAN embedded in free text.
5. Pass a UUID, a `req_…` trace id, and a non-Luhn 13-digit timestamp embedded
   in free text.
6. Pass a related `OutboxEvent.lastError` containing an embedded credential
   through the monitoring incident detail path.

## Expected Result

Every field in step 1 comes back `[REDACTED]`; `accountId`/`accountStatus`
are untouched. Steps 2-4 have their secret/credential segments redacted (the
connection string's host survives). Step 5's values are left untouched — the
false-positive guard. Step 6's embedded credential is redacted before it
reaches the incident detail response.
