# QA-LEGAL-003 — Every seeded legal document is publishable by the release chain

## Preconditions

None beyond the repository. This scenario is deliberately a **unit** scenario
with no database and no running service: it compares two source artefacts that
must agree, and the whole point is that it can run before anything is deployed.

The two artefacts are:

- `services/api/prisma/seed-legal.ts` — what the release chain seeds.
- The draft self-declaration predicate that `legal:publish --confirm` applies
  when deciding whether a document may be published.

## Steps

1. Run the suite:

   ```bash
   npm --workspace api run test -- src/modules/legal/seed-legal-publishable.spec.ts
   ```

2. For each of the ten documents `seed-legal.ts` emits, the suite feeds the
   seeded body to the same predicate `legal:publish` uses.

3. To confirm the scenario still has teeth, reintroduce a draft banner into any
   one document — for example a line reading
   `Draft — not published, and not legal advice` — and re-run.

## Expected Result

- Step 1: all assertions pass. Every seeded document is publishable, so
  `legal:publish --confirm` will publish rather than skip, and will not exit `2`.
- Step 3: the suite **fails**, naming the document that declares itself a draft.

That second expectation is the scenario. A suite that passes with a draft banner
present is not guarding anything, and BUG-0899 is exactly what happens when
nothing guards this: the seed and the publisher were each correct alone and
jointly impossible, and Render's `preDeployCommand` was the first thing to run
them together — in production, on a deploy that then aborted.
