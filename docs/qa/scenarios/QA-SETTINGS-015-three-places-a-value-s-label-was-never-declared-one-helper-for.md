# QA-SETTINGS-015 — Three places a value's label was never declared, one helper for the floor under all three

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-341 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

Branding: every key in `BRANDING_COLOR_KEYS`/`BRANDING_TEXT_KEYS` — not just the ten reported — resolves to a label that is never equal to the key itself, plus the ten reported labels by exact value, plus a hypothetical undeclared key to prove the fallback humanises rather than repeats. Runtime formatter: a declared optionset label wins; an undeclared optionset value and a field with no metadata at all both humanise; ordinary prose passes through unchanged. Dashboard: an enum constant humanises, an entity display name does not.

## Expected Result

The behaviour holds as REG-341 describes it. The automated guard is `apps/web/lib/runtime/runtime-value-formatter.spec.ts`; a run of that suite is sufficient evidence for this scenario.

## Why This Is Reusable

Three independent label-resolution paths each had a gap that fell through to the raw stored token. `branding-settings-form.tsx`'s `COLOR_FIELD_LABELS`/`TEXT_FIELD_LABELS` maps were missing entries for six of sixteen colour tokens and four of thirteen text fields, falling back to the bare key (`mutedTextColor`, `supportEmail`, …)
