# QA-TENANT-030 — A subscription record names its tenant plan and price

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.
- At least one subscription exists.

## Steps

1. Run `npm --workspace api run test -- subscription-record-shape`.
2. Open **Subscriptions**. Note the Tenant and Plan shown for a row.
3. Open that row.
4. Compare Tenant, Plan and Price against what the list showed.

## Expected Result

- The suite passes.
- The record shows the same tenant name and plan name the list did.
- Price shows an amount that says what it is per — for example
  `PKR 300 per seat / month` — and never a bare number.
- Nothing reads "Not set" for a relation whose id is present.

## Notes

The list was always right; only the record was wrong, which is why comparing the
two screens is the test rather than looking at either alone.

The per-seat labelling is not cosmetic. A subscription of 25 seats at PKR 300 is
PKR 7,500, and a record page showing `300` invites an operator to read that as
the bill.
