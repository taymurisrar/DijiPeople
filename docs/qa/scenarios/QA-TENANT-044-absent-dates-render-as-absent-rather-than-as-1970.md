# QA-TENANT-044 — Absent dates render as absent rather than as 1970

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.
- A contract with at least one date left unset — two of seven on production had
  this.

## Steps

1. Open the contract and read its date fields.
2. Check any other screen that showed 1 January 1970.
3. Open a lead and compare the owner shown in the record header with the owner
   shown in the body.

## Expected Result

- An unset date shows an empty state, not `Jan 1, 1970`.
- A real date is unaffected.
- The lead's header and body agree about the owner.

## Notes

The guard is `getTime() === 0` exactly. A 1970 date that is not midnight UTC to
the millisecond is somebody's real data and should still render — if one stops
rendering, the guard has been widened and that is a regression in the opposite
direction.

**Step 3 is not a confirmed fix.** The owner divergence was never reproduced
from the source: both surfaces read `assignedToUserId` and the label resolver
already handles the shape the API returns, so the cause is a payload difference
the source does not show. What changed is that both now name the relation
explicitly. If they still disagree, capture both fetches — that comparison is
the thing the fix could not do.
