# QA-ATTENDANCE-002 — Web attendance check-in prompts for location and records a position

## Preconditions

- A tenant workspace on `apps/web` with attendance enabled and web attendance
  allowed.
- An employee account linked to an Employee record, signed in.
- A browser with **no prior geolocation grant** for the tenant host. This is the
  whole point of the scenario: a browser that has already been granted access
  cannot distinguish a working prompt from a blocked one.

## Steps

1. Confirm the starting state in DevTools:
   `document.featurePolicy.allowsFeature('geolocation')` and
   `(await navigator.permissions.query({name:'geolocation'})).state`.
2. Open `/attendance`.
3. Press **Check In**.
4. Grant the browser prompt when it appears.
5. Read the `POST /api/attendance/check-in` request body on the Network tab.
6. Repeat from step 2 in a second browser profile, and **deny** the prompt.

## Expected Result

- Step 1: `allowsFeature` is `true` and the permission state is `prompt`.
  `false`/`denied` here means the Permissions-Policy header has regressed and
  the rest of the scenario cannot pass — see BUG-2331.
- Step 3-4: the browser's own location prompt appears. It must appear; an
  immediate "Location access is required" card with no prompt is the regression.
- Step 5: the body carries `locationLatitude`, `locationLongitude`,
  `locationSource` and `locationCapturedAt`. It carries `userAgent` only if the
  tenant policy has `storeUserAgent: true` (BUG-2333).
- Step 6: denying produces the "Location access is required" card with a working
  **Try again**, and no technical error dialog.

## Notes

Created 2026-08-30 at `f77c0abb`.

The precondition about a clean browser profile is the part most easily skipped
and the only reason this scenario has value. BUG-2331 shipped for as long as it
did partly because `PERMISSION_DENIED` from a permissions-policy block is
byte-identical to `PERMISSION_DENIED` from a user refusal — the difference is
visible only in `allowsFeature` and in whether a prompt was ever offered, which
is why step 1 is a step and not a note.
