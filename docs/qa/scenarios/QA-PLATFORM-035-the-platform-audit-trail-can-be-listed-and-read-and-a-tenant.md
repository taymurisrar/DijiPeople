# QA-PLATFORM-035 — The platform audit trail can be listed and read, and a tenant-scoped reader refuses a platform caller

## Preconditions

A SUPER_ADMIN session; a recent tenant profile edit that wrote a
`PlatformAuditLog` row; a session for a role without `monitoring.read`
(PRESALES_MANAGER); a tenant user session.

## Steps

1. Edit a tenant's profile as SUPER_ADMIN (writes a `PlatformAuditLog` row).
2. Call `GET /platform/audit-logs` and `GET /platform/audit-logs/:id` for that
   row, filtering by trace id and by free-text search together.
3. Call `GET /audit-logs` as the same SUPER_ADMIN (the tenant-scoped route).
4. Call `GET /platform/audit-logs` as PRESALES_MANAGER, and as a tenant user,
   and unauthenticated.
5. Inspect a returned row's `beforeSnapshot`/`afterSnapshot` for a field that
   would be sensitive if unredacted.
6. Request page 3 at page size 10.

## Expected Result

Step 2 returns the row with actor, action label, entity and trace id, and the
combined trace-id/free-text filter narrows correctly (neither filter silently
overwrites the other). Step 3 returns `400
PLATFORM_AUDIT_TRAIL_USE_DEDICATED_ENDPOINT` naming the dedicated endpoint,
never an empty `200`. Step 4 refuses PRESALES_MANAGER and the tenant user with
`403`, and the unauthenticated call with `401`; READ_ONLY_AUDITOR and the
other audit-facing roles are admitted. Step 5's snapshot is redacted even
though the write path already redacted it (defence in depth). Step 6's query
uses `skip: 20, take: 10` against the database, not an in-memory slice.
