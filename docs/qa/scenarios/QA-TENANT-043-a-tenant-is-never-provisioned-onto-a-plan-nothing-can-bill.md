# QA-TENANT-043 — A tenant is never provisioned onto a plan nothing can bill

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.
- A plan that is inactive or carries no active price — `QA00591` was the one
  this was found on.

## Steps

1. Run `npm --workspace api run test -- onboarding-prerequisites`.
2. Open a customer and look at the Preferred plan picker.
3. `GET /api/super-admin/plans?sellable=true` and compare with the unfiltered
   list.
4. Attempt tenant creation against the unsellable plan **through the API**.
5. Load the Partners screen.

## Expected Result

- The suite passes.
- The unsellable plan is absent from the picker and from the filtered list, and
  present in the unfiltered one.
- Step 4 is refused, with a message saying whether the plan is inactive or
  unpriced.
- The Partners screen loads rather than answering 400.

## Notes

Step 4 is the one that matters. The picker is a usability improvement and cannot
be the enforcement point — a plan id still arrives from a lead's `agreedPlanId`,
from a customer chosen before the plan was retired, or straight from the API.

The guard counts *active* prices. A plan carrying only inactive prices is as
unsellable as one carrying none, and it is the case a test using "has prices"
would miss.
