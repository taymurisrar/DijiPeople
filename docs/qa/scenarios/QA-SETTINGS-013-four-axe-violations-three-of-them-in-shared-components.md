# QA-SETTINGS-013 — Four axe violations, three of them in shared components

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-337 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

The category toggle has an accessible name and both chevrons are `aria-hidden`. The current-page indicator no longer pairs the accent with a tint of itself, and still carries `aria-current="page"`. A clickable table row has no widget role, keeps `tabIndex` and its key handler, and keeps `aria-selected`. The settings shell does not nest an `aside` inside the one `SettingsLayout` supplies.

## Expected Result

The behaviour holds as REG-337 describes it. There is no automated guard, so this scenario is executed by hand and its result recorded here.

## Why This Is Reusable

An axe audit of one settings screen returned four critical or serious violations whose selectors were Tailwind utility strings. Three are not settings components
