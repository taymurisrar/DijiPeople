# QA-LANDING-001 — Public pages degrade rather than 500 when the plans API is unreachable

## Preconditions

The landing app is running. The plans API is deliberately unreachable — stopped, or the app pointed at a closed port. No authentication and no seeded tenant are needed.

## Steps

1. Request `/`, `/subscribe` and `/plans`.
2. Confirm each returns 200 and renders header, navigation and body copy.
3. Read the region where pricing would appear.
4. Restart the API and confirm pricing returns without a redeploy.

## Expected Result

All three routes return 200. The pricing region states "We could not reach our pricing service just now." rather than showing or inventing a price.

An unreachable API and a region with nothing published are reported
**differently**, because only one of the two is worth retrying — collapsing them
either tells people to retry something that will never work, or hides an outage
behind an empty state.

Guards BUG-0061, where an unguarded `fetch` threw out of a server component and
returned 500 on the site's front door and its purchase page.
