# QA-TENANT-021 — Country reaches the database as a name, whichever surface wrote it

## Preconditions

- Platform owner access to the admin console.
- At least one country in `/api/public/geography/countries`.

## Steps

1. Run `npm --workspace admin run test -- country-field-submits-name`.
2. Create a customer through the admin Customers form, choosing a country.
3. Read the stored record — through the API, not the form.
4. Compare with a customer created through public signup.

## Expected Result

- Every country lookup in the registry declares `submitsLabel`.
- The stored `country` is a name, e.g. `Pakistan`.
- Both surfaces store the same representation.
- No customer holds a value matching a UUID.

## Notes

**Read the stored value, not the form.** The picker redisplays its own id as a
selected label, so the screen looks correct either way — which is why this was
found on a rendered legal agreement rather than on the form that caused it.

The quickest production check is a scan for a UUID-shaped `country` across
customers. On 2026-08-27 that found exactly one, and it was the only customer
ever created through the admin form.
