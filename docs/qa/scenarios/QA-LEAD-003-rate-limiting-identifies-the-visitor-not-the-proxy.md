# QA-LEAD-003 — Rate limiting identifies the visitor, not the proxy

## Preconditions

Requests arriving through the landing proxy with forwarding headers set.

## Steps

1. Resolve the client IP for a request with a forwarding chain.
2. Resolve it for a direct request.
3. Resolve it for a request with a spoofed forwarding header.

## Expected Result

The visitor is identified, not the proxy, and a spoofed header cannot claim another visitor's bucket. Collapsing every visitor into one bucket makes the limiter a denial-of-service on legitimate traffic.

## Notes

The `shared-identity-bucket` pattern.
