# QA-BILLING-007 — Every unauthenticated write handler is rate limited

## Preconditions

A checkout of the API workspace with its Prisma Client generated. No database
and no running server are required — the invariant reads controller sources
rather than booting Nest, deliberately, so it constrains handlers that have not
been written yet.

## Steps

1. Run `npm --workspace api run test -- public-write-rate-limit`.
2. Remove `@UseGuards(PublicRateLimitGuard)` from above `@Controller('public')`
   in `services/api/src/modules/billing/controllers/public-billing.controller.ts`,
   **leaving the import statement in place**, and run it again.
3. Restore the decorator and run it a third time.

Step 2 is the scenario. Steps 1 and 3 only establish the baseline it is measured
against — a passing run proves nothing on its own here, which is the whole
reason this scenario exists.

## Expected Result

Step 1 passes. **Step 2 fails**, and the failure names the unguarded handler —
`"createSubscriptionCheckout("` — rather than reporting a generic count. Step 3
passes again.

Leaving the import in place at step 2 is not incidental. BUG-0075 was precisely
that an import satisfied the class-level check, so a mutation that also deleted
the import would fail for the wrong reason and re-certify the broken predicate.

## Notes

The `assertion-matches-mention` pattern: a check that asserts a file *mentions*
something keeps passing once the behaviour is gone. This scenario exists because
the endpoint half of BUG-0075 is a one-line fix, while the invariant half is
what actually prevents the fourth recurrence of BUG-0013 / BUG-0031 / BUG-0033 —
and the only way to know an invariant works is to watch it fail.

Applies to every controller, not only billing: the predicate is swept across all
controllers under `services/api/src/modules/` (106 at `494c44d`), and the
allowlist — `stripe-webhook`, `release-publisher` — is asserted to be both
justified and non-stale, so an exemption cannot silently protect nothing.
