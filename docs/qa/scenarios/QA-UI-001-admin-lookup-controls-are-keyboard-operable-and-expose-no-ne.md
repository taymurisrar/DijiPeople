# QA-UI-001 — Admin lookup controls are keyboard-operable and expose no nested-interactive listbox

## Preconditions

Signed in to the platform admin console as any platform user who can reach a
runtime form with at least one lookup field (for example a Customer, Contract
or Support Case record), and a screen using the generic `FormControl` in
`type: "lookup"` mode (for example the platform defaults form).

## Steps

1. Open a runtime record form with a reference (lookup) field. Tab to it with
   the keyboard only — do not click.
2. Press Enter or the down arrow to open the list. Confirm the search input
   receives focus automatically.
3. Type a partial match. Press the down/up arrow keys and confirm a single
   option highlights and the highlight moves; press Home/End and confirm it
   jumps to the first/last match.
4. Press Enter on a highlighted option and confirm it is selected and the
   popup closes.
5. Reopen the list, press Escape, and confirm the popup closes without
   changing the selection.
6. With a value selected, Tab to the control's clear affordance (an "X"
   button) without using the mouse, and activate it with Enter or Space.
   Confirm the value clears.
7. Repeat steps 1-6 against a `FormControl` `type="lookup"` field (for
   example platform defaults / preferences) if one is reachable, since it is
   a second, independently implemented control.
8. Inspect the DOM (or an accessibility tree inspector) while a list is open:
   confirm no element with role="option" is itself a Tab stop, and that the
   combobox or search input carries aria-activedescendant naming the
   highlighted option's id.

## Expected Result

Every step above succeeds without a mouse. No option is independently
focusable (no nested-interactive violation), aria-activedescendant is present
and correct while the list is open, and the clear control is reachable and
operable by keyboard. This mirrors the tenant product's `LookupField` fixed by
BUG-1956 (`apps/web/app/components/ui/form-control.tsx`), which this scenario
uses as the reference behaviour.

## Why This Is Reusable

The two admin controls (`LookupControl` in
`apps/admin/app/_components/ui/form-control.tsx` and `SearchableSelect` in
`apps/admin/app/_components/runtime/runtime-form.tsx`) are the only two
lookup/searchable-select implementations in Platform Admin, so this scenario
covers every reference field the console renders. `TEST_REFERENCE` covers the
source-level half (the pure keyboard-movement resolver, and a structural scan
proving neither control renders a focusable option or an unconditional
`aria-controls`); this scenario is the live-browser half neither app's jest
config can exercise (no jsdom — `apps/admin/AGENTS.md`).
