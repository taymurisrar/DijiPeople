# QA-SETTINGS-029 — The notification events page toggles In-app and Email per event and dispatch honours the choice

## Preconditions

- A seeded tenant on a throwaway database, with no notification rules for the
  claim, loan or timesheet modules.
- A tenant administrator holding `notifications.manage` and
  `notifications.manageRules`; a second user holding only `notifications.read`.
- A pending leave request and a payslip ready to publish.
- Email delivered to a controlled mailbox only.

## Steps

1. Open `/settings/notifications/rules` at 1440px.
2. Look for Claims, Loans and Timesheets, and for an Email checkbox on any leave
   event.
3. Untick In-app on "Leave request approved for employee"; reload. Check
   `NotificationPreference(IN_APP)`, the event's `NotificationRule.enabled` and
   the audit log. Tick it again.
4. With In-app off, approve the leave request; with it on, approve another.
5. Untick Email on "Payslip available"; publish the payslip.
6. Untick "Send email"; re-tick it.
7. Block `PATCH /api/notifications/event-settings/*` in devtools and tick a box.
8. Search "payslip"; then search nonsense.
9. Find Account activation and Password reset; `PATCH` one of them directly.
10. As the read-only user, open the page and send a `PATCH` directly.
11. View the page at 400px.

## Expected Result

- Step 1: one list grouped by module, each event once; no raw codes, no "Not
  configured", "No rule exists" or "Not yet available", no Browser Push or
  Digests, no paragraphs, no Save button.
- Step 2: none present.
- Step 3: the choice persists; preference `false`, rule disabled, both writes
  audited; re-ticking restores both.
- Step 4: no inbox notification with In-app off; one with it on.
- Step 5: In-app stays ticked; the email is SKIPPED with `EVENT_EMAIL_DISABLED`;
  the in-app notification is still created.
- Step 6: every Email checkbox disables; `notifications.emailEnabled` is `false`.
- Step 7: the box reverts with an inline error; other boxes are unaffected.
- Step 8: only matching events remain and empty groups disappear; nonsense shows
  "No matching events".
- Step 9: both read "Always on" with no checkbox; the `PATCH` returns 400
  `NOTIFICATION_EVENT_NOT_CONFIGURABLE`.
- Step 10: checkboxes disabled; the `PATCH` returns 403.
- Step 11: rows wrap with no row-level horizontal scroll. The settings shell's
  own mobile layout is tracked separately and is not part of this result.
