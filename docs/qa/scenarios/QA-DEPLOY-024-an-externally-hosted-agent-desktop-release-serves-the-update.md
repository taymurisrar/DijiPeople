# QA-DEPLOY-024 — An externally hosted AGENT_DESKTOP release serves the update feed

## Preconditions

A platform user holding `appDownloads.manage`. No existing `ApplicationRelease`
row for `AGENT_DESKTOP` at the version under test, on the `STABLE` channel.

## Steps

1. `POST /app-releases` with `appKey: AGENT_DESKTOP`, `channel: STABLE`, an
   `externalUrl`, a `checksumSha256`, and a 128-character hex
   `checksumSha512` — the field `PublishReleaseDto` lacked before BUG-2888.
2. Repeat the same publish with `checksumSha512` omitted.
3. `GET /app-releases` — confirm the release from step 1 is listed.
4. `GET /app-releases/{id}/download` — confirm the 302 redirect to the
   `externalUrl` still works (unaffected by the fix).
5. `GET /app-releases/feed/AGENT_DESKTOP/latest.yml` — confirm the release from
   step 1 is served and its `sha512:` line matches the digest submitted.

## Expected Result

Step 1 succeeds and the release is fully visible: listed, downloadable, and
served by the update feed with the correct sha512, closing the gap BUG-2888
found (accepted, listed and downloadable, but permanently invisible to
auto-update). Step 2 is refused with `RELEASE_SHA512_REQUIRED` — a STABLE
AGENT_DESKTOP release that cannot serve the feed must not be created silently.
A non-AGENT_DESKTOP app, or a BETA channel release, may still publish without
a checksumSha512.
