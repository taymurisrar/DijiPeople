# QA-ATT-009 — Attendance recorded for a day that has not happened

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-319 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

Tomorrow in the tenant timezone is refused with `ATTENDANCE_DATE_IN_FUTURE` and no entry is created; a far-future date (2099) is refused; today in the tenant timezone is still accepted; yesterday is still accepted; moving an existing entry to a future date through `updateManualEntry` is refused and writes nothing.

## Expected Result

The behaviour holds as REG-319 describes it. The automated guard is `services/api/src/modules/attendance/attendance.service.spec.ts`; a run of that suite is sufficient evidence for this scenario.

## Why This Is Reusable

`POST /api/attendance/manual` had no upper bound on `date`. `CreateManualAttendanceEntryDto` declared it as a bare `@IsDateString()`, and `createManualEntry` checked for a duplicate day and for reversed check-in/check-out times but never compared the date to today
