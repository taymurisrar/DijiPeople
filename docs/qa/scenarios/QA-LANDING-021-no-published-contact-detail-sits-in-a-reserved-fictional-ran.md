# QA-LANDING-021 — No published contact detail sits in a reserved fictional range

## Preconditions

None. The values under test are compiled into the page.

## Steps

1. Read `contactInfo.phone`. If it is `null`, the site publishes no number and
   the range check does not apply.
2. If a number is published, check it against the reserved fictional ranges —
   NANP `555-0100`–`555-0199`, and all-zero subscriber numbers.
3. Check `contactInfo.phone` and `contactInfo.phonePlaceholder` are distinct.
4. Load any page and inspect the footer's Contact column.
5. Load `/contact` and inspect the phone input's placeholder.

## Expected Result

- **Step 2** — no published number falls in a reserved range. A number in the
  footer is a promise that somebody answers it.
- **Step 3** — the two fields are separate. Collapsing them is how the defect
  happened: the same string is correct in a `placeholder` and a lie in a footer.
- **Step 4** — with `phone: null`, the row is absent entirely. Not blank, not a
  placeholder.
- **Step 5** — the input still shows an illustrative example, in the market the
  site bills in.
