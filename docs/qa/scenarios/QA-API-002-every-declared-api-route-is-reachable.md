# QA-API-002 — Every declared API route is reachable

## Preconditions

None. The check reads controller sources; it does not boot Nest.

## Steps

Walk every `*.controller.ts` under `services/api/src/modules`. For each, blank
out comments (preserving offsets), read the route decorators in declaration
order, and flag any fully static route declared after a same-verb, same-depth
route whose parameter segments would match it first. Assert the scan found
more than 100 controllers.

## Expected Result

No findings. Every declared route is reachable by some request.

The controller-count assertion is not decoration: without it the whole
scenario passes when the directory traversal breaks, which is the classic way
a source-scanning check goes quietly green.

## Why This Is Reusable

Express matches in declaration order, so this fault is invisible to the
compiler, invisible in review, and produces a `400` rather than a `404` — a
symptom that points at validation instead of at routing. It cost one dead
endpoint before anyone looked. Re-run on any controller that gains a static
route beside a parameterised one.

Note the scanner must blank comments first. This codebase's house style is
substantial explanatory comments, and the fix comment for BUG-2461 quotes the
offending decorator — read naively, the check reports the very bug it
documents.
