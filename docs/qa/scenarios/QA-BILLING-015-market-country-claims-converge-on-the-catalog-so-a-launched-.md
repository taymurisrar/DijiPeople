# QA-BILLING-015 — Market country claims converge on the catalog so a launched market resolves

## Preconditions

A database holding the seeded commercial markets, in one of three states:

- **A** — `GCC` holds the `QA` country row and a `QA` market exists (the state
  production reached).
- **B** — `GCC` holds `QA` and no `QA` market exists at all.
- **C** — every country row already points at the market the catalog assigns it
  to.

## Steps

1. Run `bootstrapCommercialDefaults` (`npm run seed:commercial`) against each state.
2. Read back `MarketCountry` for `QA`, and the returned `warnings`.
3. Then call `GET /public/commercial-config` with `x-vercel-ip-country: QA`.

## Expected Result

- **A** — the `QA` row now points at the `QA` market, and `warnings` names both
  the country and the market it was taken from.
- **B** — the `QA` market is created *and* holds its country row. The market must
  not be created without it: a nested create would fail the whole statement on
  the unique constraint.
- **C** — no writes, and no warnings mentioning a country.
- In every case afterwards, the config call returns `market.code == "QA"` and
  `currency == "QAR"` rather than falling through to the default market.

## Notes

`MarketCountry.countryCode` is unique globally, not per market, so two markets
can never both claim a code — and a seed that treats the resulting unique
violation as benign leaves a launched market resolving for nobody. This scenario
exists because that state is invisible from every screen: the market row looks
correct, the prices exist, and only the country join is missing.

Automated at `services/api/src/modules/super-admin/commercial-bootstrap.reconcile.spec.ts`.
The production half — step 3 against the live API — is manual until the seed has
been run there.
