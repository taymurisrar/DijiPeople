# QA-BILLING-033 — Subscription primary actions follow the tenant brand colour

## Preconditions

A tenant whose brand colour differs visibly from its body-text colour. The
demo tenant is teal on near-black, which is why the defect was visible there at
all.

## Steps

1. Open each subscription surface: overview, plans, billing history, and the
   cancel screen.
2. Look at the active tab pill, the selected billing-cycle segment, the plan
   card's action button, and the links out to the payment provider.
3. Change the tenant's brand primary colour in settings and reload.

## Expected Result

No primary action on any subscription screen is filled with the body-text
token. Changing the tenant's brand primary changes the colour of every primary
action on all four surfaces. The component takes its buttons, empty states and
status pills from the shared kit rather than defining its own.

## Notes

The token name is the trap. The foreground token reads as "the strong neutral"
and is in fact the tenant's text colour, so using it as a fill silently ties every
button to whatever a tenant sets their body copy to.

The guard is a static check, which is cheap enough to be worth distrusting: a
negative assertion passes just as well when it is looking at the wrong file. It
was mutation-tested at integration by reintroducing the fill on the cancel
screen, and it went red. A future edit to this spec should repeat that rather
than assume it.

The record counted five instances and there were six. The sixth was on the cancel
screen, outside the file the record named.
