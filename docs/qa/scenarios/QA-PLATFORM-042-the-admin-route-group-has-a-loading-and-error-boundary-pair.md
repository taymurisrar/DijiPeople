# QA-PLATFORM-042 — The admin route group has a loading and error boundary pair

## Preconditions

`apps/admin/app/(internal)/` route tree; a request that fails while a page
under `(internal)/` is loading.

## Steps

1. Confirm `apps/admin/app/(internal)/loading.tsx` and `error.tsx` exist.
2. Navigate to a page under `(internal)/` while throttling the network, and
   again while forcing a request to fail.
3. Navigate to a page under `apps/web/app/partner/`, `apps/web/app/(public)/`
   (including `login`) or `apps/web/app/workspace/` under the same conditions.

## Expected Result

Step 1's files exist and cover all 88 pages under `(internal)/` via Next's
route-group convention. Step 2 shows a skeleton loading state, then a
status/message-derived error screen instead of Next's default. Step 3 still
shows Next's default (unstyled) loading/error UI — the `apps/web` half of the
original finding (22 pages) is unchanged and out of this scenario's scope.
