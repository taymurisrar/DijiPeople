# QA-TENANT-038 — A field error names the field on the screen

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.

## Steps

1. Run `npm --workspace admin run test -- humanize-field-error`.
2. Open a create form and enter a value longer than a field's maximum.
3. Save, and read the message.
4. Trigger a uniqueness conflict — reuse a key or code that already exists.

## Expected Result

- The suite passes.
- Step 3 names the field as the form labels it, not as the DTO declares it.
- The constraint half of the message is unchanged.
- Step 4 does not say "Database constraint failed"; it says what happened and
  where to look.
- The offending control is marked, not only the modal.

## Notes

Only the field *name* is rewritten. The constraint is the part that says what is
actually wrong, and the frontend cannot see the rules well enough to reword it —
a message that reads better and means less is not an improvement.

The internal-failure replacement deliberately does not name a field. It does not
know which one, and guessing would be worse than the raw string it replaced.

The "marked, not only in a modal" half comes from REG-274, fixed in the same
sweep — this record and BUG-1546 described the same gap from opposite ends.
