# QA-ATTENDANCE-010 — An employee's correction work-site list resolves from the caller, never a supplied id

## Preconditions

An employee with a subset of the tenant's work sites authorised to them, and a
second employee whose authorised sites differ. A correction request that names a
requested work site.

## Steps

1. As the first employee, request the list of work sites available for a
   correction.
2. Attempt to obtain the second employee's list by supplying their id.
3. Repeat as a caller holding none of the correction or read permissions.
4. Read a correction that requested a site, and one that did not.

## Expected Result

- The list is the caller's own authorised sites.
- There is no way to ask for somebody else's: the list resolves from the
  authenticated caller, and supplying an id changes nothing. This is the
  assertion that fails first if the method is later refactored to take an
  employee argument.
- A caller with none of the relevant permissions is refused.
- The route does **not** require `attendanceDevices.read`. Gating an
  employee-facing selector behind a device-administration permission presents as
  an empty dropdown and reads as missing data.
- A correction naming a site resolves that site's name, tenant-scoped; one that
  named none resolves null.
