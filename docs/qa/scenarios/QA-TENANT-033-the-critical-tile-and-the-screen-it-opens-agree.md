# QA-TENANT-033 — The critical tile and the screen it opens agree

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.
- Incidents recorded with severity in mixed case, which production has.

## Steps

1. Run `npm --workspace api run test -- incident-severity-case`
   and `npm --workspace admin run test -- monitoring-overview`.
2. Open **Settings → Monitoring**. Read the "Critical, untriaged" tile.
3. Click it.
4. Compare the count on the destination screen with the tile's number.

## Expected Result

- Both suites pass.
- The tile's count and the destination's count agree.
- The destination is not empty when the tile is non-zero.
- The URL names a view (`viewId=critical`), never a raw severity value.

## Notes

The two numbers disagreeing is the whole defect, so comparing them is the test —
neither number is checkable on its own. The tile read 11 and the screen it opened
returned 0 of 0.

Three copies of the definition existed. If this ever fails again, count the
copies before changing any of them: BUG-1420 fixed the view and left the metric
carrying the original defect, which is how one bug became two.

`severity` is still free text holding roughly 1,466 lowercase rows. Promoting it
to an enum is a separate migration, and the duplicated spellings in the `in` list
stay load-bearing until then.
