# QA-PLATFORM-063 — Admin deletes draft agreements and inactive never-sold plans, keeps evidence, and shows names not ids

## Preconditions

A non-production database with seed:config, seed:admin, seed:commercial and
seed:demo applied. Signed in as the platform super admin.

## Steps

1. On the demo customer, create a Draft agreement and a second agreement moved
   to SENT.
2. Customer → Agreements: select both, Delete selected, confirm.
3. Delete the Draft one again by id.
4. Create a plan and try to delete it while active. Deactivate it, set it as a
   customer's preferred plan, then delete it.
5. Deactivate a plan with a subscription and delete it, through the runtime and
   through DELETE /super-admin/plans/:id.
6. Open the customer's Summary.

## Expected Result

1. The confirmation lists what goes with the draft (versions, parties, fields,
   timeline). The draft is deleted and audited (CONTRACT_DELETED); the SENT one
   is kept with "Void, supersede or terminate it instead"; the customer is
   untouched.
2. Deleting again reports "it no longer exists".
3. The active plan is refused with "Deactivate or archive it first". The
   inactive one deletes, the preferred-plan link is cleared and the plan is
   absent from /public/plans.
4. The sold plan is refused with "Archive it instead" on both routes (400 on
   REST).
5. Tenant primary owner shows the owner's name, never a UUID.
