# QA-PLATFORM-072 — Platform-admin runtime lists page, search and sort in the database, falling back only for unsupported filters

## Preconditions

A mocked Prisma client; request inputs carrying search text, a view tab, filters, sort and a page for each of the nine lists.

## Steps

1. Build the DB query for each list with search text, a view tab, a supported filter and a sort.
2. Build it again with an unsupported filter (numeric, date equality, invalid enum value).
3. Call the platform runtime list for each module and inspect the Prisma `where`, `orderBy`, `skip`, `take` and `count` arguments.

## Expected Result

Supported requests become a Prisma `where` / `orderBy` / `skip` / `take` plus a `count()`, with no full-table read. An unsupported filter makes the builder return null and that request uses the old whole-table path, so a filter never silently stops filtering. Residuals: the spec is mocked, so it proves Prisma arguments and not SQL results, and no DB-backed e2e exists (ITEM-0243). ILIKE over the listed columns is not index-assisted. Search now covers only the documented columns per module, where it was the whole-record JSON. The `my-records` view now filters on `createdById`.
