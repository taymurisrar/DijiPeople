# QA-REPORTING-009 — An expired session lands on the login form, not a redirect loop

## Preconditions

A signed-in browser session whose server-side session has since expired, with the cookies still set.

## Steps

1. Open any protected page.
2. Follow the redirects.
3. Separately, sign in normally and type `/login` by hand.

## Expected Result

The stale session lands on the login form. No `ERR_TOO_MANY_REDIRECTS`. A genuinely signed-in visitor who types `/login` is still sent on to their workspace.

## Notes

The middleware only sees cookie presence, not validity, and an access token stays structurally valid for hours after the session row is gone — so do not test this by deleting cookies, which takes a different path entirely. Let the session expire with the cookies in place.
