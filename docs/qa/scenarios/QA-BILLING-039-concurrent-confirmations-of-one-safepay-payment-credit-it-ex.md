# QA-BILLING-039 — Concurrent confirmations of one Safepay payment credit it exactly once

## Preconditions

A real PostgreSQL (`DATABASE_URL` pointing at a disposable database) with the migration applied; one `PENDING` Safepay payment for an `INCOMPLETE` subscription.

## Steps

1. Run five settlements of the same payment concurrently, each with the provider reporting it paid.
2. Try to insert a second payment row with the same provider and tracker.
3. Insert the same provider webhook event twice.

## Expected Result

- Exactly one credit: payment `SUCCEEDED`, subscription `ACTIVE`, and no refund request raised for a phantom duplicate.
- The second payment row is refused with `P2002`.
