# QA-CI-004 — The lockfile can be regenerated from the manifests alone

## Preconditions

A checkout. No `node_modules`, no network install — resolution only.

## Steps

1. Copy every tracked `package.json` into an empty directory. Nothing else:
   resolution needs no source.
2. Run `npm install --package-lock-only`.

## Expected Result

It succeeds. No `ERESOLVE`.

## Notes

`npm ci` cannot answer this question — it replays a committed lockfile and never
asks whether the manifests could still produce one. [[BUG-0163]] is what lived in
that gap: two optional peers of `@tiptap/react` carried caret ranges that drifted
past the pinned family, a from-scratch resolve failed with ERESOLVE, and the
committed lockfile papered over it for weeks.

The cost was not theoretical. `overrides` in the root manifest were read and then
silently discarded — npm cannot apply an override while it cannot produce a tree
— so the one lever for forcing a transitive version had stopped working.
[[BUG-0052]] needed exactly that lever and grafted resolutions in by hand instead.

About 20 seconds, and it runs in `Framework validation` alongside the other
structural checks.
