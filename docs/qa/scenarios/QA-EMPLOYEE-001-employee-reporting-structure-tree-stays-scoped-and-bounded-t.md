# QA-EMPLOYEE-001 — Employee reporting-structure tree stays scoped and bounded to the queried employee

## Preconditions

A tenant with at least two independent org roots (two employees with no
manager), each with their own descendant chain of at least two levels. The
caller holds `hierarchy.read`.

## Steps

1. Call `GET /employees/{employeeId}/reporting-structure` for an employee
   under org root A.
2. Inspect the response's `tree` field.
3. Repeat for an employee under org root B in the same tenant.
4. Seed (or construct via the unit-test fixture) a manager chain deeper than
   `MAX_HIERARCHY_DEPTH` (8) levels and call the endpoint for the deepest
   employee.
5. Repeat with more than `MAX_HIERARCHY_NODES` (500) employees under one
   manager.

## Expected Result

- Step 2: `tree` contains only nodes reachable from org root A — no node from
  org root B's branch appears anywhere in it.
- Step 3: symmetrically, only org root B's branch appears; A's branch is
  absent.
- Step 4: `hierarchyTruncated` is `true`, and the deepest node returned is no
  more than 8 levels below the tree's root.
- Step 5: `hierarchyTruncated` is `true`, and the total node count in `tree`
  does not exceed 500.
- In every case, `reportingLine`, `directReports` and `currentEmployee` are
  present and unchanged in shape from before this change.
- A second tenant's employees never appear, even if `managerEmployeeId`
  values happen to collide across tenants (the query is tenant-scoped before
  the tree is built).
