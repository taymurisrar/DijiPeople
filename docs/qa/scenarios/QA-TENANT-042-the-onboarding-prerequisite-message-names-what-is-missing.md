# QA-TENANT-042 — The onboarding prerequisite message names what is missing

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.
- A customer with no industry and no company size set.

## Steps

1. Run `npm --workspace api run test -- onboarding-prerequisites`.
2. Attempt to start onboarding for that customer.
3. Read the failure message.
4. Create a customer onboarding from the admin console with all prerequisites
   met.

## Expected Result

- The suite passes.
- The message names what is *missing* — "no industry is selected" — and agrees
  with its own header.
- The checklist elsewhere still shows the positive phrasing beside its ticks.
- Step 4 succeeds rather than failing on a foreign key.

## Notes

Both phrasings exist on purpose and are read in opposite directions. If a future
change collapses them back to one string, this defect returns — the spec asserts
no pair is identical bar capitalisation for exactly that reason.

**Step 4 leaves the onboarding with no owner**, and that is the visible
consequence of a modelling question left open: `onboardingOwnerUserId` is
declared as a tenant `User` while every read filters it by a platform user id.
If operations needs an owner recorded there, the answer is the migration
described in BUG-1545, not restoring a fallback that writes an id the column
cannot hold.
