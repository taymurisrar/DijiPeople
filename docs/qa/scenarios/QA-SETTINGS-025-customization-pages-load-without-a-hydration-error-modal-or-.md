# QA-SETTINGS-025 — Customization pages load without a hydration error modal or a false client error log row

## Preconditions

- A tenant whose configured timezone is not UTC, with at least one package and
  one draft so dates render.
- An administrator holding the customization permissions.
- Browser console and network tab open.

## Steps

1. Load `/settings/customization/tables/<key>`.
2. Load `/settings/customization/publish-center`.
3. Load `/settings/customization/packages`; compare the dates in the server HTML
   (fetched with `page.request.get()`) with the hydrated DOM.
4. From the console, throw an ordinary runtime `TypeError` asynchronously.

## Expected Result

- Steps 1-2: no React #418 in the console, no error modal, and no
  `POST /api/error-logs/client`.
- Step 3: server and hydrated dates are identical.
- Step 4: the error modal still opens and the error is logged, with a plain
  message rather than React's minified text.

source was identified by code reading; if #418 still appears there, the
classifier keeps it silent, so check the console, not only the absence of the
modal.
