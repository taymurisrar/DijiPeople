# QA-AUTHZ-018 — The admin session heartbeat never requires a tenant business permission

## Preconditions

A signed-in admin session for each of the 16 platform roles and for a tenant
user with no permissions; an unauthenticated request.

## Steps

1. Call `POST /api/auth/activity` as each of the 16 platform roles and as a
   permission-less tenant user.
2. Call the same endpoint with no session.
3. In `apps/admin`, use the app long enough to trigger the background activity
   ping while signed in as a role that used to lack `user-preferences.write`.
4. Trigger a genuine user-initiated action failure (e.g. a rejected save).

## Expected Result

Every session in step 1 gets `200`. Step 2 gets `401` — the handler is not
`@Public()`, `JwtAuthGuard` still runs. In step 3, no blocking error dialog
opens and no failed network call is logged for the heartbeat. Step 4 still
opens the error dialog as normal — only the background heartbeat is exempted.
