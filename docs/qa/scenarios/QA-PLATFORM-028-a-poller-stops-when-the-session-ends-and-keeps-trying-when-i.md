# QA-PLATFORM-028 — A poller stops when the session ends and keeps trying when it has not

## Preconditions

None. The unit under test is the error type the notification request layer
throws; no browser, server or session is required.

## Steps

Assert a `NotificationRequestError` built with status 401 reports
`isAuthFailure`, and that one built with 400, 403, 404, 429, 500, 502 or 503
does not. Assert a plain `Error`, a `TypeError`, `null`, `undefined` and a
bare object shaped like `{ status: 401 }` are all rejected by `isAuthFailure`.
Assert the error is still `instanceof Error` and preserves `.message`.

Manually, to cover what the unit test cannot: sign in to the tenant
workspace, leave a tab open, revoke the session from another device, and watch
the network panel across two minutes.

## Expected Result

Only a `401` is treated as the end of the session. After the manual
revocation, `GET /api/notifications/in-app` and
`GET /api/notifications/in-app/unread-count` stop firing — one refusal each,
not one per minute for ever — and the bell reads "Your session has ended. Sign
in again to see notifications."

The negative cases matter as much: a `500` or `503` must **keep** retrying.
Stopping on a transient failure would leave a live session silently without
notifications until the page was reloaded, which trades a noisy bug for a
quiet one.

## Why This Is Reusable

`apps/web` has no jsdom or testing-library, so the interval teardown cannot be
asserted automatically and the manual half above is the only coverage of it.
The automated half guards the layer both pollers stand on: if `requestJson`
reverts to throwing a bare `Error`, both fixes silently stop working and the
infinite loop returns with no test failing anywhere.
