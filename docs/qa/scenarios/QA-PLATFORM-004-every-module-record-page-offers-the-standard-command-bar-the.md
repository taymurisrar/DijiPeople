# QA-PLATFORM-004 — Every module record page offers the standard command bar the API can serve

## Preconditions

None. A static check of the admin command bar against the API service source.

## Steps

1. Extract the `case '<key>':` labels from the `create`, `update` and `remove`
   switch statements in
   `services/api/src/modules/platform-runtime/platform-runtime.service.ts`.
2. Compare each set against the modules whose registry `capabilities` declare
   the matching flag.
3. For every module, collect the record-scope action keys.

## Expected Result

The three derived sets equal the three declared sets. Every module except
`dashboard` offers `back` and `record-refresh` on its record page. No module
without `update` offers `edit`; none without `delete` offers `delete`. The
standard commands appear in one fixed order — Back, New, Edit, Save, Save and
close, Refresh, Delete — on every module, so a button does not move between
screens.

## Notes

Before this, the command bar was written per module by hand: seven record pages
carried a single Back button, and none offered Refresh at all, because
`STANDARD_RECORD_ACTIONS` never contained one.

The check parses the service source deliberately. Observing the same mapping
through the Nest container needs fifteen injected services mocked, which tests
the mocks rather than the mapping. It asserts first that it found the file and
all three switch statements, so a regex that matches nothing fails loudly
instead of agreeing with an empty set.
