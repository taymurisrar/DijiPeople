# QA-PLATFORM-003 — A plan form field the API will reject is never offered as editable

## Preconditions

None. A static contract check between the admin runtime registry and the API DTO that receives its writes.

## Steps

1. Load the `plans` module definition from the platform module registry.
2. Take every field on its `detail` form that is not `readOnly` and that the
   generated Prisma manifest reports as `editable` — this is exactly the set
   `RuntimeRecordEditor.save()` puts in the PATCH body.
3. Parse the property names declared by
   `services/api/src/modules/super-admin/dto/update-plan.dto.ts`.
4. Subtract the second set from the first.

## Expected Result

The difference is empty. `PlatformRuntimeService` validates with
`forbidNonWhitelisted: true`, so one field the DTO does not declare fails the
entire save with a 400 — not that field, the whole request. The publication
columns (`publicationStatus`, `salesModel`, `isPublic`, `publishedAt`,
`archivedAt`) must additionally be present on the form, read-only, and carry a
description saying where they are decided instead.

## Notes

The same failure mode as [[QA-AGENT-002]], one layer in: there the payload came
from a deployed desktop client, here it comes from a form the runtime generated
out of the Prisma schema. Both are shapes assembled without reference to the DTO
that receives them.

Assert against the DTO **source**, never a list of property names repeated in
the test. A copied list agrees with itself forever.
