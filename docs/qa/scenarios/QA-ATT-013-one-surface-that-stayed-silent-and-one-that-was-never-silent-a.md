# QA-ATT-013 — One surface that stayed silent, and one that was never silent at all

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-340 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

Source-level, because `apps/web` has no jsdom: the attendance form imports and calls the shared `useSideToast()` hook, calls `notifySuccess(...)` on the 201 branch strictly before `setForm(initialForm)` in the same branch, and renders the returned `{toast}` element. No assertion was written for branding, because no code there changed.

## Expected Result

The behaviour holds as REG-340 describes it. There is no automated guard, so this scenario is executed by hand and its result recorded here.

## Why This Is Reusable

The manual attendance create form (`manual-attendance-form.tsx`) already reset itself on a 201 (`setForm(initialForm)`) but reported nothing — no toast, no inline confirmation — so the next feedback the user got was the 409 from pressing Save a second time. The branding settings form, by contrast, already called `setToast({ title: "Branding updated", …, variant: "success" })` on its own 2xx branch (`branding-settings-form.tsx:315-321`, present since `ee10f739`, unrelated to this session) — the record's premise that it stayed silent no longer held by the time this task investigated it
