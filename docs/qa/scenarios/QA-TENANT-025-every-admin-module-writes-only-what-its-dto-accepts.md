# QA-TENANT-025 — Every admin module writes only what its DTO accepts

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.
- At least one customer and one partner record exist.

## Steps

1. Run `npm --workspace admin run test -- runtime-write-contract`.
2. Open **Customers**, open any customer, press **Edit**, change **Company
   name**, press **Save**.
3. Re-read the record and confirm the new name persisted.
4. Open **Partners**, open any partner, press **Edit**, change **Partner
   name**, press **Save**. Re-read and confirm.
5. Open **Leads → New Lead**, fill only the required fields on both tabs, and
   press **Save** without selecting a partner.

## Expected Result

- The suite passes for every module in the manifest, not just plans.
- The customer edit persists; no `originChannel` rejection.
- The partner edit persists; no `partnershipModel` rejection.
- The lead is created; the request body carries no `partnerId` key at all,
  rather than `partnerId: ""`.

## Notes

The automated half is the load-bearing one, and it is written to be
module-agnostic on purpose. BUG-0220 fixed this defect for plans and left behind
a plans-shaped test that passed for the whole time customers and partners were
unsavable — so a scenario naming specific modules would repeat that mistake. The
suite reads the create/update switch out of `platform-runtime.service.ts` and
covers whatever it finds there, including modules added later.

When re-running the browser half, watch the network tab rather than the toolbar:
the failure was quiet. The record page returned to read mode and looked as
though it had saved.
