# QA-TENANT-007 — A workspace link resolves from one rule on every surface

## Preconditions

None. Pure functions over an environment object, driven directly.

## Steps

1. Build a workspace URL in development with a tenant base domain configured.
2. Build one in production, and one in staging.
3. Build one with no tenant base domain configured at all.
4. Build the same workspace URL through Platform Admin's helper.

## Expected Result

Case 1 carries the port the web app listens on. `<slug>.localhost` resolves —
browsers loopback any `.localhost` label — so without the port the URL is port
80, where nothing listens, and every generated workspace link in development is
dead while looking correct.

Cases 2 and 3 carry no port at all. Both non-development stages are asserted,
not production alone.

Case 4 falls back to the slug-parameter form and still reaches the workspace: an
unconfigured base domain is how local development starts, and the link must
work anyway.

Case 5 produces a byte-identical URL to case 1. One rule, every surface.

## Notes

The reason this scenario exists is not the port. It is that
`packages/config/platform-domains.js` states in its own comment that this rule
may only live in one place, and a second copy existed in `apps/admin` anyway —
keyed on a variable with a different name, so the two disagreed silently rather
than loudly.

When adding a surface that links into a workspace, the check is not "does my URL
look right". It is "did I call `buildWorkspaceUrl`".
