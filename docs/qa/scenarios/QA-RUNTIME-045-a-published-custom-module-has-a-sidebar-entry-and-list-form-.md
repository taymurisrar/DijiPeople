# QA-RUNTIME-045 — A published custom module has a sidebar entry and list, form and record screens

## Preconditions

- A tenant with a published custom module (on the demo tenant: `qaAsset`, with
  a Serial Number field, the Main form and the "Active QA Assets" and
  "QA All Assets" views).
- User A holds `custom-records` read, create and write.
- User B holds no `custom-records` privilege.

## Steps

1. As user A, reload the product and read the sidebar.
2. Click the module's entry.
3. Choose New, fill Serial Number, Save.
4. Open the record, Edit, change Serial Number, Save.
5. Open `/custom-modules/doesNotExist` and `/custom-modules/qaAsset/not-a-uuid`.
6. In Settings → Customization → Sidebar Designer, rename and hide the module's
   entry; reload.
7. As user B, read the sidebar and open `/custom-modules/qaAsset`.
8. Deactivate the module (or publish without it) and reload as user A.
9. Repeat steps 2-4 at 400px and 820px.

## Expected Result

- Step 1: an entry with the module's plural display name sits immediately above
  Settings.
- Step 2: `/custom-modules/qaAsset` renders the standard list with the published
  views in the view selector and the Serial Number column; an empty list shows
  the empty state.
- Step 3: the published form renders; `POST /api/data/qaAsset` returns 201 and
  the record appears in the list.
- Step 4: `/custom-modules/qaAsset/<id>` renders the record shell; `PATCH`
  returns 200.
- Step 5: both show the not-found state; no error modal; no
  `SYSTEM_UNEXPECTED_ERROR` row.
- Step 6: the designer lists the module; rename and hide apply to the sidebar.
- Step 7: no entry; the route shows access denied.
- Step 8: the entry disappears and the routes show not-found.
- Step 9: list and record pages reflow like other runtime modules.

## Notes

Created 2026-09-13 at `4d249b40` for REG-492. Custom-module screens use the
standard runtime command set; the published action bar is not consumed yet
(tracked as a follow-up on BUG-3494), so do not fail this scenario on it.
