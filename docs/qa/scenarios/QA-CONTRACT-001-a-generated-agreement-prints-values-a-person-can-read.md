# QA-CONTRACT-001 — A generated agreement prints values a person can read

## Preconditions

None for the automated half. For the manual half: Platform Admin, a seeded
`TENANT_PROVISIONING_SERVICE_ORDER` template, and an API restarted since
`seed:config` was last run.

## Steps

1. `npm --workspace api run test -- placeholder-formatting`
2. Manual: open **Templates → DijiPeople Tenant Provisioning & Service Order**
   and press **Preview sample data**.
3. Read sections 1, 2, 3, 4 and 6 in full.
4. Generate a real agreement from the template against a customer with a plan
   price, and read the same sections.

## Expected Result

Automated: a percentage carries its sign and no trailing zeros; a date renders
as "1 October 2026"; money carries the agreement's currency code and still
renders without one; a boolean is Yes/No; a count is thousand-separated; a
collection is a list or a table; an uninterpretable value is unchanged.

Manual: section 2 shows a bulleted list, not `["Employees",...]`. Section 4
shows a table with Name / Type / Status headers, not a JSON array. Section 6
reads "Uptime target 99.5%". Section 3 shows a date in words. The customer line
names the country once.

## Notes

The value of this scenario is that it covers the **executed** document, not only
the preview. `formattingRule` had been declared on nineteen placeholders and
applied by nothing, so signed agreements carried the raw values — a service
level printed as "99.5" is a commercial document saying something other than
what was agreed.

Consideration when re-running: existing agreements keep their stored HTML and
are *supposed* to. An executed document is immutable; only newly generated ones
pick this up. The seeded template itself refreshes on `npm run seed:config`,
which is required before the manual half means anything.
