# QA-DEPLOY-018 — Migrations connect over a direct endpoint, never a pooler

## Preconditions

A checkout of the repository. No database and no network are needed — the
assertion is over configuration, not behaviour.

## Steps

1. `npm run test:database-urls`.
2. Then the end-to-end form, if a Prisma CLI is available: from
   `services/api`, run `npx prisma validate --config prisma.config.ts` with
   `DATABASE_URL` set to a host containing `-pooler`.
3. Repeat step 2 with `DIRECT_DATABASE_URL` also set to the same host
   *without* the `-pooler` infix.

## Expected Result

Step 1 passes. Step 2 fails at config load with a message naming
`DIRECT_DATABASE_URL` and BUG-0086 — not a `P1002` lock timeout ten seconds
later. Step 3 succeeds.

A pooled `DATABASE_URL` is fine on its own terms: the runtime does not need
session state. Only the migration connection must be direct.
