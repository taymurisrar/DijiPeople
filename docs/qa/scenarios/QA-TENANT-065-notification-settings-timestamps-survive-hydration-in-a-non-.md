# QA-TENANT-065 — Notification settings timestamps survive hydration in a non-UTC tenant

## Preconditions

A tenant whose configured timezone is NOT UTC — the mismatch is invisible in a
UTC tenant.

At least one saved email provider and one email template, so the Updated column
has a timestamp to render.

A browser session already inside the app, because the formatting effect must have
run once on a previous page.

## Steps

1. Sign in and open any authenticated page. Let it settle.
2. Navigate **within the app** to Settings -> Notifications -> Email Providers.
   Do not reload.
3. Read the Updated column and watch for the error dialog.
4. Navigate to Settings -> Notifications -> Templates and repeat.
5. As a control, hard-reload each page.

## Expected Result

- The Updated column shows the time in the tenant’s timezone, not UTC.
- No error dialog appears, and no SYSTEM_UNEXPECTED_ERROR reaches the client
  error log.
- The hard reload in step 5 looks identical, and proves nothing on its own:
  effects run after hydration, so both renders use the fallback and the original
  defect cannot appear that way. Step 2 is the test; step 5 is the control that
  stops a passing reload being mistaken for a passing fix.
