# QA-RUNTIME-025 — A server failure classified by a message React had already deleted

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-315 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

Both the minified and un-minified #441 placeholders, quoted verbatim, resolve to a deliberate `server-error` variant and explicitly **not** to the `unexpected` fall-through. An explicit HTTP status outranks every message heuristic, including a 404 whose message says "permission". The four message branches stay reachable for client-originated failures, and the fall-through stays reachable.

## Expected Result

The behaviour holds as REG-315 describes it. There is no automated guard, so this scenario is executed by hand and its result recorded here.

## Why This Is Reusable

`classifyDashboardError` decided what to show by string-matching `error.message` against session-expired, access-denied, not-found and api-error patterns. For anything thrown in a Server Component the message it receives is always React's production placeholder — "Minified React error #441…" — which contains none of those substrings, by design, so server detail does not leak
