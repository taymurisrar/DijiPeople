# QA-TENANT-051 — A rejected Stripe webhook names the check that refused it

## Preconditions

- The billing webhook endpoint, reachable.

## Steps

1. Run `npm --workspace api run test -- webhook-rejection-diagnostics`.
2. `POST /api/billing/stripe/webhook` with no `stripe-signature` header.
3. Post with a header but a body that is not raw.
4. Post with a valid-looking header whose signature does not verify.
5. Read the API logs for each.

## Expected Result

- The suite passes.
- Each rejection logs `stripe.webhook.rejected` naming a different `check`.
- No log line contains the request body or the signature value.
- All three still answer Stripe the way they always did.

## Notes

**This scenario does not close BUG-1543.** The cause of the production
rejections is still unknown; what this covers is being able to tell which of
three refusals fired without log archaeology.

The three need opposite responses, which is why telling them apart matters: a
missing header means the caller is not Stripe, a non-Buffer body means the
raw-body middleware did not run for this route, and a failed verification means
either the wrong webhook secret for this endpoint or a forgery.

The open work is the re-run BUG-1543 specifies: complete a paid signup on
production now that BUG-1516 is fixed, and see whether the 400 recurs. If it
does, the log now names the check.
