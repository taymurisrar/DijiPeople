# QA-PLATFORM-011 — The console theme repaints the console

## Preconditions

Platform Admin, signed in, with a machine whose system theme can be changed
while the browser stays open.

## Steps

1. `npm --workspace admin run test -- console-theme`
2. Set preferences → theme → **Dark**. Visit the dashboard, a list page, a
   record page with tabs, a form with inputs and selects, and a contract
   template.
3. Set theme → **Light** on a machine set to dark.
4. Set theme → **System**. Change the machine's theme without reloading.
5. With Dark active, open a contract template and look at the document sheet.

## Expected Result

Step 2: every card, table, border, heading and body text repaints. Headings are
*brighter* than body text, not darker. Inputs and selects have dark backgrounds
with legible text. No white card sits on a dark page.

Step 3: the console stays light.

Step 4: the console repaints immediately, without a reload.

Step 5: the document sheet is **white**. This is deliberate — a contract is
paper, and an author must see what the counterparty receives.

## Notes

`color-scheme: dark` is not a theme; it repaints what the browser draws and
nothing the application draws. That was the whole implementation before this,
which is why step 2 lists surfaces rather than saying "check dark mode".

Considerations when re-running:

- Status pills (rose / amber / emerald / sky) are **not** remapped. They should
  still be legible because each pairs a light tint with dark text of the same
  hue. If one is not, that is a finding.
- Arbitrary colour values (`bg-[#f8fafc]`) are not covered either. Anything that
  reads wrong is a call site to convert to a token, not a reason to widen the
  stylesheet's selectors.
- Step 4 is the one that regressed silently before: resolving the system
  preference once at load is a setting that is right at noon and wrong at
  sunset.
