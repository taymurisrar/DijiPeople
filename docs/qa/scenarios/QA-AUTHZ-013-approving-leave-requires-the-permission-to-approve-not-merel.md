# QA-AUTHZ-013 — Approving leave requires the permission to approve, not merely to read

## Preconditions

- Two tenant roles: one granted `leave-requests.approve`, one granted only
  `leave-requests.read`.
- A leave request in a state a decision can be taken on.

## Steps

1. `npm --workspace api run test -- leave-approval-permissions`
2. As the read-only role, call `POST /leave-requests/:id/approve` **directly**,
   not through the UI.
3. Repeat for `/reject`.
4. As the approving role, call both.
5. Confirm `POST /leave-requests/:id/cancel` still answers to
   `leave-requests.cancel`.

## Expected Result

- The suite passes: both routes declare their own legacy key and their own
  matrix privilege, and **neither declares `read`**.
- Steps 2 and 3 are refused. Before the fix they succeeded — hiding the button
  was the only thing stopping anyone who could read a request from approving it.
- Step 4 succeeds.
- Step 5 is unchanged; `cancel` was always correct.

## Notes

**Step 2 has to bypass the UI to mean anything.** The button was already hidden
from roles without the key, so a browser-only check passed against the live
defect. `apps/web/AGENTS.md` says frontend gating is UX only and every gated
action must also be enforced server-side; this is the case where nothing did.

The suite reads decorators through the `Reflector` rather than grepping the
file, because decorators are inherited and composed and the source cannot show
what Nest assembles.

Its **negative** assertions carry the weight. `toContain('APPROVE')` passes
while `READ` is also declared — and on the matrix side that is not a widening
but a total defeat, because `PermissionsGuard` requires *at least one* matrix
privilege rather than all of them. A guard written the obvious way would have
gone green over the live defect.

**End-to-end approval is not covered here and cannot be yet.** BUG-1967 and
BUG-1968 mean no leave request reaches an approval step on a fresh tenant, so
step 4 needs a seeded balance and a resolvable approval chain. What this
scenario establishes is the gate, not the journey.
