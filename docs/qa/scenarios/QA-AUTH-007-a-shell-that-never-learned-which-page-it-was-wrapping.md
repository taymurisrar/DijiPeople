# QA-AUTH-007 — A shell that never learned which page it was wrapping

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-335 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

The topbar resolves its heading from `usePathname` through the same `resolveRouteTitle` that names the browser tab, so the heading and the document title cannot disagree; the literal `pageTitle = "Dashboard"` default does not exist; a route may still override. The landmark exists **exactly once**, in the layout, with a skip link pointing at it — and the spec walks every `.tsx` under `app/(authenticated)` plus the two shared components that used to render one, asserting none of them does.

## Expected Result

The behaviour holds as REG-335 describes it. The automated guard is `apps/web/app/components/workspace-shell-headings.spec.ts`; a run of that suite is sufficient evidence for this scenario.

## Why This Is Reusable

Two structural defects in one shell. `dashboard-topbar.tsx` declared `pageTitle = "Dashboard"` as a default and `app/(authenticated)/layout.tsx`, its only caller, never passed one — so the single `h1` on all 232 authenticated routes said "Dashboard"
