# QA-TENANT-019 — An empty list distinguishes no data from no matches

## Preconditions

- A tenant provisioned through the paid public signup, with no data entered.

## Steps

1. Run `npm --workspace web run test -- empty-state-message`.
2. Sign in and open Employees with no search typed and no filter applied.
3. Type a search term that matches nothing.

## Expected Result

- Step 2 reads "No records yet." and does not mention search or filters.
- Step 3 reads "No records match the selected search or filters."
- The two states are distinguishable.

## Notes

Only reproducible on a workspace that genuinely has no data. An existing tenant
with records cannot show the first state at all, which is why this survived
until the first real first-run on 2026-08-27.

The exact wording is not the point and may improve per module; that the two
states differ is.
