# QA-TENANT-040 — A shell owns no headings or landmarks the page should own

## Preconditions

- Platform Admin and a tenant workspace, both signed in.

## Steps

1. Run `npm --workspace admin run test -- shell-landmarks` and
   `npm --workspace web run test -- workspace-shell-headings`.
2. On any admin screen, list the `<main>` landmarks and the `<h1>` elements.
3. Navigate by headings from the top of the page.
4. Press Tab once from page load.
5. Read the browser tab's title on three different screens.
6. Repeat 2–3 in the tenant workspace.

## Expected Result

- Both suites pass.
- Exactly one `<main>` and one `<h1>` per screen, and the `<h1>` names the page.
- Heading navigation starts with the page's own name, not "Control Hub" or
  "Workspace".
- The first Tab reaches a skip link.
- The three tab titles differ from one another.

## Notes

Do not spot-check. The reason these survived is that every screen was equally
wrong, so they read as the design rather than as a defect — PLAN-019 warns about
this shape and BUG-0073 was the same class. Re-run the sweep across routes.

**Two known gaps, both deliberate.** Three admin routes are client components,
which Next forbids from exporting `metadata`, so they keep the default title.
And the duplicate `<main>` the tenant audit reported was not reproducible from
the source — no shell renders one and no shared layout nests one — so if a screen
still shows two, that finding is new information and belongs on BUG-1673.
