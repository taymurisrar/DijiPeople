# QA-LANDING-012 — The country list and the step labels survive a lookup outage

## Preconditions

None. Both assertions are over values that ship in the landing bundle, which is
the point of the scenario — neither depends on the API being reachable.

## Steps

1. `npm --workspace landing run test -- use-country-options`
2. `npm --workspace landing run test -- onboarding-wizard`
3. Manually, to confirm the rendered half nothing here covers: stop the API,
   open `/subscribe`, and look at the Country field and the step rail.

## Expected Result

The bundled country list is non-empty with no request completed, gives every
entry a two-letter ISO code and a name, excludes `OTHER`, and keys each entry
uniquely. Every wizard step has a rail label; none is longer than one segment of
a five-across rail holds; no two are the same word.

Manually: Country is a `<select>` with the API stopped, and no step label is
clipped.

## Notes

This scenario exists because the previous fix to this form was reported as not
having shipped. The country field fell back to a **free-text input** when
`/public/geography/countries` could not be read, and an API process that had not
restarted since that endpoint was added answers 404 — so a lookup outage and an
unshipped change were indistinguishable on screen.

The length assertion on the labels is a proxy, and is stated as one. Nothing
here renders the rail; step 3 is the only part that observes it, and it is
manual on purpose rather than described as covered.
