# QA-AGENT-008 — The desktop agent is one settings screen on the shared shell

## Preconditions

- Platform Admin, signed in with `appDownloads.manage`.
- At least one published release, or none — both states are checked.

## Steps

1. Run `npm --workspace admin run test -- desktop-agent-settings`.
2. Open **Settings**. Look for a **Desktop agent** card under Operations.
3. Open it. Switch between the **Releases** and **Rollout** tabs.
4. Navigate to `/app-releases` directly.
5. Navigate to `/agent-rollout` directly.
6. Look for App releases or Agent rollout in the sidebar.
7. Narrow the window to a phone width and check both tables.

## Expected Result

- The suite passes.
- The screen renders on the same shell as every other settings screen: the
  "Back to settings" link, the Settings eyebrow, the page heading inside the
  header — not a dark panel with a heading floating above it.
- Both tabs render, each with its own description, and the tab strip is a
  `role="tablist"` reachable by keyboard.
- Steps 4 and 5 land on `/settings/desktop-agent`. Neither 404s: both URLs are
  in bookmarks and in the release runbook.
- Step 6 finds neither. Operations keeps only Monitoring.
- Step 7: each table scrolls inside its own container. The page itself does not
  scroll sideways.
