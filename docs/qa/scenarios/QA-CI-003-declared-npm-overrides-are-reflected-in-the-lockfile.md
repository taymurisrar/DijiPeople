# QA-CI-003 — Declared npm overrides are reflected in the lockfile

## Preconditions

A committed `package-lock.json`, and at least one `overrides` entry in the root
`package.json`. No seeded data and no running services — this reads two files.

## Steps

1. Run `node scripts/check-overrides-applied.mjs`.
2. For each `overrides` entry, the check finds every resolved instance of that
   package in the lockfile — including copies nested under other packages — and
   compares the resolved version against the demanded range.
3. To prove the check can fail, set an override to a range nothing can satisfy
   (`overrides["node-gyp"] = "^99.0.0"`) and run it again.
4. Restore the manifest and run it a third time.

## Expected Result

Step 1 exits `0` and reports `APPLIED` for every override.

Step 3 exits `1` and names the offender:
`IGNORED  node-gyp  resolved 11.5.0, override demands ^99.0.0`.

Step 4 exits `0` again.

An override naming a package absent from the graph also fails, because it is
either a typo or a stale entry that reads as protection nobody actually has.

A range form the check does not understand is reported `UNCHECKED` and does not
count as a pass. Silent acceptance is the failure mode being guarded against, so
the guard must not become an instance of it.

## Notes

Created 2026-08-21 at `4703112`, for BUG-0163.

**Why the obvious check does not work.** The first attempt asserted that
`package-lock.json` records an `overrides` key at `packages[""]`. npm 11 writes
no such key even when the overrides are applied and effective, so its absence
proves nothing — the resolved versions are the only observable that separates an
applied override from an ignored one.

**Why this is worth a regression at all.** The override npm silently ignored was
the fix for this repository's only `critical` advisory: `tar`, reachable through
the desktop agent. `npm pkg get overrides` returned the key, `npm install`
reported "up to date", and nothing moved. A security fix that quietly does not
happen is worse than one that fails loudly.
