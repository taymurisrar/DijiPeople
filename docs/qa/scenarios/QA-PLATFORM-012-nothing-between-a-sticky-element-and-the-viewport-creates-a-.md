# QA-PLATFORM-012 — Nothing between a sticky element and the viewport creates a scrollport

## Preconditions

Platform Admin, a contract template long enough to scroll, and a list long
enough to scroll its table header out of view.

## Steps

1. `npm --workspace admin run test -- sticky-containment`
2. Manual: open a contract template with **Fields & signatures** open and scroll
   the document to the bottom.
3. Open a data-table list page with more rows than fit and scroll.
4. Check that no page has gained a horizontal scrollbar.
5. Measure the document sheet: it should render at its full width where the
   viewport allows.

## Expected Result

Step 2: the fields rail stays in view for the whole scroll, scrolling
internally when its own content is taller than the viewport.

Step 3: the table header and pagination bar stay in view. These were written to
stick and never did.

Step 4: no horizontal scrollbar anywhere.

Step 5: the sheet is not squeezed by the rail.

## Notes

The cause was one word in a different file: `overflow-x: hidden` forces the
other axis to compute to `auto`, making the wrapper a scroll container, and a
sticky element sticks to its nearest scroll container — which had auto height
and never scrolled. `overflow-x: clip` does not.

Step 4 exists because `clip` is the reason the original `hidden` was there. If
switching it re-introduces horizontal overflow somewhere, that is a finding
about that page, not a reason to revert the wrapper.

Step 3 is deliberately about a screen nobody reported: every sticky element in
the console was inert, so the reported symptom was one instance of a general
fault.
