# QA-PLATFORM-021 — Editing a plan price saves, and its payload matches the update DTO

## Preconditions

A plan with at least one price, and a signed-in platform operator.

## Steps

1. Open the plan in Platform Admin and select the Pricing tab.
2. Change the amount on an existing price and save.
3. Create a new price.
4. Separately, run the real `ValidationPipe` settings over both payload shapes,
   and parse the component's payload builders against the DTOs that receive them.

## Expected Result

- The edit returns 200 and the new amount renders. It must not return 400
  `property syncToStripe should not exist`.
- Creating a price still requests a Stripe sync — `syncToStripe` belongs on the
  create body and only there.
- Every key the component sends is declared by the DTO receiving it. An extra
  property is a 400 on the whole request under `forbidNonWhitelisted`, not an
  ignored field.

## Notes

The contract spans two workspaces — a `JSON.stringify` in a React component and
a class-validator DTO in the API — and nothing in the type system holds the two
together, so it is asserted from both sides.

Worth re-reading when a screen is made reachable after being unreachable: this
defect had existed as long as the panel had, and only surfaced once the Pricing
tab was restored. Rendering is not working.
