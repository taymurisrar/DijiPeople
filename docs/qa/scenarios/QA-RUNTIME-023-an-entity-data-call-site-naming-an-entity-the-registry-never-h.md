# QA-RUNTIME-023 — An entity-data call site naming an entity the registry never held

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-313 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

Every `buildEntityDataUrl({ entityLogicalName })` call site under `apps/web/app` and `apps/web/lib` names an entity `ENTITY_REGISTRY` declares. Two vacuity guards sit above it: the registry parse must have returned entities and must include `employees`, and the source scan must have found at least one call site.

## Expected Result

The behaviour holds as REG-313 describes it. The automated guard is `apps/web/app/components/entity-data/entity-registry-contract.spec.ts`; a run of that suite is sufficient evidence for this scenario.

## Why This Is Reusable

`/users` fetched the generic entity-data endpoint for the logical entity `users`. `ENTITY_REGISTRY` in `services/api/src/modules/data/entity-registry.ts` has only ever held one entity, `employees`, so `GET /data/users` returned 404 before a single row was read
