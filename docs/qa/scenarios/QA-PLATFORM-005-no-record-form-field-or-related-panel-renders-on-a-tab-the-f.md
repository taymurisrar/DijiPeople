# QA-PLATFORM-005 — No record form field or related panel renders on a tab the form never declares

## Preconditions

None. A load-time invariant in the registry plus a per-module assertion.

## Steps

1. For every record form that declares tabs, collect the declared tab keys.
2. Assert no section names a tab absent from that set.
3. Assert no field sits in a section that is itself unreachable.
4. Assert every related-record panel names a declared tab.

## Expected Result

Nothing renders on no tab. The registry throws at import when a placement is
unreachable, so the admin app fails to boot rather than shipping an invisible
field.

## Notes

Two shapes produced the same invisible result. `completeFormsFromSchema` pinned
its generated section to the tab key `details`, which exists only in the default
tab set — so any module declaring its own tabs got fields that satisfied the
schema-coverage rule and rendered nowhere. The plans module declared two
related-record panels with no tab at all, and the record page draws a
relationship only when its tab is active.

The lesson is not the placement fix. It is that the schema-coverage rule asked
whether a field was **present** on a form and never whether the form could show
it — the second time an assertion in this repository has proven presence and
nothing else.
