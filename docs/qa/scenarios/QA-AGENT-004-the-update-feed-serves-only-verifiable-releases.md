# QA-AGENT-004 — The agent update feed serves only verifiable releases

## Preconditions

`services/api` builds and its jest project runs.

## Why this scenario exists

Auto-update is the one path where a wrong assumption installs software on an
employee's machine unattended, and every way it fails here fails *quietly*.

The original defect was that no route served `latest.yml` at all: every agent
404'd on every check for months, and because electron-updater swallows that and
the agent logged no reason, it looked exactly like a network blip in the only
logs anyone would read.

The defect this scenario guards against now is subtler. A release advertised in
the feed but missing its sha512 would be downloaded, refused at verification, and
retried — forever, silently, consuming bandwidth on every agent. An
unadvertised release is a missed update; an unverifiable one is a loop.

## Steps

1. `npm --workspace api run test -- --testPathPatterns "update-feed|release-publisher"`

## Expected Result

- The document carries `version`, `files[].url`, `files[].sha512`,
  `files[].size`, `path`, `sha512` and `releaseDate`.
- The version is **quoted**, so YAML cannot read `1.10` as the float `1.1`.
- The query requires `checksumSha512`, `fileName`, `fileSizeBytes` and
  `publishedAt`, and restricts to active STABLE.
- The publisher computes sha512 as **base64** from the bytes that arrived,
  carries it through `promote()`, and verifies it case-sensitively on read-back.

## Negative Case

Removing `checksumSha512` from the read-back fixture fails `verifyRegistration`
with `sha512 checksum differs` — which is exactly how the five existing publisher
tests failed the moment that check was added. Removing the quoting fails
`quotes the version so YAML cannot reinterpret it`.

## Notes

Base64, not hex: hex would fail every verification while looking perfectly
correct in the database. Case-sensitive comparison for the same reason —
lower-casing a base64 digest compares two different values as equal.

This scenario cannot prove electron-updater *accepts* the document, only that the
document is what electron-updater parses. The end-to-end run against a real
published artefact is [[ITEM-0052]].
