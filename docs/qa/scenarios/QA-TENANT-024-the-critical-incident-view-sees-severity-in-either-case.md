# QA-TENANT-024 — The critical incident view sees severity in either case

## Preconditions

- Incidents recorded with severity in mixed case, which production has.

## Steps

1. Run `npm --workspace api run test -- incident-severity-case`.
2. Open Settings then Monitoring, and select the Critical view.
3. Compare the count against a direct query for errors regardless of case.

## Expected Result

- The Critical view returns rows stored lowercase as well as uppercase.
- The two counts agree.

## Notes

The failure mode is silent: the screen is not empty and reports nothing wrong,
it simply answers a different question. A census on 2026-08-27 found 1,466 rows
lowercase against 5 uppercase, so an exact match returned 1 of the 15 errors
that existed.

The duplicated levels in the `in` list look redundant and are load-bearing —
Prisma's `in` has no insensitive mode. Normalising the column is the deeper fix
and needs a migration.
