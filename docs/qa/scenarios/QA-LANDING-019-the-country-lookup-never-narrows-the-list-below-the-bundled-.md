# QA-LANDING-019 — The country lookup never narrows the list below the bundled shortlist

## Preconditions

A running landing app. No database state is required — the predicate under
test is pure, and the point of the scenario is that it decides correctly
*without* asking anything.

## Steps

1. Call `isUsableLookupList` with a list shorter than `BUNDLED_COUNTRIES` —
   in particular a list of **8**, which is what production returns today.
2. Call it with `[]`, `null`, `undefined` and a non-array.
3. Call it with a list of 250 (the full ISO set) and with one exactly as long
   as `BUNDLED_COUNTRIES`.
4. For an end-to-end check, open `/subscribe` against an API whose
   `/public/geography/countries` returns fewer countries than the bundle, and
   count the options in the Country select.

## Expected Result

- **Steps 1–2** — rejected. The bundled list stands. A narrower answer is a
  degraded answer, and an outage that returns *something* is still an outage.
- **Step 3** — accepted, in both cases. Widening is the reason the lookup
  exists; a fix that blocked it would be worse than the defect it replaced.
- **Step 4** — the Country select offers at least `BUNDLED_COUNTRIES.length`
  options, never the eight defaults.
