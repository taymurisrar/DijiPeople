# QA-TENANT-018 — API proxy routes never advertise an encoding they did not apply

## Preconditions

- A tenant workspace reachable in a browser, signed in.
- The repository checked out; the guard is a static check and needs no server.

## Steps

1. Run `npm --workspace web run test -- proxy-response-headers`.
2. In the browser, sign in and open the workspace overview.
3. Read the console and look for a modal.

## Expected Result

- Every route handler passes; the walker reports having found handlers at all.
- No `ERR_CONTENT_DECODING_FAILED` in the console.
- No "Server unavailable" dialog, and the page beneath is clickable.

## Notes

The browser half matters as much as the unit half. `curl` reports the mismatched
header but hands back the body regardless, so a command-line check looks like a
pass while the product is broken — which is how this reached production.

The guard is structural on purpose: nine identical call sites were the defect,
so the test asserts the shape is absent everywhere rather than that one route
behaves.
