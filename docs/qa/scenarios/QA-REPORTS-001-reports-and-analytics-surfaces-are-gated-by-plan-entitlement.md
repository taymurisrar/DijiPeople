# QA-REPORTS-001 — Reports and Analytics surfaces are gated by plan entitlement, not only permission

## Preconditions

A tenant on a plan that does **not** include the analytics capability under
test, and a user in it holding every reporting *permission* — the point of the
scenario is that permission and entitlement are different gates.

A second tenant on a plan that does include it, for the positive case.

## Steps

1. As the user in the unentitled tenant, request the analytics catalog.
2. Request each surface and report the catalog would normally list.
3. Ask the query engine directly for a metric belonging to the unentitled
   capability, bypassing the catalog — this is the step that matters, because
   hiding a surface in the UI is not the same as refusing it at the API.
4. Repeat 1 to 3 as the user in the entitled tenant.

## Expected Result

- The unentitled tenant's catalog omits the capability's surfaces entirely.
- A direct query for one of its metrics is **refused by the API**, not merely
  absent from a list. A read filter is not an access control: the surface being
  hidden proves nothing about the engine behind it.
- The entitled tenant sees the surfaces and its queries succeed.
- Nothing in the refusal enumerates what the tenant would need to buy in a way
  that discloses another tenant's configuration.
