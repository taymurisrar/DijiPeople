# QA-ATTENDANCE-012 — An approved correction applies its requested mode and site, and re-derives status

## Preconditions

Approved correction requests covering each case: one naming a work site, one
naming none, one requesting REMOTE, one requesting FIELD mode, and one for a day
with no attendance entry at all.

## Steps

1. Approve a correction naming a work site and read the entry's
   `officeLocationId`.
2. Approve one naming no site and confirm the existing site is untouched.
3. Approve a REMOTE request and read both the entry's mode **and** its status.
4. Approve one naming no mode and confirm the mode is untouched.
5. Approve a FIELD-mode request.
6. Approve a correction for a day with no entry.

## Expected Result

- The approved site reaches `officeLocationId`; a correction naming none leaves
  the existing value alone.
- An approved REMOTE request reaches the entry's mode, and status is re-derived
  **from the approved mode**, not from the mode as it was. Deriving from the
  stale mode is the natural way to reintroduce this, so that is the assertion to
  watch.
- A FIELD-mode approval is refused outright rather than silently doing nothing.
- For a wholly missing day the entry is created carrying the approved mode and
  site.
- No case leaves the approval recorded and the entry unchanged. That silent
  outcome is the defect: it is worse than a refusal, because nothing tells the
  employee their correction did not take.
