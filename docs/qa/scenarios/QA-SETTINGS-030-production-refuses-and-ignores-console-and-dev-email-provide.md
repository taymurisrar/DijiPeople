# QA-SETTINGS-030 — Production refuses and ignores Console and Dev email providers

## Preconditions

- A local API against a throwaway database, started with `APP_ENV=production`.
- Tenant 1 holds only an enabled default Console provider.
- Tenant 2 holds no provider at all.
- The platform relay can be switched between enabled SMTP and disabled.
- Email delivered to a controlled mailbox only.

## Steps

1. `POST /api/notifications/email-providers` with `providerType: "CONSOLE"`, then
   with `"DEV"`.
2. On tenant 1: update the Console row keeping it enabled; set it as default;
   switch an SMTP row to CONSOLE.
3. On tenant 1: disable the Console row; separately switch it to SMTP.
4. With the relay enabled as SMTP, read
   `GET /api/notifications/email-providers/effective` for tenant 1 and send a
   template test.
5. With the relay disabled, repeat step 4.
6. Run `npm run seed:config` with `APP_ENV=production`, then read tenant 2's
   providers.
7. Restart without `APP_ENV`/`NODE_ENV` production and repeat step 1.
8. After release, on the demo tenant: send a template test to the controlled
   mailbox and read the delivery log.

## Expected Result

- Step 1: 400 `EMAIL_PROVIDER_TYPE_NOT_ALLOWED` for both.
- Step 2: each refused with the same code.
- Step 3: both succeed.
- Step 4: `deliveryPath` is the platform relay; the test arrives.
- Step 5: not delivered, with the reason "No email provider is available."; the
  send is recorded FAILED.
- Step 6: no "Console Provider" row is created.
- Step 7: both types are accepted.
- Step 8: the email arrives; the log row is SENT with providerType SMTP.
- Every provider write is audited without its configuration.
