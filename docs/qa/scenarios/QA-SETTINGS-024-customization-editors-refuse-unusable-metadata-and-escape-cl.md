# QA-SETTINGS-024 — Customization editors refuse unusable metadata and Escape closes only the open dropdown

## Preconditions

- A tenant administrator holding the customization permissions.
- A custom module with at least one Reference field.

## Steps

1. Action Bars → Add action bar; add a row and leave "Choose a command"; Create.
2. Send the same action bar payload directly to `POST /api/customization/layers/ensure`.
3. Relationships → Add relationship; open Reference field.
4. Send a relationship with `referenceField: "dd_assignedEmployee"` (not a field
   of the module) directly to the API.
5. Packages → New package with key `qw_walkthrough`; Save.
6. In the Add field, Add relationship and Action bar dialogs: type into a field,
   open a dropdown, press Escape; press Escape again.
7. Open the module list for a module whose components are all Draft; publish it
   and reload.

## Expected Result

- Step 1: the dialog names the row that needs a command; nothing is saved.
- Step 2: 400 naming the action row.
- Step 3: the Reference field control offers only the module's reference fields.
- Step 4: 400.
- Step 5: the stored package key is exactly `qw_walkthrough`.
- Step 6: the first Escape closes only the dropdown and the typed input remains;
  the second closes the dialog.
- Step 7: the module reads "Draft" before publish and "Published" after; the
  Package column shows the owning package's name.

## Notes
