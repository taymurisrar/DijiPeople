# QA-CONTRACTS-001 — A template draft is edited in place, published, and its agreement renders every placeholder

## Preconditions

A platform user with `contracts.manage`. A contract template whose latest
version is an unpublished draft that no agreement has been drafted from, and a
published version holding placeholders an editor wrapped in links
(`{{<a href="http://customer.contact.email">customer.contact.email</a>}}`).

## Steps

1. Save the draft with a lifecycle gate from the supported list and both signer roles.
2. Try to save a published version, an older draft, and a draft an agreement uses.
3. Try a free-text gate (`customer_onboarding`) and a free-text signer role.
4. Publish the draft; then unpublish the published version.
5. Create an agreement from a template whose signer plan puts DijiPeople first.
6. Render the linked-placeholder version, and send an agreement that was issued once before.
7. Send an agreement whose document still contains `[REQUIRED — CONFIRM]`.

## Expected Result

1. The draft is updated in place — no new version — stored with clean tokens, and audited with before and after snapshots.
2. Each refusal is `CONTRACT_TEMPLATE_VERSION_LOCKED`; nothing is written.
3. `CONTRACT_TEMPLATE_GATE_INVALID` and `CONTRACT_TEMPLATE_SIGNER_ROLES_INVALID`.
4. Publishing supersedes the old version without clearing its `publishedAt`; unpublishing also deactivates the template.
5. The DijiPeople party is a required signer in order 1 and the counterparty in order 2; signing mode follows the template.
6. No raw token remains; `{{contract.version}}` freezes as `2` into the signing copy and its snapshot.
7. `CONTRACT_DOCUMENT_CONTENT_INVALID`; nothing is sent.
