# QA-RUNTIME-015 — Every runtime record panel is mounted on a tab an operator can reach

## Preconditions

`apps/admin/app/_components/runtime/runtime-record-page.tsx` on the branch under
test, and the platform module registry it reads.

## Steps

1. Extract every bespoke panel guard from the record page — each is a
   `moduleKey === "x"` paired with an `activeTab === "y"`.
2. For each, resolve the module definition and ask whether tab `y` survives the
   tab filter: it must have form fields, a related-records panel, a timeline, or
   be named in the `hasRuntimePanel` allowance.
3. Separately, open a plan record page in Platform Admin and read the tab bar.

## Expected Result

- Every panel guard lands on a tab that can actually be selected. A panel mounted
  on a filtered-out tab is unreachable code and must fail here.
- The plan record page shows a Pricing tab, and selecting it renders
  `PlanPriceManager` with the plan's per-currency, per-cycle prices.

## Notes

The rule is derived from the file rather than restated, so a panel added without
an allowance fails in CI rather than in a browser. This has now happened twice on
the same module — `entitlements` was fixed and `pricing` was not — and the
symptom both times was a capability quietly missing from a screen, with no error
anywhere.

Automated at `apps/admin/lib/runtime/runtime-record-panels.spec.ts`. Step 3 is
manual.
