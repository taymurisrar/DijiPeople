# QA-TENANT-034 — Routine protocol outcomes stay out of the triage queue

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.

## Steps

1. Run `npm --workspace api run test -- expected-protocol-outcome`.
2. Let a session expire, or call an authenticated route with no token.
3. Request a path the application does not serve.
4. Submit a form that fails validation.
5. Open **Settings → Monitoring** and read the triage queue.

## Expected Result

- The suite passes.
- The `401` and the `404` are recorded and searchable, and are **not** in the
  triage queue.
- The validation failure **is** in the queue.
- "Waiting for triage" does not count the routine outcomes.

## Notes

Step 4 is the important one and the easy one to skip. The record that proposed
this fix also suggested filing `400` validation rejections as routine, and doing
so would have hidden BUG-1742 — no lead could be created from Platform Admin, for
anyone, in production, presenting as a 400 saying `partnerId must be a UUID`.

A `404` naming a *record* also belongs in the queue; only an unmatched *route* is
routine. The two are the same status code and completely different events.

**Still open:** the 1,588 rows written before this. `npm run
repair:routine-incidents -- --dry-run` reports what it would move; it has not
been run against production.
