# QA-CONTRACTS-003 — Every required signer of an agreement has exactly one signature block

## Preconditions

An agreement template with a provider and a counterparty signature slot.
Signers: 1, 2, 3 and 5, mixing DRAWN, UPLOADED and TYPED methods, with
sequential and parallel signing orders. One non-signatory contact and one
optional signer on the agreement.

## Steps

1. Render the preview (`renderContractVersionHtml`, display mode) with the
   agreement's party signatories.
2. Render the executed copy (`renderSignatureEvidenceTokens`) from the
   evidence, then the PDF with cover and evidence appendix.
3. Render the signing version (freeze mode).

## Expected Result

- Preview and executed copy show exactly one block per required signer, all
  before the first schedule, labelled by party and signatory number.
- The primary counterparty block holds the primary signer even when a
  co-signer signed first.
- The contact and the optional signer get no block; re-rendering adds nothing.
- Freeze mode adds no block; the frozen HTML is unchanged.
- The PDF carries one image per drawn or uploaded signature; cover and
  appendix print the same agreement version.
