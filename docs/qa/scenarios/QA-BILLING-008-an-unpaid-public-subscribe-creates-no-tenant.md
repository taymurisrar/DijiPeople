# QA-BILLING-008 — An unpaid public subscribe creates no tenant

## Preconditions

Real PostgreSQL carrying the full migration history, and a plan price that can
reach checkout — one with a `stripePriceId`, created by the test rather than
borrowed from seed data. A Stripe double implementing only `customers.create`,
`checkout.sessions.create` and `verifyRecurringPrice`.

## Steps

1. Record `Tenant`, `Lead` and `Subscription` counts.
2. Call `createPublicSubscriptionCheckout` with valid company and contact
   details. Do not pay.
3. Re-count all three.
4. Count `CustomerAccount` rows for the buyer's email, and read `industry` and
   `companySize` on them.
5. Read the resulting `SubscriptionOrder`.

## Expected Result

All three counts are unchanged. Exactly **one** `CustomerAccount` exists for the
buyer, with `industry` and `companySize` both `null`. The order is
`PENDING_PAYMENT` with a Stripe session and customer recorded, and `tenantId` and
`subscriptionId` both `null`.

Counts at step 1 and 3 are **global, not scoped to the buyer**. BUG-0077 created
its rows under a second `CustomerAccount`, so a count scoped to the buyer's own
customer would have missed exactly the rows that mattered — which is one reason
the defect survived 1,382 passing tests.

## Notes

The `additive-migration-never-finished` pattern: a replacement path was added
beside the old one and the deletion deferred to a later package that never did
it. Both then ran on every request.

This scenario is the assertion whose absence let a work package close `DONE` with
`QA_STATUS = PASS` while the behaviour it was named for was unbuilt. The value is
not that it passes — it is that running it against the pre-fix source reproduces
the entire defect, including the fabricated `"Unknown"` columns, in the assertion
diff.
