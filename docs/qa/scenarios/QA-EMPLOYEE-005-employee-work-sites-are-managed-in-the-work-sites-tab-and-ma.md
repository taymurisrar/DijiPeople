# QA-EMPLOYEE-005 — Employee work sites are managed in the Work Sites tab and Make primary moves Location

## Preconditions

- A throwaway database (the steps write `EmployeeWorkSite` rows).
- Two active locations, Head Office and Warehouse.
- An employee whose Location is Head Office with no `EmployeeWorkSite` rows.
- User A holds `attendanceDevices.read` and `attendanceDevices.manage`; user B
  holds only `attendanceDevices.read`; user C holds neither.
- A stored employee form layout that still names the old `employee.workSites`
  widget.

## Steps

1. As user A, open the employee record → Work Sites tab.
2. Assign Warehouse with a Valid From date.
3. Edit Head Office's validity dates.
4. Make primary on Warehouse, then reload the record.
5. Remove Warehouse while Head Office is still active; then try to remove the
   only remaining site.
6. Edit the employee form and save, watching the network tab.
7. As user B, open the tab; as user C, open the record.
8. Repeat steps 1-2 at 400px.
9. Open a record rendered with the stored layout from the preconditions.

## Expected Result

- Step 1: one row, Head Office, Primary Yes; no "no assignments" text; the
  Organization section has no work-site panel or info box.
- Step 2: the row appears with Primary No; the database row is ACTIVE with
  `isPrimary=false`.
- Step 3: dates saved; Head Office stays primary (`isPrimary=true`,
  `Employee.locationId` unchanged).
- Step 4: Warehouse is primary, Head Office is not, and the form's Location
  reads Warehouse; both rows and `locationId` changed together.
- Step 5: a confirmation shows; after confirming, the other site is primary.
  Removing the only site shows the API refusal in the tab.
- Step 6: Location is read-only and the request carries no `locationId`.
- Step 7: B sees rows but no Assign, Edit, Remove or Make primary; C sees no tab.
- Step 8: the tab and Assign panel controls are not truncated.
- Step 9: no "no registered renderer" box.
