# QA-DEPLOY-016 — The browser install does no apt work and proves the browser launches

## Preconditions

A GitHub-hosted `ubuntu-latest` runner, or any machine with the repository's
dependencies installed. No database, no servers, no seeded data — this scenario
is about the browser install step alone, before any journey runs.

## Steps

1. Run `npm run test:browser:install`.
2. Read the metric block the script prints, and the `Browser install` table it
   appends to `$GITHUB_STEP_SUMMARY` when running in CI.
3. On CI, open the `Browser e2e` job and confirm the `Install the browser` step
   contains no `apt` output — no `Installing dependencies...`, no
   `azure.archive.ubuntu.com` fetches.
4. Confirm the browser journeys then run and pass.

## Expected Result

- `LAUNCH_PROBE` is `PASS`. The script does not merely download the browser; it
  starts one, opens a page, reads its title and closes it. That probe is the
  whole justification for dropping `--with-deps`, and a missing system library
  must fail *here*, named, rather than inside a journey where it would read as a
  product defect.
- `APT_DEPENDENCY_DURATION` is `0s (skipped …)` on a runner image that already
  satisfies the browser — which `ubuntu-latest` does today, every library
  logging "already the newest version" before this change.
- `TOTAL_BROWSER_INSTALL_DURATION` is under two minutes, and is dominated by
  `CHROMIUM_DOWNLOAD_DURATION` rather than by anything else.
- `PLAYWRIGHT_COMMAND`, `RUNNER_IMAGE` and `PLAYWRIGHT_VERSION` are reported, so
  a future change in any of the three can be attributed rather than guessed at.
- If the probe *does* fail, the run is still expected to succeed: the script
  emits a warning, runs `playwright install-deps`, probes again, and
  `PLAYWRIGHT_COMMAND` names both commands. A working browser is the invariant;
  the cost is what varies.

## Notes

Created 2026-08-19 at `e6f4cbe`; filled 2026-08-20.

Guards BUG-0079. The failure being prevented is not a crash — it is a required
gate whose duration is set by an external package mirror. `Install the browser`
ranged from 20s to 25m55s on identical code, and at the top of that range it
consumed the job's 30-minute timeout and failed the gate for a reason unrelated
to the commit.

Read the metrics, not the step timer. One number cannot tell a slow download
from a slow apt mirror, and those have completely different fixes — which is
why this defect took three attempts to diagnose.
