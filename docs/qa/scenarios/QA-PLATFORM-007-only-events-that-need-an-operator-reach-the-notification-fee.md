# QA-PLATFORM-007 — Only events that need an operator reach the notification feed

## Preconditions

None. Rule functions over plain event shapes.

## Steps

1. Offer a failed provisioning run, a failed billing operation and a failed
   webhook.
2. Offer routine audit traffic — a sign-in, a saved view, an export, a settings
   read.
3. Offer a *successful* webhook.
4. Offer the same failure with and without a reader's last-read timestamp.
5. Offer a failure on an entity type that has no record page.

## Expected Result

The three failures become notifications, critical, each carrying the action an
operator should take.

The routine traffic becomes nothing. The successful webhook becomes nothing.

Unread is true when the event is newer than the reader's last-read timestamp,
and true for everything when they have never opened the feed.

The entity with no record page gets no link — a link that 404s reads as a broken
console, which is worse than no link.

## Notes

Most of this is about **exclusion**, and that is the harder half. A feed built
from "recent platform events" passes every test written about what it includes
and fails the only thing the feature is for: an operator who is shown everything
learns to ignore the badge, and then misses the provisioning failure.

Before adding an event code to the rules, ask whether somebody would act on it.
If the answer is "it is useful context", it belongs in the event log, which is
still searchable and still evidence.
