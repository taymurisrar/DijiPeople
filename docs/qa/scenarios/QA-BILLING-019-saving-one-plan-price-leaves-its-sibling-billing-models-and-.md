# QA-BILLING-019 — Saving one plan price leaves its sibling billing models and markets active

## Preconditions

None. The scenario compares two declarations — a Prisma `where` clause and a
SQL unique index — so it needs no database. That is deliberate: [[TASK-0018]]
assumption A-06 recorded that a fake Prisma client *cannot* enforce the partial
unique index, which is precisely why the disagreement went unnoticed. Comparing
the declarations directly is the proof that was missing.

## Steps

```bash
npm --workspace api run test -- src/modules/super-admin/plan-price-supersede-scope.spec.ts
```

To confirm the scenario still bites, revert either supersede in
`super-admin.service.ts` to its three-column form:

```ts
where: { planId, billingCycle, currency, isActive: true }
```

and re-run.

## Expected Result

| | Expected |
|---|---|
| The migration still declares five columns | `planId, marketId, billingCycle, currency, billingModel` |
| Both supersede sites are found | exactly 2 — if this drops to 1, a call site was reshaped and coverage silently lapsed |
| Every supersede constrains all five | pass |
| Every supersede stays `isActive: true` | pass — the index is partial, so the query must be too |
| With either `where` reverted | **fail** |

## Notes

What this guards is not an edge case. Saving a `PER_SEAT` price destroyed the
`FLAT` price beside it, and with no `marketId` filter reached across markets
as well — nine of Starter's twelve production prices, with no error, no audit
row naming them, and a success message on screen.

The column list is read **out of the migration** rather than hard-coded, so the
test cannot drift: change the index and the expectation changes with it. Object
shorthand (`planId,`) counts the same as an explicit value (`marketId: null`).
