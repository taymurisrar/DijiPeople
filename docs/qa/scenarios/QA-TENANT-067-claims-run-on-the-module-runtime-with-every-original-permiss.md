# QA-TENANT-067 — Claims run on the module runtime with every original permission and status gate

## Preconditions

A tenant with claim types configured. One user holds claims.read-all, update, manager-approve, payroll-approve, reject and cancel; one self-service user holds claims.read-own and claims.create.

## Steps

1. Automated: run `npx jest --config jest.config.js claims-runtime record-page-shell.conformance claim-editor` in apps/web.
2. Browser, self-service: My Claims → New → save → add a line with a receipt-requiring subtype → Submit.
3. Browser, admin: Claims → open the submitted claim → Manager approve → Payroll approve; on another claim Reject with a reason; Cancel a third.
4. Open a non-DRAFT claim's edit route.

## Expected Result

- All three suites pass.
- Lists render through the standard runtime list, with status views.
- Each command appears only for its permission and status, exactly as before the migration.
- Reject refuses a reason under 3 characters.
- The line editor enforces the subtype filter and the receipt rule.
- A non-DRAFT edit route renders read-only.
- The self-service user never sees approve, reject or cancel.
