# QA-TENANT-020 — One paid signup produces exactly one customer record

## Preconditions

- Stripe in test mode.
- A company name and e-mail not already present as a customer.

## Steps

1. Run `DATABASE_URL="postgresql://u:p@localhost:5432/dummy" npm --workspace api run test -- checkout-customer-record`.
2. Complete a paid signup through `www.dijipeople.com` end to end.
3. List customers in the platform console and count rows for that company.

## Expected Result

- The unit suite passes, including the draft-continuation cases.
- Exactly **one** customer exists for the signup, holding the buyer's real
  e-mail and the organisation profile they entered.
- No row holds `pending@onboarding.invalid`.

## Notes

The unit half covers the decision; only a real signup covers the wizard actually
sending its draft id, so this is deliberately not fully automated.

Before the fix this produced two rows about 90 seconds apart — the first with
the placeholder e-mail and none of the organisation profile, the second with all
of it. That asymmetry is the quickest way to recognise a recurrence.

Check the Stripe webhook responses in the same window. Two customers made
payment attribution ambiguous, which is the CRITICAL alert in BUG-1543.
