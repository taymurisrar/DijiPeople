# QA-TENANT-046 — Creating a promotion does not publish it

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.

## Steps

1. Run `npm --workspace api run test -- promotion-safety`.
2. Open **Discounts & promotions**. Fill only Name and press **Add promotion**.
3. Choose a scope and an amount, and add it.
4. Read the new row's status.
5. Press **Activate** on it and read the dialog.
6. Repeat with a global scope and compare the dialog.

## Expected Result

- The suite passes.
- Step 2 is refused: the form asks for a scope, then for an amount.
- The created promotion is **Inactive**.
- Activate confirms, naming what the discount applies to.
- A global scope is presented as the dangerous case.

## Notes

Step 2 is the whole point. The old form's defaults — GLOBAL scope, 10%, active
on creation — meant one press published a live 10% discount against every
eligible subscription.

**Expect a support question rather than a bug:** an operator used to the old
screen will create a promotion and find it does nothing. That is intended.

**Still open, and the more consequential half:** whether Stripe or the platform
is authoritative for discounts. `syncToStripe` is still an unticked box, so what
the platform believes and what Stripe applies can differ from the moment a
promotion exists. That is a product decision, not a defect, and BUG-1751 records
it as unresolved.
