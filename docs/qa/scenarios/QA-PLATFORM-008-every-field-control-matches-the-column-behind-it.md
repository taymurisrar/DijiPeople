# QA-PLATFORM-008 — Every field control matches the column behind it

## Preconditions

None. A derivation check over the schema and the committed manifest.

## Steps

1. Regenerate the runtime manifest from `schema.prisma` in memory.
2. Compare every field's `defaultControl` with the committed file.
3. Read the declared country fields in the platform module registry.

## Expected Result

The manifest matches, including the control inferred for every email, phone,
URL and money column — Prisma has one string type, so without inference all of
them render as plain text boxes with no mobile keyboard and no validation.

Country is a lookup pointing at `/public/geography/countries`, and no module
declares it as text.

## Notes

The inference is narrow on purpose: anchored suffixes matched against the whole
column name, never substrings. `emailStatus` is a status, `phoneVerifiedAt` is a
date and `taxRatePercent` is a rate — a looser rule catches all three and is
worse than no rule, because a wrong control is harder to notice than a plain
one.

The country lookup is served from a single public projection specifically so
another hardcoded list has nowhere to appear. There were four before this: the
table, and one copy each in admin, landing, and the free-text box people
actually typed into.
