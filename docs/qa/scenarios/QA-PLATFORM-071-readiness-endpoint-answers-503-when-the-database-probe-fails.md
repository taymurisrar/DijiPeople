# QA-PLATFORM-071 — Readiness endpoint answers 503 when the database probe fails or times out

## Preconditions

A database probe that can succeed, reject, or hang.

## Steps

1. Run the readiness probe with a succeeding probe.
2. Run it with a rejecting probe, then with a probe that never resolves.
3. Request `GET /api/health/ready`, and `GET /api/health/live`.

## Expected Result

Success reports ready; a rejection or a timeout reports not ready, with no driver message leaked and no timer left pending; the route answers 503 when not ready. Liveness stays independent of the database, and `render.yaml` `healthCheckPath` stays `/api` so a database blip is not a restart loop. Residual: per-worker `lastTickAt` is not reported (ITEM-0242).
