# QA-SETTINGS-019 — A NOT_DELIVERED row names its provider and reason, and Created keeps its time

## Preconditions

A tenant whose default email provider is CONSOLE or DEV, with a delivery
history containing at least one `SENT` row (from an SMTP-backed send in an
earlier fixture or an isolated tenant) and one `NOT_DELIVERED` row. An
administrator with `notification.logs.read`.

## Steps

1. Trigger any notification email in the sink tenant (e.g. a test send from
   the Email Templates screen with `dryRun: false`).
2. Open `/settings/notifications/logs` (the delivery log list) and find the
   row just created.
3. Open the row's record.
4. Compare the `Created` value shown in the list against the value shown on
   the record.
5. Compare the `Status` value shown in the list against the value shown on
   the record.

## Expected Result

Step 1-3: the row's status is `NOT_DELIVERED`, its `Reason` field is
non-empty and names the provider type (e.g. "Accepted by a CONSOLE
provider..."), and the list shows a `Provider Type` column with the same
value. Step 4: the list and the record show the identical `Created`
timestamp, both including the time, in the tenant's timezone — not a
date-only value on the list. Step 5: both surfaces show the same
human-readable label (e.g. "Not delivered"), never the raw enum member
`NOT_DELIVERED`. No `Edit` or `Delete` control appears on the record.
