# QA-RUNTIME-035 — State drawn as a colour, and six links with one name

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-336 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

The dot is not `aria-hidden`, carries `role="img"` and a name derived from the severity, and `SEVERITY_LABELS` is declared exactly once and read by both renderings. Every member of the union has an entry. A metric card's link takes its accessible name from the card's own title, at **every** call site, and the visible text is unchanged.

## Expected Result

The behaviour holds as REG-336 describes it. The automated guard is `apps/web/app/components/dashboard/dashboard-widget-accessibility.spec.ts`; a run of that suite is sufficient evidence for this scenario.

## Why This Is Reusable

`dashboard-widget-renderer.tsx` held two renderings of one idea. `SeverityDot` was `aria-hidden` with a background colour class as its entire output, so a widget's state reached sighted users as hue and everyone else not at all — while `SeverityPill`, in the same file, already rendered the same `DashboardSeverity` union as text
