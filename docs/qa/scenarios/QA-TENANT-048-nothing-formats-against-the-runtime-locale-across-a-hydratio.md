# QA-TENANT-048 — Nothing formats against the runtime locale across a hydration boundary

## Preconditions

- Platform Admin, signed in, with the browser console open.

## Steps

1. Run `npm --workspace admin run test -- dashboard-hydration`.
2. Load the Control Hub and read the console.
3. Compare a money figure on the dashboard with the same figure on another
   admin screen.
4. Read the "Refreshed" chip and check it against your own clock.
5. On the public signup wizard, reach the verification step and press
   **Change email address**.

## Expected Result

- The suite passes.
- No React error #418, and no hydration warning.
- Money reads identically on both screens.
- The refresh time is the viewer's local time, not the server's.
- Step 5 returns to the wizard with every field still populated.

## Notes

Steps 3 and 4 are checking opposite decisions and both are deliberate. An amount
is the same number everywhere, so it is formatted deterministically. A "refreshed
at" stamp is only useful in the viewer's own time, so that difference is declared
with `suppressHydrationWarning` rather than removed — making it deterministic
would have cleaned the console by showing everyone the server's clock.

If #418 persists, the remaining mismatch is something else: these two were
certainly mismatches, but whether they were the only ones cannot be established
without a browser, and this scenario is where that gets settled.

Step 5's invalidation half is worth confirming rather than assuming — the old
code should stop working once a new one is sent, which the API does by
overwriting the hash.
