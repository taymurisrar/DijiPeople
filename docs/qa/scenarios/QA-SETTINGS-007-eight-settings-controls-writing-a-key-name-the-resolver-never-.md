# QA-SETTINGS-007 — Eight settings controls writing a key name the resolver never read

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-326 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

The same guard as REG-325 covers this class by construction: each of the eight dead names was a catalog key with an editable control and no reader, so all eight appear in the "every declared key is either read or declared inert" assertion. Seven were deleted from the catalog and their controls repointed at the live key; the eighth, `organization.weekStartDay`, was deleted with its control.

The behaviour holds as REG-326 describes it. The automated guard is `services/api/src/modules/tenant-settings/tenant-settings-reader-coverage.spec.ts`; a run of that suite is sufficient evidence for this scenario.
