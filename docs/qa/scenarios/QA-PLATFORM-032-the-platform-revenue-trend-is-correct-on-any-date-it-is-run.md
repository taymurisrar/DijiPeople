# QA-PLATFORM-032 — The platform revenue trend is correct on any date it is run

## Preconditions

None. `buildMonthlyTrend` is a pure function and the spec supplies its own rows;
nothing here needs a database or a tenant.

## Steps

1. Run `npm --workspace api run test -- dashboard-fx`.
2. Read the assertion in *converts each row by its own currency rather than one
   currency per query* and confirm it selects its bucket **by key**, not by
   position.
3. Re-run with the system clock set to a later month — or simply re-run in a
   later month, which is how this was found.
4. Confirm the test still fails for the reason it exists: mutate `sumConverted`
   in `super-admin.service.ts` to convert every row at `rows[0].currency`
   instead of `item.currency`, run again, then revert.

## Expected Result

1–3. The suite passes, and passes identically in any month. The fixture is
pinned to August 2026 (`Date.UTC(2026, 7, …)`), so the assertion must name
`'2026-08'`. `trend[trend.length - 1]` is **not** August outside August:
`monthlyBuckets` runs from `start` to today, so the last bucket is the current
month, and for a fixture month in the past it is empty and reads `0`.

4. The mutation fails with `Received: 45840` against `Expected: 8140` — 500 PKR
converted at QAR. If it passes, the date fix has made the test vacuous and the
real coverage is gone; that is the outcome this step exists to catch.

## Notes

Created 2026-09-09 at `bdbf9dc1`, from [[BUG-2839]].

**The point of this scenario is step 4, not step 1.** A date-dependent assertion
is easy to "fix" into something that never fails, and the failure mode is silent:
a green suite with no coverage reads exactly like a green suite with coverage.

The generalisation worth carrying to any similar test: **a fixture pinned to a
date needs an assertion pinned to the same date.** Any `[length - 1]`, `.at(-1)`
or `[0]` taken from a range that ends at `new Date()` is the same defect waiting
for a month boundary — and it will surface inside whatever unrelated change
happens to run first afterwards, where it reads as that change's fault.
