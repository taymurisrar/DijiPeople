# QA-PLATFORM-022 — The console hydrates cleanly when a browser extension writes into the head

## Preconditions

The admin console running in development — `npm --workspace admin run dev`, or
any port via `ADMIN_PORT` — and a browser that injects a content script into
`<head>`. Most ad blockers, password managers and grammar checkers do; the one
in the original report is `lgblnfidahcdcjddiepkckcfdhpknnjh`.

If no such extension is installed, the injection can be reproduced exactly,
because what an extension does here is one DOM insertion at `document_start`:

```js
await page.addInitScript(() => {
  const s = document.createElement("script");
  s.src = "chrome-extension://lgblnfidahcdcjddiepkckcfdhpknnjh/content/popups-script.js";
  document.head.insertBefore(s, document.head.firstChild);
});
```

## Steps

1. `npm --workspace admin run test -- console-theme-bootstrap`
2. With the extension present (or the snippet above installed), hard-reload any
   console page — `/login` will do — and read the browser console.
3. In the console, evaluate
   `document.getElementById("admin-theme-bootstrap").parentElement.tagName`.
4. Set the cookie `dp-admin-theme=dark`, hard-reload, and read
   `document.documentElement.dataset.adminScheme` and the computed
   `background-color` of `<body>`.
5. Watch the **first frame** of that reload — record it or throttle the
   connection if you cannot see it.

## Expected Result

Step 1: all cases pass, including the two that assert the script's placement.

Step 2: **no hydration message.** Specifically, no "A tree hydrated but some
attributes of the server rendered HTML didn't match the client properties"
naming `admin-theme-bootstrap`, and no `src="chrome-extension://…"` in the diff.

Step 3: `"BODY"`. The script is inside `<body>` and is its first element; the
layout renders no `<head>` element of its own.

Step 4: `"dark"`, and a dark computed background — `rgb(11, 18, 32)` at the time
of writing. Moving the script must not cost what BUG-0495 bought.

Step 5: no light frame. QA-PLATFORM-022 exists because of where the script runs;
QA-PLATFORM-015 exists because of when, and step 5 is the seam between them.

## Notes

An `info`-level advisory from Next — "Encountered a script tag while rendering
React component. Scripts inside React components are never executed when
rendering on the client" — is **expected** and is not a failure. It is correct:
the bootstrap executes during document parse, and client-side navigation is
`ConsolePreferencesApplier`'s job, not this script's. Do not report it as a
regression, and do not "fix" it by moving the script back into `<head>`.

Executed 2026-08-25 against `next dev --webpack` on port 3102 with the injection
above, on the layout before and after the fix on the same running server: the
`<head>` placement produced the hydration error, the `<body>` placement produced
none, and the dark cookie resolved to `rgb(11, 18, 32)` either way.

The unit half is a source scan — `apps/admin` jest has no jsdom — so it asserts
the mechanism rather than the rendered document. Steps 2–5 are what actually
observe the browser, and they are the reason this scenario is `PARTIAL` and not
`AUTOMATED`.
