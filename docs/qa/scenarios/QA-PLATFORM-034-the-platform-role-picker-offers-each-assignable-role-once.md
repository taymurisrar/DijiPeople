# QA-PLATFORM-034 — The platform role picker offers each assignable role once

## Preconditions

The platform-user create/edit screen in `apps/admin`; an existing platform
user assigned `MEMBER`.

## Steps

1. Open the role picker for a new platform user.
2. Read `SUPER_ADMIN`'s label.
3. Attempt `POST /platform-users` with role `PLATFORM_OWNER`, then `MEMBER`.
4. Attempt `PATCH /platform-users/:id` changing an existing user's role to
   `PLATFORM_OWNER`, then `MEMBER`.
5. Open the existing `MEMBER` user's own edit screen and save it unchanged.

## Expected Result

`SUPER_ADMIN` reads "Platform Super Admin", with no other role sharing its
label. The new-assignment picker offers 14 roles — neither `PLATFORM_OWNER`
nor `MEMBER` — defaulting to `READ_ONLY_AUDITOR`. Both create/patch attempts
in steps 3-4 return `400 PLATFORM_ROLE_NOT_ASSIGNABLE` naming the role to use
instead. The existing `MEMBER`'s edit screen still shows their current role
(labelled "Legacy Member (deprecated)") and saving it unchanged succeeds.
