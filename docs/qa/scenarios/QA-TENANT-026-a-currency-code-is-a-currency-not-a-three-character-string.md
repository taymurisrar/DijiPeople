# QA-TENANT-026 — A currency code is a currency, not a three-character string

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.

## Steps

1. Run `npm --workspace api run test -- partner-currency` and
   `npm run test:platform-currencies`.
2. Open **Partners → New**. Inspect the **Currency** control.
3. Fill the form and save with a currency selected.
4. `POST /api/partners` directly with `currencyCode: "5"`.

## Expected Result

- Both suites pass.
- Currency is a select listing supported currency codes — not
  `<input type="number">`, and not a free-text box.
- The partner saves carrying the selected code.
- The direct API call is rejected with
  `currencyCode must be a supported currency code.`

## Notes

The reason this is worth re-running in a browser rather than trusting the unit
tests: partners created before the fix still hold `currencyCode: "5"`. Editing
one now requires choosing a real currency before it will save. That is intended,
but it means an operator's first encounter with this fix may be an existing
record refusing to save until they answer a question nobody asked them before.

`"NOT_A_CURRENCY"` used to be rejected, which made the validation look like it
worked. It was rejected for being fourteen characters long.
