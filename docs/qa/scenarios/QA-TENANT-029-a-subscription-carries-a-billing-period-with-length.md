# QA-TENANT-029 — A subscription carries a billing period with length

## Preconditions

- A Stripe webhook endpoint, at whichever API version it is configured for.

## Steps

1. Run `npm --workspace api run test -- subscription-billing-period`.
2. Complete a paid signup.
3. Read the resulting `Subscription` row's `currentPeriodStart`,
   `currentPeriodEnd` and `renewalDate`.
4. Compare them against the Stripe subscription's own period.

## Expected Result

- The suite passes.
- `currentPeriodEnd` is one billing cycle after `currentPeriodStart` — a period
  with length, not two copies of the same instant.
- `renewalDate` is in the future for an active subscription.
- The Subscriptions list renders a real renewal date rather than an em dash.

## Notes

Check the webhook endpoint's API version before concluding anything from a
failure. `STRIPE_API_VERSION` pins outbound calls only; Stripe renders events at
the version configured on the endpoint, so this can change without a deploy. From
`2025-03-31.basil` the period lives on subscription *items*, not on the
subscription.

This is the second defect in this file from that one fact — BUG-1128 was the
first, on `invoice.parent`. A third is likely wherever a Stripe field is read at
one level only.

**Still open:** the two production rows written before the fix are still wrong.
They need a backfill from Stripe, which this scenario does not cover.
