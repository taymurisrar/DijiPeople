# QA-BILLING-021 — The public plans endpoint never publishes a price the visitor cannot buy

## Preconditions

A published, active plan holding **both** a `PER_SEAT` price (`SELF_SERVICE`)
and a `FLAT` price (`SALES_ASSISTED`) for the same currency and billing
interval. That combination is the whole scenario — a plan with only per-seat
prices passes whether or not the rule is applied, which is why this defect
survived as long as it did.

## Steps

1. `GET /api/public/plans` as an anonymous caller.
2. List the prices returned for that plan and currency.
3. `GET /api/public/commercial-config` for the same market.
4. Compare the two.
5. Repeat with the *plan's* `salesModel` set to `SALES_ASSISTED`, and again to
   `CUSTOM_ONLY`, leaving the price rows `SELF_SERVICE`.

## Expected Result

- **Step 2** — the `FLAT` / `SALES_ASSISTED` price is **absent**. Not present
  with `checkoutReady: false`; absent. It is internal pricing, and a visitor
  should not be able to read it at all.
- **Step 4** — the two endpoints agree on which prices exist for this visitor.
  They are two readers of one rule and must not diverge.
- **Step 5** — a `SALES_ASSISTED` or `CUSTOM_ONLY` plan publishes **no** prices,
  even though every price row says `SELF_SERVICE`. The plan's model narrows the
  price's and never widens it.

The rule is `narrowestSalesModel(plan.salesModel, price.salesModel) ===
SELF_SERVICE` — the same predicate `resolveCommercialOffer` uses. Asserting a
`billingModel !== 'FLAT'` check instead would pass today and be a second rule
for one decision, which is the defect rather than the fix.

Automated in `services/api/src/modules/billing/flat-pricing-is-internal.spec.ts`
— deliberately the same file that already guards the resolver, so both readers

The production evidence this was written from: `/public/plans` returned four
active QAR prices for Starter (`MONTHLY FLAT 249`, `MONTHLY PER_SEAT 8`,
`ANNUAL FLAT 2490`, `ANNUAL PER_SEAT 80`) while `/public/commercial-config`,
over the same rows, returned only the two per-seat offers.

The owner's rule this enforces is recorded in that spec's header: the website,
the plans page and self-service checkout show per-seat prices only; flat pricing
exists for customers onboarded by hand and must never be quoted to a visitor.
