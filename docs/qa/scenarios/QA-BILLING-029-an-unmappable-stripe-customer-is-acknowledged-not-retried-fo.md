# QA-BILLING-029 — An unmappable Stripe customer is acknowledged, not retried for ever

## Preconditions

A Stripe subscription webhook event whose customer cannot be resolved to exactly
one tenant, a second that resolves ambiguously to more than one, and a third that
fails for an unrelated reason.

## Steps

1. Deliver the unresolvable-customer event.
2. Deliver the ambiguous-mapping event.
3. Deliver an event that fails for a reason outside the unmapped-tenant class.
4. Deliver one that fails generic validation without being tagged as unmapped.
5. Deliver an event that processes successfully.

## Expected Result

- Both the unresolvable and the ambiguous cases are acknowledged with a 2xx and
  recorded. Stripe retries a non-2xx, and no retry can fix an unmappable
  customer, so rejecting it converts one failure into an indefinite series on
  Stripe's full backoff schedule.
- The two unrelated failures are still **rejected**. These are the assertions
  that stop the fix widening into "acknowledge everything", which would silently
  swallow real processing failures.
- The successful event's response shape is unchanged.
