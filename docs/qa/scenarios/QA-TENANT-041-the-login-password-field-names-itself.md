# QA-TENANT-041 — The login password field names itself

## Preconditions

- The tenant login screen, and a browser with a password manager.

## Steps

1. Run `npm --workspace web run test -- login-field-accessibility`.
2. Open the tenant login and inspect the password input.
3. Save a credential, sign out, and return.
4. Repeat on the admin login.

## Expected Result

- The suite passes.
- The password input has an accessible name of "Password" and
  `autocomplete="current-password"`.
- The email input carries `autocomplete="username"`.
- The password manager offers to fill **both** fields together.
- The visible "Password" text still appears once, in the heading row beside
  "Forgot password?".

## Notes

Step 3 is the real test. The two fields are only fillable as a pair when they are
identifiable as a credential set, which `username` + `current-password` is what
declares — this is why the email token changed even though `email` was also
valid.

The admin login was already correct and is included as a comparison rather than
as a target.

Watch that the label does not become visible twice. The hiding exists so the
heading row can hold the "Forgot password?" link, and showing it again would undo
the layout rather than fix the accessibility.
