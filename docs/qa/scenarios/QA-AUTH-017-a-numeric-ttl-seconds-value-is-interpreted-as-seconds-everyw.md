# QA-AUTH-017 — A numeric TTL_SECONDS value is interpreted as seconds everywhere it is consumed

## Preconditions

`AUTH_ADMIN_ACCESS_TOKEN_TTL_SECONDS=1800` (a bare digit string, no unit
suffix) set in the API's environment; the equivalent web/agent/refresh-token
variables set the same way.

## Steps

1. Sign in to `apps/admin` with the bare-digit TTL configured.
2. Decode the returned access token's `exp`/`iat` claims.
3. Repeat for a web access token, a refresh token, and an agent token, each
   configured with a bare-digit `*_TTL_SECONDS` value.
4. Repeat with an already-suffixed value (`15m`, `7d`).
5. Set the variable to a blank value.
6. Check the cookie `maxAge` the frontend sizes from `accessTokenExpiresIn`.

## Expected Result

Every bare-digit case in steps 1-3 decodes to `exp - iat` equal to the
configured number of seconds (1800), not ~1 second. Step 4's suffixed values
keep their stated meaning unchanged. Step 5 falls back to the documented
default rather than a zero lifetime. Step 6's cookie lifetime matches the
signed token's real lifetime.
