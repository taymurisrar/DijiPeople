# QA-TENANT-035 — An empty list says which kind of empty it is

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.
- At least one module with no records and no filters applied.

## Steps

1. Run `npm run test:empty-list-message`.
2. Open a module with no records and no filters. Read the empty state.
3. Apply a filter that matches nothing. Read it again.
4. Open **Invoices**, **Payments** and **Commissions** with no records.
5. Find a list holding exactly one record and read its count.

## Expected Result

- The suite passes.
- Step 2 mentions neither filters nor search.
- Step 3 says the filters are why, and offers to clear them.
- Step 4 says where those records come from, and never says "create".
- Step 5 reads "1 record", not "1 records".

## Notes

Step 2 is the one that was wrong for everybody: a brand-new workspace told its
first operator that a search they had never run was hiding data that did not
exist.

A view is not a filter. "Resolved" being empty is good news, and telling the
operator to clear something would be wrong — so switching views should not change
the wording, only searching and filtering should.

This was fixed once already, in `apps/web` (BUG-1654), and `apps/admin` kept the
defect. The implementation now lives in `packages/config` for that reason; if a
third app grows a copy, that is the regression.
