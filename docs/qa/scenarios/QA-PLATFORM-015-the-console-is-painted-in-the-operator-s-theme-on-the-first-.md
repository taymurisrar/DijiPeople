# QA-PLATFORM-015 — The console is painted in the operator's theme on the first frame

## Preconditions

A console account with the theme preference set to Dark, and a machine whose
system theme can be changed without closing the browser.

## Steps

1. `npm --workspace admin run test -- console-theme-bootstrap`
2. Set the theme to **Dark**. Hard-reload any console page and watch the **first
   frame** — record a video or use a throttled connection if you cannot see it.
3. Navigate between pages.
4. Set the theme to **System** and hard-reload.
5. Change the machine's theme with the console open.
6. Clear cookies for the site and reload.

## Expected Result

Step 2: no light frame. The page is dark from the first paint.

Step 3: no flash on navigation either.

Step 4: the resolved scheme matches the machine, decided before paint — and
`data-admin-theme` is **absent**, not left saying "dark".

Step 5: the console repaints without a reload.

Step 6: the console renders — light, which is the same outcome as before this
existed. A console that renders nothing would not be.

## Notes

The first frame is exactly what no test here can see, which is why steps 2–6 are
manual and the automated half asserts the mechanism instead: a cookie the root
layout can read, a blocking script in `<head>` that resolves SYSTEM, and a body
painted from tokens.

Consideration: step 4's absent attribute is easy to miss and is the difference
between "follow the system" and "pinned to whatever you last chose". Inspect
`<html>` rather than trusting the colour — on a dark machine both look the same.
