# QA-FRAMEWORK-001 — The id allocator never returns a PLAN number an ExecPlan already holds

## Preconditions

A checkout containing both plan families:

- `docs/qa/test-plans/` — QA test plans, numbered in the filename
  (`PLAN-019-platform-admin.md`).
- `docs/plans/` — ExecPlans, filed as `EXECPLAN-00nn-*.md` and declaring
  `ID: PLAN-nnn` in frontmatter.

No database, no server, no credentials.

## Steps

1. `node --test scripts/id-allocator.test.mjs`
2. Independently, check the ceiling against the live records — list every
   `ID: PLAN-` line in `docs/plans`, list the `PLAN-` filenames in
   `docs/qa/test-plans`, then call `highestAllocated(root, 'plan')` from
   `scripts/lib/id-allocator.mjs`.
3. Compare the ceiling with the highest number appearing in either listing.

## Expected Result

All four cases pass. The reported ceiling is greater than or equal to the highest
`PLAN-nnn` in `docs/plans` frontmatter **and** the highest `PLAN-nnn` filename in
`docs/qa/test-plans`.

Specifically: an ExecPlan whose filename says `EXECPLAN-0027` while its
frontmatter says `ID: PLAN-027` must raise the ceiling to 27. Reading filenames
alone finds 0027 and misses the number that actually matters.

A kind with a single string `dir` — `bug` — must be unaffected.

## Notes

Created 2026-08-30 at `39d8ddc4` for [[BUG-2413]] / REG-365.

while `EXECPLAN-0027-attendance-single-source-of-truth.md` already held it, and
`EXECPLAN-0028` exists twice because the filename half of the name had no
allocation path at all.

Mutation-tested — reverting `dir` to a single directory fails two of the four
cases.
