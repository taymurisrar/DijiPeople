# QA-AUTHZ-017 — Every platform role that holds tenants.update can save a tenant profile

## Preconditions

A platform user session for each of SUPER_ADMIN, PLATFORM_OWNER,
PLATFORM_ADMIN, PLATFORM_OPERATIONS and MEMBER; a tenant record to edit; a
tenant user carrying the `system-admin` role key and `tenants.update`.

## Steps

1. As each of SUPER_ADMIN, PLATFORM_OWNER, PLATFORM_ADMIN, PLATFORM_OPERATIONS
   and MEMBER, call `PATCH /api/platform-runtime/tenants/:id` with
   `{ values: { displayName: "<new name>" } }`.
2. As the same roles, submit a `status`/`subStatus` change through the same
   route.
3. Submit a blank `name`.
4. As the tenant user carrying `system-admin` and `tenants.update`, call the
   same route.
5. Inspect the resulting `PlatformAuditLog` row for the successful edit.
6. In `apps/admin`, edit and save a tenant as PLATFORM_ADMIN and
   PLATFORM_OPERATIONS.

## Expected Result

All five platform roles in step 1 get `200` and the field is saved. A
`status`/`subStatus` change gets `400 TENANT_STATUS_REQUIRES_LIFECYCLE_ACTION`
naming the Actions-menu lifecycle action instead. A blank `name` gets `400`.
The tenant user in step 4 gets `403` — a `system-admin` role key never
substitutes for a platform permission. One `TENANT_PROFILE_UPDATED` audit row
carries `name`/`displayName`/`legalName` before and after. The admin UI shows
"Tenant saved." with no permission dialog and no failed network calls.
