# QA-DEPLOY-019 — The API names pending migrations at startup instead of failing a screen later

## Preconditions

A checkout of the repository. The unit scenario needs nothing; the
integration form needs a local Postgres whose `_prisma_migrations` table is
behind `services/api/prisma/migrations`.

## Steps

1. `npx jest src/common/prisma/migration-drift.spec.ts` from `services/api`.
2. Integration form: point `DATABASE_URL` at a database missing at least one
   committed migration and start the API.

## Expected Result

Step 1 passes. In step 2 the API logs a warning that **names each pending
migration by directory name**, states that queries touching their columns will
fail with `P2022`, and continues to start.

It must not refuse to boot: a developer deliberately on an older database
should not be locked out, and a refusal over a common, often-intentional state
is how a warning gets ignored.
