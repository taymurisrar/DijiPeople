# QA-PLATFORM-044 — A stale admin record edit is refused instead of overwriting another operator's change

## Preconditions

Two platform users with write access to the same runtime module (leads, partners, customers, customer onboarding, tenants, contracts, support cases or plans), and one existing record.

## Steps

1. Both users open the record and click Edit.
2. User A changes a field and saves.
3. User B changes a different field and saves.
4. User B reloads the record and saves again.

## Expected Result

Step 2 saves. Step 3 is refused with 409 RECORD_CHANGED_SINCE_OPENED and the message telling B to reload; A's change is intact. Step 4 saves. Saving twice in a row from one page, or after a status change on the same page, is never refused.
