# QA-RUNTIME-026 — A child record pre-filled with its parent's values

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-316 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

The four confirmed collisions encoded as data, each asserting the posted body contains **only** the parent foreign key. A declared inheritance is carried through and nothing else travels with it. A draft value cannot overwrite the parent foreign key. A user's own edit beats an inherited value. Null and empty parent values are skipped rather than seeding a blank.

## Expected Result

The behaviour holds as REG-316 describes it. The automated guard is `apps/web/lib/runtime/related-record-create-values.spec.ts`; a run of that suite is sufficient evidence for this scenario.

## Why This Is Reusable

`module-related-subgrid.tsx` handed the quick-create dialog the parent record **whole** as `contextValues`, and `module-quick-create-panel.tsx` spread it into the child form's initial value map. Any field name shared between parent and child therefore opened pre-filled with the parent's value and was posted with it unless the user noticed and overwrote it
