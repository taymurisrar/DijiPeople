# QA-TENANT-053 — The tenant product opens, module by module, for the plan a tenant is on

## Preconditions

- API and `apps/web` running; a migrated, seeded, disposable database.
- `E2E_TENANT_USER_EMAIL` / `E2E_TENANT_USER_PASSWORD` for an **ordinary** tenant
  user — deliberately not a platform admin and not a tenant owner if avoidable.
- `E2E_TENANT_SLUG`, or an ACTIVE tenant with a slug for the fixture to find.
- **Fewer than four full runs in the last ten minutes.** `PublicRateLimitGuard`
  allows 20 POSTs per 10-minute window per IP and path; a run spends five on
  `/api/auth/login`.

## Steps

1. `npx playwright test --config e2e/playwright.config.ts flow-h flow-i flow-j`
2. Flow H: sign in, and observe where it lands.
3. Flow I: each Growth-entitled module — employees, leaves, attendance,
   timesheets, projects, recruitment, onboarding.
4. Flow J: settings index, organization, branding, notifications.
5. Check the API log for `429 RATE_LIMIT_EXCEEDED` before believing any
   sign-in failure.

## Expected Result

- **17 passing, 5 skipped, 0 failing**, every skip carrying a named reason.
- Sign-in leaves `/login`; a workspace picker is a pass, not a failure — one
  `Identity` may reach several tenants since TASK-0009's contract phase.
- Every module reaches an **intentional state**: its own content, or a refusal
  that explains itself and carries an error reference. Never a blank page, never
  an unhandled client exception.
- Three of seven refuse for a least-privileged user, and that is correct —
  projects and onboarding with "Access denied", timesheets with "not linked to
  an employee profile". A user who could open all seven would hide exactly the
  authorization defects this scenario exists to notice.
- A list screen shows only the signed-in tenant's records.
- Against an unseeded environment, every test **skips with a message** naming
  what was missing rather than failing.

## Notes

The slice is the Growth plan's entitlement, from `plans.catalog.ts` — a
checkable boundary rather than a judgement about importance. **Payroll is not in
it**, which is why no payslip journey appears here: it is Enterprise-only, and
asserting it would test a 403 and report it as coverage.

Three assertions are `test.fixme` against BUG-1951, BUG-1986 and BUG-1668. They
describe required behaviour and are expected to fail until those are fixed;
they will start passing on their own rather than needing somebody to remember.
