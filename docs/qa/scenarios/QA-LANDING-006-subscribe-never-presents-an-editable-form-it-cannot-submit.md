# QA-LANDING-006 — Subscribe never presents an editable form it cannot submit

## Preconditions

The landing app and API are running. Exercised in whichever checkout state the environment is in; the scenario branches rather than assuming one.

## Steps

1. Open `/subscribe`.
2. Determine whether a submit control exists inside the form.
3. If it does not, inspect the company-details fieldset and the stated reason.
4. If it does, confirm it is enabled and the fields are interactive.

## Expected Result

With checkout unavailable: the company-details fieldset is disabled, no control inside it matches `:enabled`, and the reason is stated **beside the fields** rather than only on the neighbouring plan card. With checkout available: a submit control is present and enabled.

Guards BUG-0066, where six enabled fields sat under a heading promising
"continue to secure checkout" with no way to submit, and following the fallback
link silently discarded whatever had been typed.
