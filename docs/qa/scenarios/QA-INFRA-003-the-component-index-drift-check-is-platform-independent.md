# QA-INFRA-003 — the component index drift check is platform-independent

## Preconditions

- A checkout where Git normalises line endings — any Windows worktree with the
  default configuration. `git add` printing "LF will be replaced by CRLF" for
  these files confirms it.
- `.agent/context/component-index.md` current for that commit.

## Steps

Automated coverage — `node --test scripts/index-drift.test.mjs` — pins the
comparison itself. The manual pass is what proves it on the platform that
exposed the bug, and is worth re-running on any change to the generator:

1. In a **fresh** worktree on Windows, run
   `node scripts/generate-component-index.mjs --check` without regenerating
   anything first.
2. Change a doc-comment above an exported component — for example the summary
   line on `ModuleActionBar` — and run `--check` again.
3. Restore the comment and run `--check` once more.

## Expected Result

1. **Up to date, exit 0.** This is the whole scenario: before the fix it
   reported drift here, on a file nobody had touched.
2. **Out of date, exit 1.** Normalisation must not have become a way for real
   drift to pass.
3. Up to date, exit 0.

## Notes

Created 2026-08-25 at `ddb457ff`.

**CI cannot run this scenario meaningfully.** The failure requires a CRLF
checkout, and the runner is `ubuntu-latest`, which produces `\n` — which is
exactly why the defect shipped green. The automated test compensates by
constructing both line endings in memory rather than relying on the checkout,
so the case is covered on every platform; step 1 above remains the honest
end-to-end confirmation and needs a human on Windows.

That asymmetry is the lesson worth keeping: a check whose result depends on the
platform is not one check but two, and only one of them was ever being run.
