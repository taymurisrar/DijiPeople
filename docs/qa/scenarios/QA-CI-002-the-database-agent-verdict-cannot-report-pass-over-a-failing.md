# QA-CI-002 — The Database Agent verdict cannot report PASS over a failing field

## Preconditions

A checkout with `node_modules` installed. No database is required for the
automated part: `classifyVerdict()` is exported from `scripts/db-preflight.mjs`
and is pure, precisely so this scenario can run anywhere.

The end-to-end part needs a reachable local PostgreSQL and a **throwaway**
database. Never run it against the populated `dijipeople` development database.

## Steps

Automated — `npm run test:db-preflight`:

1. Classify four agreeing links (`CURRENT` × 4).
2. Classify `MIGRATION_STATUS = PENDING_MIGRATIONS` with
   `LOCAL_DATABASE_STATUS = DATABASE_MISMATCH` — the state the user's machine
   was in when BUG-0083 was reported.
3. Classify each of `UNREACHABLE`, `MIGRATION_DRIFT`, `CLIENT_MISMATCH`, `STALE`.
4. Classify each of the four fields set to `UNKNOWN`, one at a time.
5. Classify a state carrying both an `UNKNOWN` field and a known failure.

End-to-end, when a throwaway database is available:

6. Create an empty database; point `DATABASE_URL` at it.
7. `node scripts/db-preflight.mjs --postflight`; record the verdict and the
   exit code.
8. Drop the database.

## Expected Result

1. `PASS`. Four inspected, agreeing links are the **only** route to it.
2. `BLOCKED`, with `MIGRATION_STATUS=PENDING_MIGRATIONS` named in the blocking
   list. This is the case that regressed: the verdict was `PASS`.
3. `BLOCKED` for each.
4. `INCOMPLETE` for each — never `PASS`. A link nobody could inspect is not a
   link known to hold.
5. `BLOCKED`. A known failure outranks an unresolved one, and the unresolved
   fields are still reported rather than discarded.
6–8. `DATABASE_COHERENCE_STATUS = BLOCKED` and exit code `1`. Measured against
the pre-fix script the same input gives `PASS` and exit `0`.

The distinction between `BLOCKED` and `INCOMPLETE` must survive: they call for
different next actions — repair or diagnose, versus re-run the check somewhere
it can see — and collapsing them loses that.

## Notes

Created 2026-08-20 at `844b6d3`.

This scenario exists because the textual checks around it could not see the
defect. `validate-framework.mjs` asserted that `database.md` *says* "UNKNOWN is
not an acceptable resting state", and that sentence was present and true for the
entire period the script was reporting `PASS` over two `UNKNOWN` fields. Prose
about behaviour is not a check on behaviour — hence simulations 32e–32g, which
call the function rather than reading about it.
