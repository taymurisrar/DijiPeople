# QA-SETTINGS-034 — A custom field on any customizable system module stores, shows and saves its value

## Preconditions

A tenant admin, and a second tenant for the isolation check. Custom fields are added in Settings → Customization, then published.

## Steps

1. Add a Choice field to Departments. Create a department with a value, over HTTP through the full app. The `ValidationPipe` is configured as in `main.ts`.
2. Save the same department with a value that is not one of the choices.
3. Update the department: once with a new value, once with an unrelated field only.
4. List departments.
5. Add a text field to Holidays. Create a holiday under its calendar, with a value.
6. From the second tenant, read the definitions and the first tenant's department.
7. Try to add a custom field to Payslips.
8. In a browser, edit one record on each kind of page and save a value:
   - a settings page (Work Calendars);
   - a standard page (project edit);
   - a bespoke form (the holiday manager);
   - the employee form.

## Expected Result

- Step 1: 201, and the answer carries `customFields` with the value. The module's strict DTO does not refuse the key.
- Step 2: 400 with `customFields.<key>`. No department is written.
- Step 3: the value changes. The unrelated update keeps it. An audit row `CUSTOM_FIELD_VALUES_UPDATED` records before and after.
- Step 4: the department's row carries the value.
- Step 5: the holiday answers with the value, and it is stored against the holiday.
- Step 6: no definitions for the other tenant, and 404 on the department.
- Step 7: refused with `CUSTOMIZATION_TABLE_NOT_CUSTOMIZABLE`.
- Step 8: each form shows "Additional information" with the stored value, and a saved change reads back through the API.
