# QA-TENANT-049 — The signup wizard advertises the address the tenant will get

## Preconditions

- The public signup wizard, reachable at `/subscribe`.

## Steps

1. Run `npm --workspace landing run test -- workspace-address`.
2. `curl -s https://www.dijipeople.com/subscribe | grep -o 'tenantBaseDomain[^}]*'`
3. Enter a slug in step 2 and read the availability sentence.
4. Complete a signup and compare the address on the success page, and the
   provisioned tenant's actual hostname, with what step 2 said.

## Expected Result

- The suite passes.
- Step 2 of the curl reports `ws.dijipeople.com`.
- The wizard, the success page and the tenant all name the same address.
- That address resolves.

## Notes

Step 2 is the real check and step 1 cannot replace it. The value is inlined into
the bundle at build time, so a corrected variable and a stale bundle look
identical from a browser — what matters is the *served* value, because that is
what a customer sees.

The availability check sends only the slug; the API composes the hostname. So a
wrong domain here is always a display defect and never a wrong answer about
availability — worth knowing, because the opposite would be far more serious and
is the first thing BUG-1544 asks to rule out.

Same root cause family as REG-271 in `apps/web`. If one of these regresses, check
the other: they read the same resolver and are configured per deployment.
