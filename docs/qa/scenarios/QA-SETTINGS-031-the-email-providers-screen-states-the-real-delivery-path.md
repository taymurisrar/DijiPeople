# QA-SETTINGS-031 — The Email Providers screen states the real delivery path

## Preconditions

- A local stack on a throwaway database, API started with `APP_ENV=production`.
- A tenant holding only an enabled default Console provider.
- The platform relay can be switched between enabled SMTP and disabled.

## Steps

1. Open Settings → Notifications → Email Providers with the relay enabled as SMTP.
2. Disable the relay and reload.
3. Read the Console row.
4. Choose Add provider; open Provider type; press Escape.
5. Edit the Console row; Save with Enabled ticked; untick Enabled and Save.
6. Restart without production settings; open Add provider; set a Console
   provider as default and read the banner.
7. View the page at 1440px and 400px.

## Expected Result

- Step 1: "Email is delivered by the DijiPeople platform relay", with a "Sent
  as …" line.
- Step 2: "Email is not delivered", with "No email provider is available."
- Step 3: state "Not used"; no Set Default.
- Step 4: a dialog opens; Provider type offers only SMTP; Escape closes it.
- Step 5: the type reads "Console (not available)"; saving enabled shows the
  refusal; saving disabled succeeds.
- Step 6: Console and Dev are offered; the banner reads "Email is not
  delivered" with "The Console provider does not send email."
- Step 7: no horizontal page scroll; no JSON note, field help text or page
  description.
