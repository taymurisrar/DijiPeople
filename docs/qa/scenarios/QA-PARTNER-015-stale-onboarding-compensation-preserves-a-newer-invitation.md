# QA-PARTNER-015 — Stale onboarding compensation preserves a newer invitation

## Preconditions

An onboarding application with an invitation, two overlapping resend
attempts, and a delayed failure result from the older attempt.

## Steps

1. Issue resend A and delay its provider result.
2. Issue and deliver resend B.
3. Return failure for resend A and run its compensation.
4. Inspect the persisted invitation hash.

## Expected Result

Resend A's compensation does not update or delete the row because its issued
token hash no longer matches. Resend B's delivered invitation remains valid.
