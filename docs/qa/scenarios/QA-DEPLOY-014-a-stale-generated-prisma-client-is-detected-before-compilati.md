# QA-DEPLOY-014 — A stale generated Prisma client is detected before compilation

## Preconditions

A generated Prisma client exists. No database connection is required — the
check reads generated data, never a datasource, which is the point: it has to
work on a dev boot where `DATABASE_URL` is often absent.

## Steps

1. Add a scalar field to any existing model in `services/api/prisma/schema.prisma`.
2. Do **not** run `npm run prisma:generate`.
3. Run `node scripts/check-prisma-client-fresh.mjs`.
4. Remove the field and run the check again.
5. Repeat step 3 with `DATABASE_URL` unset.

## Expected Result

Step 3 exits **1**, names the missing field as `Model.field`, and offers
`npm run prisma:generate`. Step 4 exits **0** and reports the counts it
compared — enums, models and fields — so the scope is visible rather than
assumed. Step 5 behaves identically to step 3: an absent datasource must not
silently reduce what is checked.

Guards BUG-0068. The predecessor guard reported
`OK — 267 enums reachable` against a client missing
`ApplicationRelease.checksumSha512`, while `tsc` reported 8 errors on that
exact property — healthy output at the moment of the failure it existed to
prevent.
