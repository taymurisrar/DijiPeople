# QA-BILLING-030 — A per-seat price states its unit and totals the seats entered

## Preconditions

A tenant workspace signed in as a user who can read billing. At least one
plan carries a `PER_SEAT` price with a non-zero `minimumSeats` and a
`maximumSeats` bound. Only self-service prices reach this screen, and those are
per-seat by construction, so this is the ordinary case rather than an edge one.

## Steps

1. Open `/settings/subscription/plans`.
2. Read the price on any plan card, and the interval suffix beside it.
3. Enter a seat count inside the price's bounds in **Seats to purchase**.
4. Read the order summary beside the seat field.
5. Enter a seat count below `minimumSeats`, then one above `maximumSeats`.

## Expected Result

The price never renders without the word "seat" when the billing model is
`PER_SEAT`. Changing the seat count changes a visible total on the same screen,
and that total equals the unit amount multiplied by the billable seats the
server's own rule resolves — not the raw seat count, which differs whenever a
price carries included seats.

An out-of-bounds seat count is refused in the field with the bound stated. It is
never silently clamped and submitted, which is what made the original defect
invisible: the buyer saw one number and was charged against another.

## Notes

The rule is mirrored in the browser rather than fetched, because no seat-quote
endpoint is exposed over HTTP yet. That mirroring is the risk this scenario
exists to contain — the same arithmetic already had to be de-duplicated once on
the server after two copies disagreed. The spec asserts against the same fixture
values as the server's own seat-pricing suite, so a divergence fails on one side
or the other rather than reaching a card.
