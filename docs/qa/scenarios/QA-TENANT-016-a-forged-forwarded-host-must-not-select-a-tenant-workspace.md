# QA-TENANT-016 — A forged forwarded host must not select a tenant workspace

## Preconditions

No running system, no database, no tenant data. This is a pure-logic scenario
and that is deliberate: the decision under test happens in Next.js middleware
*before* any query, so reproducing it against a live stack would test the
database's answer rather than the routing rule's.

Environment for the run:

- `PLATFORM_ENVIRONMENT=production`, `TENANT_BASE_DOMAIN=dijipeople.com`,
  `PUBLIC_BASE_DOMAIN=dijipeople.com`
- `TRUST_PROXY_HEADERS`, `RENDER` and `VERCEL` all unset for the untrusted
  cases; set per case for the trusted ones.

## Steps

1. Resolve a request carrying `Host: app.internal` and
   `X-Forwarded-Host: maseer.dijipeople.com` with no proxy declared, and
   classify the result.
2. Repeat with `Forwarded: host=maseer.dijipeople.com;proto=https` instead.
3. Resolve a request carrying only `X-Forwarded-Host` and no `Host`.
4. Resolve a request carrying `Host: maseer.dijipeople.com` and no forwarded
   header, to confirm the genuine path still works.
5. Repeat step 1 with `VERCEL=1`, then with `TRUST_PROXY_HEADERS=true`, then
   with `VERCEL=1` **and** `TRUST_PROXY_HEADERS=false`.
6. With `VERCEL=1`, resolve a forwarded host of
   `maseer.dijipeople.com.attacker.com`.
7. Read `apps/web/proxy.ts` and confirm it resolves the hostname through the
   shared rule and reads no forwarded header directly.

## Expected Result

1. `CANDIDATE`, with **no** `slug` — the forged header selects no workspace,
   even though `maseer.dijipeople.com` is a real one. This is the scenario's
   whole point: an attacker names a real tenant, not a nonsense host.
2. `CANDIDATE`. The RFC 7239 form is not a way around the rule.
3. `INVALID`. Failure is closed, and nothing enumerates which tenants exist.
4. `WORKSPACE_HOST` with `slug: maseer`.
5. `WORKSPACE_HOST` for the two trusted cases — the deployed Vercel topology
   must keep working — and `app.internal` for the third, because an explicit
   `false` overrides platform inference.
6. `CANDIDATE`, with no `slug`. A trusted proxy is not a licence to skip exact
   suffix matching.
7. Both assertions hold.

## Notes

Created 2026-08-24 at `004ee666`, alongside REG-243 and the closure of
ITEM-0044.

Step 7 exists because steps 1–6 would all pass with the middleware still reading
`x-forwarded-host` directly: `proxy.ts` cannot be imported under this app's jest
config without the Next runtime, so the call site has to be asserted from
source. Reverting the call site fails exactly those two assertions and leaves
the other nine green — verified by mutation rather than assumed.

The API's half of the same rule is covered by
`services/api/src/modules/tenant-domains/request-hostname.spec.ts`, and the rule
itself by `packages/config/forwarded-host.test.js`.
