# QA-DEPLOY-015 — Repository health reports the primary worktree and blocks on unexplained dirty files

## Preconditions

A throwaway Git repository with three worktrees attached — a primary checkout on
`develop`, a task worktree on `agent/task`, and a sibling worktree on
`agent/other` — plus `docs/sessions/` present. No remote, no database, no
external service. The simulations build this themselves; nothing needs seeding.

`repo-health.mjs` and `session.mjs` both accept `--root <path>` so they can be
driven against the sandbox rather than the real repository.

## Steps

1. Dirty one tracked file in the **primary** checkout and leave both other
   worktrees clean. Run `repo-health.mjs --json --root <sandbox>
   --task-branch agent/task`.
2. Re-run it with `--primary-baseline <that path>`.
3. Restore the file. Write a tracked path a framework generator owns
   (`docs/backlog/index.md`) and re-run.
4. Remove it. Write `docs/sessions/SESSION-9001-*.md` with `STATUS: COMPLETE`
   and re-run; then rewrite the same file with `STATUS: ACTIVE` and re-run.
5. Dirty a tracked file in the **sibling** worktree and re-run.
6. Write CRLF into a tracked file and re-run.
7. Dirty the primary again, capture branch, HEAD and `git status --porcelain`,
   run the check, and capture all three again.
8. Run `session.mjs start "<title>" --json --root <sandbox> --branch
   agent/somewhere-else`, then again with `--branch develop`.

## Expected Result

Written before execution.

1. `PRIMARY_WORKTREE_STATUS = DIRTY_UNEXPLAINED`, `TASK_WORKTREE_STATUS =
   CLEAN`, the path listed in `unexplainedDirtyFiles` with `owner: UNKNOWN`, and
   a matching entry in `blockers` — not `warnings`.
2. `PRIMARY_WORKTREE_STATUS = DIRTY_USER_OWNED`, nothing unexplained, and the
   file still present on disk with its edit intact.
3. The generator path is attributed `GENERATED_BY_FRAMEWORK`, and the status is
   not `CLEAN` — uncommitted generator output is repository work.
4. `STATUS: COMPLETE` gives `ORPHANED_SESSION_STUB` and
   `PRIMARY_WORKTREE_STATUS = DIRTY_UNEXPLAINED`. `STATUS: ACTIVE` gives
   `ACTIVE_SESSION_RECORD` owned by `SESSION-9001` and
   `PRIMARY_WORKTREE_STATUS = DIRTY_OTHER_SESSION_OWNED`, which does not block.
   The file is untouched either way.
5. The sibling appears in `otherDirtyWorktrees` with its branch, and its
   uncommitted content is unchanged afterwards.
6. The line-ending change is either normalised away by `.gitattributes` or
   reported as a dirty path — never silently invisible.
7. Branch, HEAD and porcelain output are byte-identical before and after. The
   dirty file still holds its edit: nothing was pulled, merged, reset or
   restored.
8. The first reports `PRIMARY_WORKTREE_ARTIFACT: true` and names the worktree it
   wrote into; the second reports `false`.

Every worktree in the report carries a `role` of exactly one of `PRIMARY`,
`TASK` or `OTHER`, with exactly one `PRIMARY`.
