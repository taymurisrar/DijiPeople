# QA-AUTH-031 — Terminating an employee ends the linked user's access, now or on the effective date

## Preconditions

An employee with a linked, signed-in user (web and agent sessions) in a tenant that is not the owner of that user; HR role holding employees.terminate.

## Steps

1. POST /employees/:id/terminate with no date (or a past date).
2. Use the old access token and refresh token, and the agent session, again.
3. Repeat step 1 (idempotency).
4. Terminate with a future date; confirm access still works; advance past the date and run one sweeper tick.
5. Terminate the tenant owner.

## Expected Result

Step 1 disables the user and revokes web and agent refresh tokens in one transaction; step 2 is refused. Step 3 reports ALREADY_REVOKED. Step 4: access continues until the date, the audit row says FUTURE_DATED_REVOCATION_SCHEDULED, and the sweeper then revokes and audits EMPLOYEE_ACCESS_REVOKED with no human actor. Step 5: the owner is never disabled.
