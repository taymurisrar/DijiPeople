# QA-SETTINGS-012 — A footer that reported the page it loaded as the collection

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-354 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

The requested page reaches the API and the adapter's own query parameters survive it; an over-cap page size is clamped to the 100 both query DTOs allow; an adapter that cannot paginate receives no page parameters at all; a response of 20 items with `meta.total: 305` reports 305; both envelope shapes are read - nested under `meta` and flat beside `items`; `totalPages` is derived when omitted; a bare array reports null so the caller keeps client mode.

## Expected Result

The behaviour holds as REG-354 describes it. There is no automated guard, so this scenario is executed by hand and its result recorded here.

## Why This Is Reusable

`SettingsRuntimeList` fetched `settingsListApiPath(adapter)` with no `page` or `pageSize`, took the server's default of 20 rows, and handed the table `totalItems: records.length` under `paginationMode="client"`. The response's own `meta.total` - 305 on the observed tenant - was never read, and the URL's page size reached only the client slice
