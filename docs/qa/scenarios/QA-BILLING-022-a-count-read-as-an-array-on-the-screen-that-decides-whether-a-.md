# QA-BILLING-022 — A count read as an array, on the screen that decides whether a plan can be retired

## Preconditions

A tenant on which the affected surface is reachable, and a signed-in user with
the permissions the surface requires. REG-349 in the regression register carries
the full root cause; this scenario is the reusable check, not the diagnosis.

## Steps

`planSubscriptionCount` returns the count for the exact production payload (`{ subscriptions: 2 }`), for the explicit `subscriptionCount` field, and for the relation-array shape `PlatformRuntimeService.findGeneric` genuinely returns for a plan. Zero stays zero; a string, a NaN and a negative are refused rather than coerced.

## Expected Result

The behaviour holds as REG-349 describes it. The automated guard is `apps/admin/lib/runtime/plan-subscription-count.spec.ts`; a run of that suite is sufficient evidence for this scenario.

## Why This Is Reusable

`SuperAdminService.mapPlan` publishes the subscription count twice — as `subscriptionCount` and, deliberately, as `subscriptions`, because `validateRuntimeDefinition` resolves every list column against the Prisma model graph and a computed alias resolves to nothing. Both are numbers
