# QA-AGENT-009 — A release the update feed cannot serve is refused at publish, not silently omitted

## Preconditions

A platform administrator able to publish an application release. Two artefact
routes: one uploaded through StorageService, and one hosted externally and
registered by URL.

The desktop agent update feed selects releases on a non-null SHA-512, so a release
without one can never serve it.

## Steps

1. Publish an AGENT_DESKTOP release with an externalUrl and a SHA-256 but no
   SHA-512, on the STABLE channel.
2. Publish the same with a SHA-512 supplied.
3. Publish an uploaded-artefact release, which computes its own digest.
4. Request the update feed for AGENT_DESKTOP after each.

## Expected Result

- Step 1 is **refused at publish**. Before this fix it was accepted, listed in the
  catalogue, downloadable through the 302, and silently absent from the update
  feed for ever — a release that looks published and reaches nobody.
- Step 2 is accepted and appears in the feed.
- Step 3 is unaffected: the upload path already computed and stored the digest.
- The feed never returns 404 for a release the catalogue shows as publishable on
  a stable channel. Silence is the defect here, so the requirement is that the
  failure becomes visible at the moment it is created.
