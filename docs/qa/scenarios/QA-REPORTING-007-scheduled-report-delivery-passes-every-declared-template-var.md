# QA-REPORTING-007 — Scheduled report delivery passes every declared template variable

## Preconditions

A due report schedule with at least one recipient in the workspace.

## Steps

1. Drain the scheduler for that schedule and capture the notification dispatch.
2. Read `availableVariables` off the `REPORT_SCHEDULE_DELIVERY` catalog seed.
3. Compare the keys the template declares against the variables the worker sent.
4. Repeat with a tenant whose display name is blank, and with a tenant row that cannot be read.

## Expected Result

Every declared key is present and non-null in the dispatch. A blank display name falls back to the tenant's own name, and an unreadable tenant row falls back to the product name — the report is delivered in both cases.

## Notes

Assert against the template's own declaration, never a hand-written list, so a variable added later fails this test rather than production. `EmailTemplateRendererService` treats a declared-but-absent variable as a hard failure, so an omission stops the email rather than blanking a field.
