# QA-TENANT-027 — A blocked save always points at the field that blocked it

## Preconditions

- Platform Admin, signed in as a `PLATFORM_OWNER`.

## Steps

1. Run `npm --workspace admin run test -- blocked-save`.
2. Open **Partners → New**. Fill only **Partner name** on the Summary tab.
3. Press **Save**.
4. Repeat on any other multi-tab create form — Leads and Customers both
   qualify.

## Expected Result

- The suite passes.
- The save is blocked and the form moves to the tab holding the first failure.
- Every tab holding an invalid field shows a count badge.
- The toolbar message names the failing fields rather than only stating that
  some exist.
- At no point does the form refuse to save while marking nothing anywhere.

## Expected Result — the negative

The state this scenario exists to prevent: a generic "Complete the required
fields." with a complete-looking visible tab and no error marker anywhere in the
DOM.

## Notes

The last assertion in the automated suite runs against the real partner form
definition rather than a fixture, and fails for any module declaring a required
field with no tab — that is the exact condition that produced the original dead
end.

Server-side field errors take the same path. Worth checking that half too: it is
what made BUG-1742 present as "nothing on either tab is marked".
