# QA-BILLING-017 — A missing or malformed Stripe webhook secret fails the deployment smoke suite

## Preconditions

A reachable API base URL. No database and no Stripe account are needed — the
check reads the running process's own environment, which is the point: it is
meant to run from inside the deployment, where that environment is production's.

## Steps

Four branches, run against any reachable API:

```bash
BASE="SMOKE_API_BASE_URL=https://api.dijipeople.com/api SMOKE_ORIGIN=https://app.dijipeople.com"

# A — absent and not required (a developer's laptop)
env $BASE node scripts/smoke-deployment.mjs

# B — required but unset (a deployment missing the variable)
env $BASE SMOKE_REQUIRE_STRIPE_WEBHOOK_SECRET=1 node scripts/smoke-deployment.mjs

# C — set to the wrong kind of key
env $BASE STRIPE_WEBHOOK_SECRET=sk_test_notasigningsecret node scripts/smoke-deployment.mjs

# D — set to a well-formed signing secret
env $BASE STRIPE_WEBHOOK_SECRET=whsec_exampleonly node scripts/smoke-deployment.mjs
```

## Expected Result

| Branch | Expected |
|---|---|
| A | **Skipped**, with the reason printed. A developer running the suite locally must not be told their machine is a broken deployment. |
| B | **`not ok`**, and the message names *Stripe → Developers → Webhooks → Recent deliveries → Resend* |
| C | **`not ok`** on the missing `whsec_` prefix |
| D | **`ok`** |

Branches B and C are the scenario. A check that passes with the variable unset
guards nothing, and that is exactly the state production was in on 2026-08-23
while every delivery was rejected.

## Notes

**What this scenario deliberately does not prove.** It cannot establish that the
secret is *correct*. A request with a deliberately-invalid signature is rejected
whether the configured secret matches the endpoint or not — which is why the
probe used to diagnose [[BUG-0989]] could exonerate the code and could not
confirm the fix. Only Stripe, replaying a genuinely signed delivery, answers
that, and the failure message says so rather than implying more than it knows.

The full proof is the end-to-end purchase in [[ITEM-0078]]. The operator-facing
gap that let this reach production — a go-live check reporting one blocker while
every webhook failed — is [[ITEM-0094]].

Run 2026-08-24 at `7365fe46` — all four branches behaved as specified.
