# QA-SETTINGS-028 — Email templates are authored with a visual editor, a variable picker and Customize on system templates

## Preconditions

- A tenant administrator holding the notification template permissions.
- Tenant 1 on a plan with payroll; tenant 2 on the Starter plan.
- Email delivered to a controlled mailbox only.

## Steps

1. Open `/settings/notifications/templates` at 1440px and 400px.
2. Open Password reset.
3. Choose Customize; go back to the list and Customize again.
4. In the copy: apply bold, italic, a list, a heading and a link; insert the
   Recipient name variable in the subject and in the message; type `{{salary}}`.
5. Remove `{{salary}}`; Save and activate; Send test to the controlled mailbox.
6. Request a password reset; then Archive the copy (confirm dialog; Escape
   closes it) and request another.
7. New template: open the Event picker; pick an event; Save as draft.
8. On tenant 2, open New template and the Module picker.
9. Repeat steps 4-5 in Chrome, Firefox and Safari.

## Expected Result

- Step 1: system rows Account activation, Password reset, Scheduled report, and
  Payslip only with payroll; no Invoice, Support, Verification code, Leave,
  Timesheet or Payroll processed; each key shown once; no clipping.
- Step 2: a rendered preview (subject, formatted view, plain text), no inputs,
  one Customize action.
- Step 3: a DRAFT tenant copy with the same key; the second Customize opens the
  same copy.
- Step 4: formatting applies; `{{recipientName}}` lands at the caret; the
  preview updates within about half a second; `{{salary}}` is reported as not
  supplied and Save is refused.
- Step 5: the test result matches the delivery log status.
- Step 6: the first email uses the customized copy, the second the system copy.
- Step 7: only authorable events; content prefilled; redirect to the editor;
  no HTML or JSON field anywhere.
- Step 8: no Payroll, Claims, Loans, Benefits or Performance; no Payslip event.
- Step 9: markup survives a save in each browser.
