# QA-PLATFORM-006 — The platform runtime manifest is derived from the current Prisma schema

## Preconditions

None. A pure derivation check over two files in the repository.

## Steps

1. Parse `services/api/prisma/schema.prisma` and derive the runtime manifest in
   memory, using the generator itself rather than a reimplementation.
2. Compare it to the committed
   `packages/config/platform-runtime-schema.generated.json`, module by module
   and field by field.

## Expected Result

They are identical. Any difference fails naming the module and the field —
`customers: missing field originChannel` — rather than reporting that a 4 MB
file differs.

## Notes

Do not "improve" this into a standalone comparator script. The check runs the
generator's own derivation precisely so there is one implementation; a second
copy could drift independently, which is the defect it exists to catch.

The reason this was needed at all: `test:runtime-schema` validates the registry
against the manifest, so when the manifest went stale the registry built from it
agreed and every check passed. Same family as [[QA-PLATFORM-005]] — an assertion
that proves presence rather than reachability.
