# LESSON-0004 — New component keys must be camelCase logical names

## Evidence

The existing Package ALM e2e suite went from 19/19 to 6/19 after the plan added hyphenated keys; the integrity-check log said only "failed verification" until it was changed to name the cause: `components[6].objectKey: Component logical name is invalid`. Fixed by camelCase keys; `module-provisioning.spec.ts` now asserts every planned key matches the metadata key pattern.

## Proposed change

Reuse the metadata key pattern as one exported constant checked wherever component keys are minted (provisioner, designer APIs), instead of a private regex in the DTO file.

## Why this is not already covered

The DTO pattern guards user input only; keys generated by code bypass it. Only an unrelated end-to-end suite noticed.
