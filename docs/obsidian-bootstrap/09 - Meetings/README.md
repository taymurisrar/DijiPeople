# 09 - Meetings

Meeting notes.

Use `99 - Templates/Meeting.md`.

Naming: `YYYY-MM-DD — <topic>.md`

## Why these matter

Most requirements in a product like this originate in a conversation. Six months
later the question is always the same: *who decided this, and why?* These notes
answer it.

## Rules

- **Keep attribution.** Who said what matters when a requirement is later
  questioned.
- **Record decisions separately** from discussion, in the table the template
  provides. Anything with lasting architectural consequence becomes a note in
  `05 - Decisions/` and, once settled, an ADR in the repository.
- **Record requirements in the speaker's own words** where possible.
  Paraphrasing into implementation language loses information that turns out to
  matter.
- **Record open questions.** These become the
  `TODO: Confirm product/business rule.` markers elsewhere in the vault.
- Action items get an owner and a date, or they are not action items.
