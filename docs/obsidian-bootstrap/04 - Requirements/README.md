# 04 - Requirements

Feature requirements **before** they are built: what the product should do, in
business terms.

Use `99 - Templates/Feature.md`. One note per feature.

Naming: `Feature — <name>.md`

## Rules

- Requirements live here, not in the repository. The repository documents what
  **is**; this documents what **should be**.
- Do not fabricate business rules. Anything not established from the repository
  or confirmed by a human is marked:
  `TODO: Confirm product/business rule.`
- Link the module notes in `03 - Modules/` and, once planned, the ExecPlan in
  `06 - Implementation Plans/`.
- Keep the requirement and the plan separate. The requirement is *what and why*;
  the plan is *how*.

## Status flow

`#status/draft` → `#status/needs-review` → `#status/confirmed` → Implemented →
Released
