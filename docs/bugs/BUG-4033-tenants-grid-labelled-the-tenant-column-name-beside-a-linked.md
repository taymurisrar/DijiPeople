# BUG-4033 — Tenants grid labelled the tenant column Name beside a linked Customer name, so operators opened the customer believing it was the tenant

## Summary

The Tenants grid labelled its identity column "Name" and rendered the related customer's company name as a linked value beside it. Tenants are usually named after their customer, so the only blue, clickable name in a row was often the customer's — operators clicked it expecting the tenant and landed on the customer. The customer's own Tenants tab repeated a Customer column pointing back at itself.

## Expected Behavior

The record a grid lists owns the primary link and is labelled as that record; related records are labelled for what they are.

## Actual Behavior

Tenant identity was an unlinked "Name"; the linked value was the Customer.

## Reproduction

1. Open Platform Admin → Tenants.
2. A row shows "Name" (plain) and "Customer" (link) with identical text.
3. Click the link: the customer record opens, not the tenant.

## Evidence

`apps/admin/lib/runtime/platform-module-registry.ts`, tenants module columns: `col("displayName", "Name", 220)` beside `col("customerAccount.companyName", "Customer", …, link /customers)`. The customer Tenants related grid used the tenant list's first four columns, including Customer.

## Root Cause

Column metadata: the identity column had no link and a generic label, and the related grid inherited columns meant for the global list.

## Impact

Platform operators navigating to the wrong record — customer instead of tenant — before acting on it.

## Affected Areas

Tenants list; Customer → Tenants tab; Partner → Tenants tab.

## Proposed Resolution

Label the identity column "Tenant" and link it to the tenant; give related tenant grids explicit columns without a self-referencing Customer column.

## Acceptance Criteria

- Tenants list: first column "Tenant" links to /tenants/{id}; "Customer" links to /customers/{id}.
- Customer → Tenants tab has no Customer column.

## Regression Coverage
