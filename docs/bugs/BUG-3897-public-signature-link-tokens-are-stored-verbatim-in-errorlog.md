# BUG-3897 — Public signature-link tokens are stored verbatim in ErrorLog.path and readable by monitoring.read holders

## Summary

When a request to a public signature link fails, the error log stores the full
request path, `/api/public/signatures/<token>`. The token is a bearer secret:
anyone who has it can open the signing page. Every platform user with
`monitoring.read` can therefore read live signature tokens. The sanitizer redacts
keys and request bodies, but not URL path segments.

## Expected Behavior

Bearer-token path segments are redacted before an error-log row is persisted.
This covers signature links, and the invite and password-reset routes too.

## Actual Behavior

The token is stored verbatim in `ErrorLog.path`, and on its occurrences.

## Reproduction

1. Request `GET /api/public/signatures/<any token>` so that it fails, for
   example a token that is not found.
2. Open the incident in Platform admin, Monitoring. The path shows the token in
   full.

## Evidence

- Production `ErrorLog`, read-only query on 2026-10-07: 2 incidents queued as
  NEW, on 2026-08-11 and 2026-09-05, with no tenant. One reads "already
  completed" and one "not found". Each path carries a 43-character token. The
  values are deliberately not reproduced here.
- The error-log sanitizer redacts by key and body, and never inspects `path`.

## Root Cause

Path segments are outside the redaction rules.

## Impact

Raised from LOW to MEDIUM because these are bearer secrets readable by anyone
with `monitoring.read`. A token for an unfinished signature would let the reader
view the document and possibly sign it. The two observed tokens refer to a
completed and a missing signature, so their own risk is low. Any future failure
on a live link would expose a usable one.

## Affected Areas

- `services/api/src/modules/error-logs` (persisting paths)
- The error-log sanitizer in `services/api/src/common`
- Public routes that carry tokens in the path: signatures, and any invite or
  reset routes that do the same.

## Proposed Resolution

Redact token segments on known public bearer routes before persisting, for
example `/api/public/signatures/[REDACTED]`. Then scrub the existing rows with a
reviewed one-off update. The scrub mutates production data and needs the owner's
go-ahead.

## Acceptance Criteria

- A failing request to a signature link persists a redacted path.
- A spec covers each public bearer route pattern.
- No existing `ErrorLog` or occurrence row contains a raw signature token.

## Regression Coverage

None yet.

## Dependencies

The owner's go-ahead for the scrub of existing rows.
