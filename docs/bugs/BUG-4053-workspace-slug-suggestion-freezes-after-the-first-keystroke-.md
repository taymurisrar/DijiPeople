# BUG-4053 — Workspace slug suggestion freezes after the first keystroke (reads as initials)

## Summary

The workspace slug suggested during subscribe froze after the first keystroke of the company name, so a long name produced a one or two letter slug that read as initials. Accented characters were dropped instead of folded.

## Expected Behavior

The suggested slug tracks the company name until the user edits the slug by hand, and accented letters fold to their base letter.

## Actual Behavior

suggestSlug only ran while the requested slug field was empty, so after the first character it stopped updating. NFKD normalisation without a combining-mark strip dropped accented characters.

## Reproduction

1. Open /subscribe and type a company name such as Cafe Zoe slowly.
2. Observe the slug field stop updating after the first letter.
3. Type an accented name and observe missing letters.

## Evidence

Reproduced and diagnosed during SESSION-0121 (DP platform remediation) against 4489a3c6. The regression tests named in REG coverage pass with the fix; they were not mutation-tested against the pre-fix code.

## Root Cause

apps/landing/lib/onboarding-wizard.ts suggestSlug was gated on requestedSlug being empty and never marked the slug as user-edited versus suggested; the server-side slug suggestion in the subscription order service had the same mark-stripping gap.

## Impact

Reachable in production through the normal user flow described above.

## Affected Areas

apps/landing, billing

## Proposed Resolution

Implemented; see Resolution.

## Acceptance Criteria

The expected behaviour above holds and the regression test passes.
