# BUG-3506 — The payslip email has no working button and names the payroll calendar as the company

## Summary

When a payslip is published, the payslip email is built from variables the
payslips service passes to the notification templates. It passes the "view
payslip" link as a relative path and passes the payroll calendar's name where
the template expects the tenant's name. So the email cannot carry a working
button, and wherever it names the company it would print the payroll calendar
instead. The authored payslip copy written for [[BUG-3500]] therefore leaves out
both the button and the company name.

## Expected Behavior

The payslip email carries an absolute link that opens the employee's payslip in
the tenant's workspace, and names the tenant (the employer), exactly like the
other ACTIVE system emails.

## Actual Behavior

- `actionUrl` is a path relative to the web app, which an email client cannot
  open.
- `tenantName` holds the payroll calendar's name, not the tenant's name.
- The authored copy therefore omits the button and the company name.

## Reproduction

1. On a tenant with payroll and a mailbox you control, publish a payslip for an
   employee whose email is that mailbox.
2. Inspect the payslip email, or the variables recorded on its
   `EmailDeliveryLog` row.
3. Observe `actionUrl` as a relative path and `tenantName` equal to the payroll
   calendar's name.

Found by reading the emitter while authoring template copy in TASK-0031 WP-04;
not yet observed in a delivered email.

## Evidence

- `services/api/src/modules/payslips/payslips.service.ts` — the payslip email
  call site (lines 562-577 at `88f33c6e`) passes `actionUrl` as a relative path
  and `tenantName` from the payroll calendar.
- `services/api/src/modules/notifications/system-email-templates.copy.ts` — the
  payslip template's variables are the intersection of what this emitter
  passes, so neither a button nor the company name is declared.
- `docs/tasks/TASK-0031-streams/WP-04-report.md`, "Residual risks and
  follow-ups".

## Root Cause

The payslips emitter builds its variables from payroll-run context: the calendar
record is in hand, the tenant record is not, and no absolute web base URL is
resolved before the call.

## Impact

Every employee who receives a payslip email gets a message with no way to open
the payslip from it and no employer name. Reachable in production once tenant
email is delivered for real (ADR-0015), which is the state after the TASK-0031
release. No data exposure.

## Affected Areas

- API `payslips` module: the payslip email call site.
- API `notifications` module: the payslip system template copy.

## Proposed Resolution

Pass an absolute payslip URL, built from the tenant's workspace host the way the
other ACTIVE emitters do, and pass the tenant's name. Then add the button and the
company name to the authored copy, and let
`services/api/src/modules/notifications/system-email-template-emitters.spec.ts`
enforce the new variables. No ExecPlan needed.

## Acceptance Criteria

- The payslip email's `actionUrl` is absolute and opens the payslip for the
  recipient.
- The email names the tenant, never the payroll calendar.
- The payslip copy declares both variables and the emitter spec passes.

## Regression Coverage

Extend `system-email-template-emitters.spec.ts` so the payslip template declares
`actionUrl` and `tenantName`, and add a payslips spec asserting the URL is
absolute and the name comes from the tenant. Both must fail against the current
call site. A REG entry follows the fix.
