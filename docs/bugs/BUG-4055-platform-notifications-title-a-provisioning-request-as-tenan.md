# BUG-4055 — Platform notifications title a provisioning request as 'Tenant provisioned' and carry no subject

## Summary

Platform notifications for a tenant provisioning request were titled Tenant provisioned and carried no subject, so operators could not tell which request or tenant they referred to, and a request looked like a completed provisioning.

## Expected Behavior

A provisioning request is titled as a request, and every platform notification names its subject (tenant or request).

## Actual Behavior

Title read Tenant provisioned for a request that had not been provisioned, and the notification had no subject.

## Reproduction

1. Submit a tenant provisioning request.
2. Open the platform admin notification bell.
3. Observe the misleading title and missing subject.

## Evidence

Reproduced and diagnosed during SESSION-0121 (DP platform remediation) against 4489a3c6. The regression tests named in REG coverage pass with the fix; they were not mutation-tested against the pre-fix code.

## Root Cause

The platform notification mapping in services/api/src/modules/platform-events reused the provisioned title for the request event and did not copy the subject from the event payload.

## Impact

Reachable in production through the normal user flow described above.

## Affected Areas

platform-events

## Proposed Resolution

Implemented; see Resolution.

## Acceptance Criteria

The expected behaviour above holds and the regression test passes.
