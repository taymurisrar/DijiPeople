# BUG-4218 — Stored signed copy of an agreement is not reachable from Platform Admin

## Summary

When the last signer completes, the immutable signed PDF and the evidence bundle are stored as contract documents. The API exposes a download for them, but nothing in Platform Admin listed or linked them; "Generate document" builds a new copy instead of opening the stored one.

## Expected Behavior

The agreement record lists its stored documents — signed copy first — each downloadable.

## Actual Behavior

No screen showed `CON-20261012-E7421CC1-v2.pdf` (SIGNED_COPY) or its evidence bundle.

## Reproduction

1. Open an executed agreement in Platform Admin.
2. Look for the signed copy: none of the tabs lists it.

## Evidence

`GET /contracts/documents/:documentId/download` exists in the controller; no admin code referenced it. The record payload already carries `documents`.

## Root Cause

No admin panel was ever built for `ContractDocument`.

## Impact

Operators cannot retrieve the legally executed copy without database or storage access.

## Affected Areas

Platform Admin agreement record (Signatures tab); admin contracts proxy route.

## Proposed Resolution

A "Signed documents" panel on the Signatures tab; the proxy streams any attachment.

## Acceptance Criteria

- The Signatures tab lists the agreement's documents, signed copy first, each with a Download link.
- The evidence bundle (JSON) downloads as a file.

## Regression Coverage

Covered by REG-684 together with BUG-4217; the panel is presentational.

## Dependencies

None.

## Related Items

- [[BUG-4217]]

## Resolution

Branch `agent/contract-activation-documents`: `ContractDocumentsPanel` in the admin record page; the contracts proxy forwards attachments as files.
