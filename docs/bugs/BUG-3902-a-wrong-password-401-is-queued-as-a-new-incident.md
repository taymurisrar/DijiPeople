# BUG-3902 — A wrong-password 401 is queued as a NEW incident

## Summary

A failed sign-in with a wrong password, which returns 401
`AUTH_INVALID_CREDENTIALS`, is queued in monitoring as a NEW incident. That code
is not in `SESSION_AUTH_CODES`, so the expected-outcome classifier does not treat
it as routine. An admin login rejected with 400 for a malformed email is also
queued.

## Expected Behavior

A wrong-password attempt is recorded as an expected outcome and is not queued.
Spikes are visible through the Authentication health tile and the lockout
counts, which measure exactly that.

## Actual Behavior

Each wrong-password attempt opens or extends a NEW incident.

## Reproduction

1. Sign in with a valid email and a wrong password.
2. Platform admin, Monitoring, Error logs shows a NEW `AUTH_INVALID_CREDENTIALS`
   incident.

## Evidence

- Production `ErrorLog`, read-only query on 2026-10-07: 8 occurrences from
  2026-08-08 to 2026-09-24, 1 in the last 14 days, with no tenant.
- `expected-protocol-outcome.ts`: `SESSION_AUTH_CODES` does not include
  `AUTH_INVALID_CREDENTIALS`.

## Root Cause

The expected-outcome list covers session codes but not credential failures.

## Impact

Low-volume noise in the incident queue. No security impact.

## Affected Areas

- `services/api/src/modules/error-logs` (the expected-outcome classification)
- `services/api/src/modules/auth`

## Proposed Resolution

Classify `AUTH_INVALID_CREDENTIALS`, and validation 400s on login, as expected
outcomes. Rely on the Authentication tile and the lockouts for spikes. Decide this
together with [[BUG-3230]], which covers auditing login failures.

## Acceptance Criteria

- A wrong-password attempt writes no NEW incident.
- The Authentication tile still counts it.

that the signal is not lost.
