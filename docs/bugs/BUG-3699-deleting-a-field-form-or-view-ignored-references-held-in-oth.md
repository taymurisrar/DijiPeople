# BUG-3699 — Deleting a field, form or view ignored references held in other packages' layers

## Summary

Deleting a field, form or view checked only form layouts and view columns. A relationship, action bar, or an extension of a DijiPeople Core form that named the component was invisible to that check, so the delete succeeded and left those layers pointing at nothing.

## Expected Behavior

A component another layer still names cannot be deleted; the refusal names what uses it.

## Actual Behavior

Before the fix: the delete succeeded and the referencing layer silently broke.

## Reproduction

1. Create a lookup field and a relationship whose reference field is that field, in another package.
2. Delete the field. It was deleted.

## Evidence

`services/api/test/customization-package-alm.e2e-spec.ts` — "delete safety (B3)".

## Root Cause

Two dependency notions: the layout check for deletes, and the metadata scan for publish. Deletes never consulted the second.

## Impact

Broken relationships and action bars after an ordinary delete. Reachable in production before the fix.

## Affected Areas

customization: deleteColumn, deleteForm, deleteTableView.

## Proposed Resolution

Done: delete safety uses the same portable reader that computes package dependencies for export.

## Acceptance Criteria

Deleting a component named by any layer in any package is refused with the names of the users.

## Regression Coverage

REG-635 — `services/api/test/customization-package-alm.e2e-spec.ts`.
