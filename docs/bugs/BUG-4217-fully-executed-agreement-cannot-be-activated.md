# BUG-4217 — Fully executed agreement cannot be activated

## Summary

Completing the last signature moves an agreement to FULLY_EXECUTED, but the governed "next stage" transition activated only from FULLY_SIGNED — a status the signing flow never sets. An executed agreement therefore had no way to become ACTIVE.

## Expected Behavior

A fully signed or fully executed agreement can be activated; activation records `activatedAt` and a timeline entry.

## Actual Behavior

`CON-20261012-E7421CC1` (FULLY_EXECUTED, production) offered no activation; the transition API refused it.

## Reproduction

1. Sign every required signer of an agreement.
2. Status is FULLY_EXECUTED.
3. Next stage → "The fully executed stage must use its governed … activation … action", and no such action existed.

## Evidence

`services/api/src/modules/contracts/contracts.service.ts`, `transitionStage`: forward map had `FULLY_SIGNED: ACTIVE` only; `completeSignature` sets `FULLY_EXECUTED`.

## Root Cause

The forward map and the activation guard predate the FULLY_EXECUTED completion status and were never updated.

## Impact

Every executed agreement stays "Fully executed" indefinitely. Governing-agreement gates already accept FULLY_EXECUTED, so conversion and provisioning were not blocked.

## Affected Areas

Contracts API transition; Platform Admin contract record actions.

## Proposed Resolution

Allow FULLY_EXECUTED → ACTIVE; offer a primary "Activate contract" action.

## Acceptance Criteria

- FULLY_EXECUTED and FULLY_SIGNED agreements move to ACTIVE with `activatedAt` and a STAGE_CHANGED timeline entry.
- An unsigned (SENT) agreement still cannot be activated.
