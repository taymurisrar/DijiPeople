# BUG-3955 — Partner Save persists no field but reports Partner saved, because the write contract misreads PartialType

## Summary

Editing a partner and clicking Save showed "Partner saved." but changed nothing. The generated runtime write contract marked zero partner fields editable. The admin app therefore sent `values: {}`, and the API accepted it as a successful no-op update.

## Expected Behavior

Every field the Update DTO accepts is editable, and a save persists it. An edit with nothing to send says "No changes to save" rather than reporting success.

## Actual Behavior

`scripts/lib/runtime-write-contract.mjs:172` used the regex `extends\s+(\w+)`. For `UpdatePartnerDto extends PartialType(CreatePartnerDto)` it captured `PartialType`, so it never reached the wrapped DTO's fields. The independent parser in `apps/admin/lib/runtime/runtime-write-contract.spec.ts` had the same flaw, which is why the spec passed.

## Reproduction

1. Open a partner and click Edit.
2. Change Phone, then click Save.
3. The page shows "Partner saved." but the value is unchanged after a reload.

## Evidence

- In the generated runtime schema at `898a6ac3`, partners has 0 editable fields and 16 creatable fields.
- `buildWritePayload` filters the payload by the editable set.
- The regression came in with `eb172564` and `cd777b78`, the DTO change to PartialType.

## Root Cause

The write-contract generator could not parse NestJS mapped-type wrappers, and the spec meant to catch that used the same flawed parser.

## Impact

No platform operator could edit any partner field from the record page, and the UI hid that by reporting success.

## Affected Areas

Partner edit in apps/admin. In principle, any runtime module whose Update DTO uses a mapped type; today that is only partners.

## Proposed Resolution

Resolve PartialType, OmitType, PickType and IntersectionType in the parser, and test each one. Regenerate the schema. Report an empty edit as "No changes to save".

## Acceptance Criteria

- Partner fields accepted by UpdatePartnerDto are editable.
- status, accountStatus, partnerNumber and code are not editable.
- An empty edit says "No changes to save" and makes no request.
- The parser spec covers every wrapper type.

## Regression Coverage

## Resolution

- Fixed the parser in `runtime-write-contract.mjs`, including nested and multi-line wrappers, and fixed the admin spec parser.
- Regenerated the runtime schema. Partners is the only module whose editable set changed; each newly editable field was reviewed against UpdatePartnerDto and `partnerUpdateData`.
- Added `emptyEditOutcome()` for every module.
