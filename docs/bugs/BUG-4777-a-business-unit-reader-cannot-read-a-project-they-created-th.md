# BUG-4777 — A business-unit reader cannot read a project they created themselves

## Summary

A user whose access to projects is business-unit, organisation or subtree level could create a project and then get a 404 on it unless the project sat in a unit they reach. Only the self-service branch of the read filter included the creator.

## Expected Behavior

Whoever created a project can always read it.

## Actual Behavior

`POST /projects` returned 201 and `GET /projects/:id` returned 404 for the same user.

## Reproduction

1. As a manager with business-unit reach create a project with no business unit. 2. Read it back.

## Evidence

Found by the browser journeys for the project Work area. `ProjectsService.buildProjectReadWhere` added `createdById` for the self-scope branch only.

## Root Cause

The business-unit, subtree and organisation branches of the read filter filtered by placement alone.

## Impact

A creator is locked out of their own project, and the work area built on it, until someone changes its placement.

## Affected Areas

`services/api/src/modules/projects/projects.service.ts`.

## Proposed Resolution

Every non-tenant branch also allows `createdById`.

## Acceptance Criteria

A business-unit reader reads a project they created.

## Regression Coverage

REG-733: a unit test in `services/api/src/modules/projects/projects.service.spec.ts` asserting the scope includes the creator.

## Dependencies

None.

## Related Items

QA-PROJECTS-001 (scenario record)

## Resolution

The three branches now OR in `createdById`, on branch `agent/dp-master-wp01-baseline`.
