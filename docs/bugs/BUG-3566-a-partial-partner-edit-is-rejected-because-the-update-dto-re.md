# BUG-3566 — A partial partner edit is rejected because the update DTO requires every create field

## Summary

Updating a single field of a partner through the API is refused with a validation error, because `UpdatePartnerDto` inherits every required field of `CreatePartnerDto` instead of making them optional like every sibling update DTO.

## Expected Behavior

A PATCH carrying only the changed fields succeeds; business rules are applied to the merged record.

## Actual Behavior

A partial PATCH returns 400 for the missing required create fields. The admin UI resends every editable field, so it does not hit this, but any API client does.

## Reproduction

1. As SUPER_ADMIN, `PATCH /api/platform-runtime/partners/<id>` with `{ "values": { "phone": "+1 555 0100" } }`.
2. 400 naming required fields.

## Evidence

- WP-08 live CRUD harness, 2026-09-25, finding 3.
- `services/api/src/modules/partners/dto/partner.dto.ts:79` `export class UpdatePartnerDto extends CreatePartnerDto {}`.

## Root Cause

The update DTO reuses the create DTO wholesale.

## Impact

Integrations and scripts cannot partially update partners; the UI works by always sending the full record.

## Affected Areas

partners DTOs and service; platform-runtime partners update.

## Proposed Resolution

Make every update field optional; apply the partner-type policy (BUG-3549) to the merged record. Assigned to TASK-0032 WP-04.

## Acceptance Criteria

A one-field PATCH succeeds; a PATCH that would leave a company partner without its required fields is refused.
