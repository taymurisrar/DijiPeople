# BUG-4058 — Customer list Owner, Onboarding and Agreements columns are empty

## Summary

The platform admin customer list showed empty Owner, Onboarding and Agreements columns for every customer.

## Expected Behavior

Owner shows the assigned user name, Onboarding shows onboarding progress and Agreements shows the agreement count.

## Actual Behavior

All three columns were blank.

## Reproduction

1. Open Customers in platform admin.
2. Observe the three columns empty although records have owners and agreements.

## Evidence

Reproduced and diagnosed during SESSION-0121 (DP platform remediation) against 4489a3c6. The regression tests named in REG coverage pass with the fix; they were not mutation-tested against the pre-fix code.

## Root Cause

super-admin listCustomers never included assignedToUser or the relation counts, and fullName was never mapped onto the row, so the columns had nothing to read.

## Impact

Reachable in production through the normal user flow described above.

## Affected Areas

super-admin, apps/admin

## Proposed Resolution

Implemented; see Resolution.

## Acceptance Criteria

The expected behaviour above holds and the regression test passes.

## Regression Coverage

REG-673. See docs/qa/regressions/index.md.

## Dependencies

None.

## Related Items

None.

## Resolution

Commit 51c80beb: listCustomers includes the owner and counts with explicit select, maps fullName, and the admin runtime column definitions (apps/admin/lib/runtime/platform-module-registry.ts) read the new fields.

## QA Retest

Scenario: Customer list Owner, Onboarding and Agreements columns are populated (see the QA scenario linked from REG-673).
