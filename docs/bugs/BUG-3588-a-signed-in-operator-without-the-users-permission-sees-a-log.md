# BUG-3588 — A signed-in operator without the users permission sees a login-style Access denied page

## Summary

A platform operator who is signed in but lacks `platform-users.manage` (or the
equivalent permission for the Platform Users screen) sees a full-page "Access
denied … Open admin login" screen when opening that screen — the same
presentation used for an unauthenticated visitor, which reads as "you are not
signed in" rather than "you are signed in but not authorized for this
screen".

## Expected Behavior

A signed-in operator refused a screen for lacking permission should see a
distinct, in-shell "you don't have access to this" state — keeping navigation
and their signed-in identity visible — rather than the same page a logged-out
visitor sees, and with no dead-end "Open admin login" action for someone who
is already logged in.

## Actual Behavior

The Platform Users screen's access-denied rendering reuses the unauthenticated
gate's full-page layout, including a login prompt, for a signed-in user who is
simply missing a permission.

## Reproduction

1. Sign in to `apps/admin` as a platform user without `platform-users.manage`.
2. Navigate to the Platform Users screen.
3. Observe a full "Access denied … Open admin login" page rather than an
   in-shell, permission-specific message.
