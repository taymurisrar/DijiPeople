# BUG-3898 — Platform health tile drill-downs land on panels that do not show the signal the tile measures

## Summary

Each platform health tile on the Monitoring overview links to a drill-down. Most
of those links land on a panel that does not show what the tile measures:

- The Authentication tile links to an error-log filter that matches nothing.
- Background processing links to platform events, not to the outbox.
- Queue, Storage and Email link to the Integrations tab, which shows none of
  them.

## Expected Behavior

Each drill-down opens a view of the same signal that produced the tile's state.

## Actual Behavior

- **Authentication:** links to `error-logs?category=AUTH_TOKEN_INVALID`.
  Production has 0 such rows. The tile actually counts `AuditLog`
  `AUTH_LOGIN_FAILED` events and `User.lockedUntil`.
- **Background processing:** links to `/settings/monitoring/events`, which lists
  `PlatformEvent` and has no outbox view.
- **Queue, Storage and Email:** link to `/settings/monitoring/integrations`,
  which shows Stripe and a static email card.

## Reproduction

1. Open Platform admin, Monitoring, Overview.
2. Select the Authentication tile. The error-log list is empty.
3. Select the Storage tile. The Integrations tab shows no storage information.

## Evidence

- `services/api/src/modules/platform-monitoring/platform-health.service.ts`:
  - `:175`: background drill-down.
  - `:218`, `:295`, `:346`: queue, storage and email drill-downs.
  - `:264-265`: authentication drill-down.
- Production, read-only query on 2026-10-07: 0 `ErrorLog` rows with category
  `AUTH_TOKEN_INVALID`.

## Root Cause

The drill-down targets were chosen to existing pages rather than to views of the
measured data.

## Impact

Operators who follow a tile that is red cannot see why. This is a usability
problem, not an exposure.

## Affected Areas

- `services/api/src/modules/platform-monitoring/platform-health.service.ts`
- The admin monitoring pages under `apps/admin/app/(internal)/settings/monitoring/`

## Proposed Resolution

Point Authentication at the platform audit log, filtered to failed sign-ins.
Point Background processing at an outbox view, or at the platform events of the
outbox type. Give Queue, Storage and Email a view that renders the health payload
itself. This is related to [[BUG-3899]].

## Acceptance Criteria

- Each tile's drill-down shows rows or values from the same source the tile
  measures.
- A spec asserts the drill-down target for each tile.
