# BUG-4776 — Agent tray keeps saying monitoring is off after the policy is acknowledged

## Summary

After an employee acknowledged the monitoring policy the desktop agent tray kept reading "Content monitoring: off until you acknowledge the policy" until an unrelated session event redrew it. Monitoring was in fact on for that employee.

## Expected Behavior

The tray reflects the acknowledgement as soon as it is recorded.

## Actual Behavior

The stale label stayed, so the employee was told monitoring was off when it was on, or that they still had to acknowledge.

## Reproduction

1. Publish a monitoring policy in a test database and enable capture. 2. Sign in to the real agent. 3. Choose "Review and acknowledge monitoring policy..." and acknowledge. 4. Read the tray menu.

## Evidence

Found by the real-Electron privacy journey `e2e/electron/agent-dlp-privacy.cjs` (8 of 9 checks passed; the last failed). The tray redraws only on session events; a config refresh is not one.

## Root Cause

`reviewMonitoringPolicy` refreshed the config but never announced a change, and the tray listens only to the session manager.

## Impact

Every employee who acknowledges the policy sees a wrong privacy statement. It matters because the tray is the employee's only standing indicator of what is collected.

## Affected Areas

`apps/agent-desktop/src/main/main.ts`.

## Proposed Resolution

Emit the session "changed" event after the refresh.

## Acceptance Criteria

The tray reads "Content monitoring: ON" without any other event, in a real Electron run.

## Regression Coverage

REG-732: a source-pinning spec in `apps/agent-desktop/src/main/policy-ack-tray.spec.ts` and the real-Electron journey in `e2e/electron/agent-dlp-privacy.cjs`.

## Dependencies
