# BUG-0795 — Saved table preferences hide every column added to a module afterwards

## Summary

Every runtime list persists the operator's table state and reapplies it on load.
The reapplication was verbatim: `visibleColumns` from the saved preference became
the visible set outright, so a column added to the module afterwards was absent
from it and therefore hidden — permanently, silently, and only for the operators
who use the screen enough to have saved anything. `normalizeColumnOrder` then
appended unknown columns to the far right, so a column the definition puts first
arrived last.

## Expected Behavior

A column added to a module becomes visible, at its definition position, to every
operator — while columns an operator deliberately turned off stay off.

## Actual Behavior

Operators with saved table state keep seeing the module as it stood when they
last saved. Newly added columns are hidden with no indication, and the only route
to them is the column picker.

## Reproduction

1. Open any runtime list in Platform Admin and change a column setting, so table
   state is persisted.
2. Add a column to that module's definition and deploy.
3. Reload the list. The new column is absent from the table and unchecked in the
   picker.

## Evidence

- `apps/admin/app/_components/runtime/runtime-module-list.tsx:158-163` — the saved visible set was filtered against the definition, an operation that can only narrow.
- `apps/admin/app/_components/runtime/runtime-module-list.tsx` — the previous `normalizeColumnOrder` kept known columns first and appended everything else.
- Preferences are stored per platform user via `/api/platform-runtime/preferences` with `tableStateJson.version === 2`.

## Root Cause

The saved state was treated as the answer rather than as one input. Nothing
distinguished "this operator hid it" from "this operator has never been offered
it", even though `columnOrder` carries exactly that information — it lists every
column the saved state knew about, hidden ones included.

## Impact

Every module, not just Tenants. Reported as "the tenant list doesn't look
updated", which is precisely what it was: the definition was current and the
screen was not.

## Affected Areas

`apps/admin` runtime list for all eighteen platform modules.

## Proposed Resolution

Use `columnOrder` as the record of what the saved state knew. A definition column
absent from it takes its definition visibility; one present but not visible stays
hidden. Insert new columns at their definition position rather than appending.

## Acceptance Criteria

- A column added after a save is visible, unless it ships hidden by default.
- A column the operator turned off stays off.
- A new first column appears first, not last.
- An older save with no `columnOrder` falls back to definition visibility.
- Re-running the merge on its own output changes nothing.

## Regression Coverage

`apps/admin/lib/runtime/column-preferences.spec.ts` — twelve cases across
`mergeVisibleColumns` and `normalizeColumnOrder`.

## Dependencies

None.

## Resolution

`mergeVisibleColumns` added, `normalizeColumnOrder` rewritten to insert at the
definition position. Both exported for test. Commit `cbc65c5`.
