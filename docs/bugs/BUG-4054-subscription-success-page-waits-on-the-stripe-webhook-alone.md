# BUG-4054 — Subscription success page waits on the Stripe webhook alone

## Summary

After a Stripe payment the public subscription success page depended on the Stripe webhook alone. If the webhook was late or the payment was asynchronous, the customer saw a pending page for a long time and no payment email was sent for public orders.

## Expected Behavior

Returning from Stripe reconciles the checkout session directly, the post-payment chain finishes promptly, asynchronous payment outcomes are handled, and the customer receives a payment email.

## Actual Behavior

settleOrder returned early for Stripe so nothing reconciled on return; the session_id query parameter was dropped; each hop of the post-payment chain waited for a 5 second outbox tick; checkout.session.async_payment_succeeded and async_payment_failed were unhandled; public orders got no payment email.

## Reproduction

1. Pay a subscription order with Stripe on the public flow.
2. Delay or drop the webhook delivery.
3. Observe the success page stay on a pending state and no payment email.

## Evidence

Reproduced and diagnosed during SESSION-0121 (DP platform remediation) against 4489a3c6. The regression tests named in REG coverage pass with the fix; they were not mutation-tested against the pre-fix code.

## Root Cause

services/api/src/modules/billing order settlement skipped a live recheck for Stripe; the landing return route discarded session_id; the outbox worker processed one event per tick with a fixed delay; the payment-confirmed handler did not send email for public orders.

## Impact

Reachable in production through the normal user flow described above.

billing, outbox, apps/landing

Implemented; see Resolution.

## Resolution

Commit 51c80beb: payment-recheck.service reconciles the Stripe checkout session on return (using session_id passed through by the landing page), order-activation and payment-confirmed handler chain directly, the outbox worker drains follow-up events within a tick, async payment events are handled, and the payment email is sent. The landing provisioning view reflects the faster states. MANUAL ACTION REQUIRED: the Stripe webhook endpoint must be subscribed to checkout.session.async_payment_succeeded and checkout.session.async_payment_failed.
