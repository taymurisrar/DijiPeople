# BUG-3809 — A tenant admin can create document types and categories every tenant sees

## Summary

Document types and categories can be global (no tenant), and every tenant reads
global rows alongside its own. The tenant routes that create them —
`POST /documents/types` and `POST /documents/categories` — honoured an
`isGlobal` flag from the request body and wrote the row with no tenant. Any
tenant admin with `documents.types.manage` could therefore publish a type or
category into every other tenant's document settings and upload forms.

## Expected Behavior

A tenant route writes only the caller's tenant's data. Global document types
and categories are platform data; a tenant cannot create or change them.

## Actual Behavior

`isGlobal: true` in the body produced a row with `tenantId = null`, visible to
every tenant.

## Reproduction

1. As a tenant admin of tenant A, `POST /documents/types` with
   `{ "key": "x", "name": "X", "isGlobal": true }`.
2. The response is 201 and the row has no tenant.
3. As a user of tenant B, `GET /documents/types` — the type is listed.

## Evidence

Found while building the document types settings screen in TASK-0036:
`createDocumentType` and `createDocumentCategory` in
`services/api/src/modules/documents/documents.service.ts` wrote
`tenantId: dto.isGlobal ? null : currentUser.tenantId`. The e2e in
`services/api/test/document-types.e2e-spec.ts` reproduced the 201 with the
refusal removed.

## Root Cause

The create DTOs carry `isGlobal` for the platform seeding path, and the tenant
service trusted it from the client instead of deriving ownership from the
authenticated tenant.

## Impact

Cross-tenant write: one tenant can add document types and categories to every
tenant's settings and upload choices (defacement and confusion; no read of
another tenant's documents). Reachable in production by any tenant admin with
the permission. Whether any tenant has already done so in production was not
checked — that needs a read-only production query and the owner's go-ahead.

## Affected Areas

`services/api/src/modules/documents` — the type and category create routes;
the tenant web document settings.

## Proposed Resolution

Refuse `isGlobal` on the tenant routes and always write the caller's tenant.

## Acceptance Criteria

- `isGlobal: true` on either tenant create route answers 403 and writes nothing.
- A tenant cannot edit a global type.
- One tenant's types are not visible to another.

## Regression Coverage

REG-642: `services/api/test/document-types.e2e-spec.ts`. With the refusal
removed, the shared-type case answers 201 (mutation-checked).

## Dependencies

None.

## Resolution

Fixed in 06cdfab5 (TASK-0036). The service refuses `isGlobal` from a tenant
with 403 `DOCUMENT_GLOBAL_FORBIDDEN` and always writes `currentUser.tenantId`.
The new `PATCH /documents/types/:id` refuses global rows and a changed key.
