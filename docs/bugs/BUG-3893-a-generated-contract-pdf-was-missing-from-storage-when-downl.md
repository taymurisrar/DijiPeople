# BUG-3893 — A generated contract PDF was missing from storage when downloaded, suggesting non-durable file storage

## Summary

A platform admin's request to generate a contract PDF failed because the stored
file could not be found. One plausible cause is that generated files are written
to local disk on a host with no persistent disk, so a redeploy deletes them. If
so, every contract PDF and uploaded document stored before the latest deploy is
gone.

## Expected Behavior

A generated contract PDF stays retrievable for as long as the contract exists,
across deploys and restarts.

## Actual Behavior

`POST /api/contracts/:id/generate/pdf` returned `FILE_DOWNLOAD_FAILED` 404,
"The stored file could not be found."

## Reproduction

Not yet reproduced. Suggested check:

1. Generate a contract PDF in a non-production environment that uses the same
   storage provider as production.
2. Redeploy or restart the API.
3. Download the PDF again. A 404 confirms non-durable storage.

## Evidence

- Production `ErrorLog`, read-only query on 2026-10-07: 1 occurrence, admin,
  2026-09-25 22:29, on one tenant.
- The storage provider and its `durable` flag are shown on the Storage health
  tile. That tile was not read during the triage, and neither were the Render
  `STORAGE_PROVIDER` settings.
- The Render API service has no persistent disk.

## Root Cause

Not established. The candidates are:

- A local storage provider on ephemeral disk.
- A storage key recorded before the file was written.
- A file deleted outside the application.

## Impact

If storage is ephemeral: loss of generated contracts and any uploaded documents
for every tenant, which is a data-integrity and legal-record problem. If not: a
single failed regeneration.

## Affected Areas

- `services/api/src/modules/contracts` (PDF generation)
- The shared storage provider used by contracts and documents.

## Proposed Resolution

First establish which provider production uses, and whether it is durable. If it
is local disk, plan a move to durable object storage, with an inventory of the
file rows whose blobs are already missing. This needs an ExecPlan because it
touches stored data.

## Acceptance Criteria

- This record states the production storage provider and whether it is durable.
- A generated contract PDF can be downloaded after a redeploy.
- Rows whose files are missing are counted and handled: regenerated or flagged.
