# BUG-3565 — Opening a contract template or signature request from its admin list returns 404

## Summary

In the admin app, the Contract templates and Signature requests lists load, but opening any record from them fails with 404, because the generic runtime `get()` has no case for either module.

## Expected Behavior

Opening a record from either list shows the record.

## Actual Behavior

`GET /api/platform-runtime/contract-templates/:id` and `/signature-requests/:id` return 404 for an id taken from the module's own list.

## Reproduction

1. As SUPER_ADMIN, `GET /api/platform-runtime/contract-templates` and take an `id`.
2. `GET /api/platform-runtime/contract-templates/<id>` → 404.
3. Same for `signature-requests`.

## Evidence

- WP-08 live CRUD harness, 2026-09-25, finding 2.
- `services/api/src/modules/platform-runtime/platform-runtime.service.ts:357` `get()` has no `contract-templates`/`signature-requests` case and falls to `findGeneric()` (`:1112`), whose fallback only recognises plans, subscriptions and payments. The list path has both cases (`:205`, `:216`).

## Root Cause

The runtime list and get dispatchers were extended separately; the two agreement modules were added to list only.

## Impact

Operators cannot open a template or a signature request record through the generic runtime pages; any drill-down to them 404s.

## Affected Areas

platform-runtime service; admin runtime record pages for the two modules.

## Proposed Resolution

Add explicit `get()` cases delegating to the contracts service readers (which apply the platform permission), and a spec that every module with a list case also has a get case.

## Acceptance Criteria

Both records open from their lists; a spec enumerates list vs get module coverage.

## Regression Coverage

REG-600 (`services/api/src/modules/platform-runtime/runtime-get-coverage.spec.ts`).
Proven to fail against the pre-fix code: with the service change stashed, both
`contract-templates` and `signature-requests` `get()` cases fall through to
`findGeneric` and fail the spec.

## Dependencies

None.

## Related Items

[[BUG-3552]], [[TASK-0032]]

## Resolution

Fixed by commit `0149bef6` (`fix(platform-runtime): open contract templates
and signature requests by id (BUG-3565)`): `PlatformRuntimeService.get()` now
has explicit cases for `contract-templates` and `signature-requests`,
delegating to `ContractsService.getTemplate`/`getSignatureRequest` (which
apply the platform permission), instead of falling through to `findGeneric`.

## QA Retest

Verified by the passing `runtime-get-coverage.spec.ts` and by TASK-0032 WP-09
live QA opening both record types from their admin lists.
