# BUG-3890 — The incident drawer's Diagnostics download calls the tenant endpoint and 404s for platform admins

## Summary

The incident drawer in Platform admin, Monitoring, Error logs has a
**Diagnostics** button that downloads the incident's log. It links to the tenant
endpoint `/api/error-logs/:traceId/download`. That endpoint returns a log only
when it belongs to the caller's own tenant. Platform admins therefore get 404
for almost every incident.

## Expected Behavior

A platform user with `monitoring.read` can download the diagnostics for any
incident shown in the platform queue.

## Actual Behavior

The download returns 404 for platform-scope incidents with no tenant, and for
every incident from another tenant.

## Reproduction

1. Sign in to Platform admin as a user with `monitoring.read`.
2. Open Monitoring, Error logs, then open any incident that has no tenant.
3. Select **Diagnostics**. The response is 404.

## Evidence

- `apps/admin/app/_components/monitoring/error-logs-table.tsx:1068`: the link
  targets `/api/error-logs/${referenceNumber}/download`.
- That path is proxied to the tenant `ErrorLogsController.downloadLog`
  (`services/api/src/modules/error-logs/error-logs.controller.ts:113`).
- `ErrorLogsService.findForUser` (`error-logs.service.ts:236-251`) returns the
  log only when `log.tenantId === user.tenantId` and the caller is tenant
  support or the owner.
- Production `ErrorLog`, read-only query on 2026-10-07: 2,121 of 2,230
  incidents have no tenant. Two 404s on the download were recorded from admin on
  2026-09-24 at 19:30 and 19:31, for a `web_` trace.

## Root Cause

The admin drawer reuses the tenant download route. No platform-scoped download
exists.

## Impact

Platform operators cannot download the diagnostics for nearly every incident.
They have to query the database or read Render logs instead. The download fails
closed, so nothing is exposed.

## Affected Areas

- `apps/admin/app/_components/monitoring/error-logs-table.tsx`
- `services/api/src/modules/platform-monitoring` (the new endpoint)
- `services/api/src/modules/error-logs` (reuse of the log builder)

## Proposed Resolution

Add `GET /platform/logs/events/:traceId/download`, guarded for platform users
with `monitoring.read` and built on the existing log builder. Point the drawer
at it. Leave the tenant route unchanged.

## Acceptance Criteria

- A platform user with `monitoring.read` downloads the diagnostics of a no-tenant
  incident and of a tenant incident.
- A tenant user cannot call the platform route.
- The tenant route keeps its current tenant check.
