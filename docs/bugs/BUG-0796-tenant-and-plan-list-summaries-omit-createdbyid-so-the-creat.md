# BUG-0796 — Tenant and plan list summaries omit createdById so the Created by me view is always empty

## Summary

`PLATFORM_MODULE_VIEW_RULES` filters the "Created by me" view on `createdById`
for both Tenants and Plans. Neither `mapTenantSummary` nor `mapPlan` returned
that field — only the corresponding *detail* mappers did. `readPath` therefore
returned `undefined`, which never equals the operator's platform-user id, so the
tab was empty for everyone, always.

## Expected Behavior

"Created by me" lists the records the signed-in platform operator created.

## Actual Behavior

It lists nothing, on both modules, for every operator.

## Reproduction

1. Sign in to Platform Admin as a platform user who has created a tenant or a plan.
2. Open Tenants (or Plans) and select the "Created by me" tab.
3. Zero rows, with no empty state distinguishing "none" from "broken".

## Evidence

- `packages/config/platform-runtime-views.js` — the rule for `tenants` / `my-records` is `{ label: 'Created by me', field: 'createdById' }`.
- `services/api/src/modules/super-admin/super-admin.service.ts` — `mapTenantSummary` returned id, tenantCode, name, displayName, legalName, slug, status, timestamps, customerAccount, owner, counts, features and subscription, and no `createdById`. `mapPlan` likewise.
- `mapTenantDetail` does return `createdById`, which is why the record page never showed the symptom.

## Root Cause

A view rule and a list payload maintained in different files, with nothing
asserting the field the rule names is one the payload carries.

## Impact

Low. A personal view returns nothing rather than something wrong, and no other
behaviour depends on it. Recorded because it is the same shape as the "Active"
view that once matched a status a module never used — a control that looks
functional and selects nothing.

## Affected Areas

`super-admin` tenant and plan list payloads; the Tenants and Plans list views.

## Proposed Resolution

Return `createdById` from both list mappers.

## Acceptance Criteria

- "Created by me" on Tenants returns the tenants the signed-in operator created.
- The same holds for Plans.

## Regression Coverage

REG-234. Covered structurally by the runtime metadata validation in
`apps/admin/lib/runtime/platform-module-registry.ts`, which resolves every column
and view field against the generated schema.

None.
