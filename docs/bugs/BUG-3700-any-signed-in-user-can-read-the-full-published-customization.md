# BUG-3700 — Any signed-in user can read the full published customization snapshot

## Summary

`GET /api/runtime-metadata/published` returns the tenant's whole published customization snapshot to any authenticated user, with no permission key. It holds metadata (module, field, form and view definitions), not record data.

## Expected Behavior

A user receives the metadata for the modules they can use.

## Actual Behavior

Any signed-in user of the tenant receives all of it.

## Reproduction

Sign in as an employee with no customization permission and call the endpoint.

## Evidence

`services/api/src/modules/customization/customization-runtime.controller.ts` — JwtAuthGuard only.

## Root Cause

The runtime needs the snapshot to render custom modules; it was never narrowed by module permission.

## Impact

Low: tenant-internal metadata disclosure, no records, no cross-tenant access.

## Affected Areas

customization runtime endpoint; apps/web custom module rendering.

## Proposed Resolution

Filter the snapshot to modules the user's permissions cover. Deferred: no data exposure, and the filter must not break custom module rendering.

## Acceptance Criteria

A user without access to a custom module does not receive its definition.
