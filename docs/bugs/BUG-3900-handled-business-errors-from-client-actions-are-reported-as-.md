# BUG-3900 — Handled business errors from client actions are reported as SYSTEM_UNEXPECTED_ERROR 500

## Summary

When a tenant web client action fails with a handled business error, the client
error reporter records it as `SYSTEM_UNEXPECTED_ERROR` with status 500 and
severity `ERROR`. The server actually answered 400 with a business message. These
rows count toward the monitoring "critical" tile.

## Expected Behavior

A reported client-action failure keeps the server's status code and error code.

## Actual Behavior

The status and code are replaced with 500 and `SYSTEM_UNEXPECTED_ERROR`.

## Reproduction

1. On the tenant web app, run an action that the server rejects with a 400
   business error, for example `employees.resetPassword` on an ineligible user.
2. The `ErrorLog` row reads 500 `SYSTEM_UNEXPECTED_ERROR`.

## Evidence

- Production `ErrorLog`, read-only query on 2026-10-07: 2 occurrences, on
  2026-08-29 and 2026-09-12, on one tenant. The `method` values are
  `employees.resetPassword` and `system.save`.

## Root Cause

The action wrappers report a caught error without carrying through the status
and code the server returned. Not yet confirmed in code.

## Impact

The critical tile is slightly inflated, and handled errors are misclassified.
The volume is low.

## Affected Areas

- The `apps/web` client error reporter and the server-action wrappers.

## Proposed Resolution

Carry the server's `statusCode` and `errorCode` into the client report from the
action wrappers.

## Acceptance Criteria

- A 400 business error from an action is recorded as 400, with the server's
  code.
