# BUG-4639 — Payroll journal reversal fails: unique index on payrollRunId was never dropped

## Summary

Reversing a POSTED payroll journal (`POST /payroll/runs/:runId/journal/reverse`) fails with HTTP 500 for the tenant's own administrator. The reversal row violates a unique index on `(tenantId, payrollRunId)` that the schema no longer declares.

## Expected Behavior

A posted journal can be reversed, creating a reversal journal for the same run.

## Actual Behavior

HTTP 500; a unique violation on `PayrollJournalEntry_tenantId_payrollRunId_key`.

## Reproduction

1. Apply every migration to an empty database.
2. Create a payroll run with a POSTED journal.
3. Call `POST /payroll/runs/:runId/journal/reverse` as the tenant admin.

Observed 2026-11-22 by the payroll isolation suite on a database built from migrations. `schema.prisma` declares no such unique, so a database built by `db push` would not show it.

## Evidence

- `services/api/prisma/migrations/20260430040000_payroll_gl_foundation/migration.sql:92` creates `CREATE UNIQUE INDEX "PayrollJournalEntry_tenantId_payrollRunId_key"`.
- `services/api/prisma/migrations/20260712190000_payroll_journal_reversal_documents/migration.sql:10` runs `ALTER TABLE ... DROP CONSTRAINT IF EXISTS` on that name. It was created as an index, not a constraint, so the statement does nothing and the index survives.
- `schema.prisma` `PayrollJournalEntry` has `@@index([tenantId, payrollRunId])` and no unique on that pair.

## Root Cause

A unique INDEX was removed with `DROP CONSTRAINT IF EXISTS`, which silently matches nothing. Schema and migrated databases have diverged.

## Impact

Every migrated database, production included if it applied both migrations, refuses to create the reversal row, so journals cannot be reversed. Not an isolation issue. Production was not queried.

## Affected Areas

payroll: journal reversal.

## Proposed Resolution

A follow-up migration `DROP INDEX IF EXISTS "PayrollJournalEntry_tenantId_payrollRunId_key"`, with a check that production has the index first. Dropping an index is a schema change on a shared database, so it needs an ExecPlan and the owner's go-ahead; it is not applied autonomously.

## Acceptance Criteria

- On a database built only from migrations, reversing a POSTED journal returns 2xx and creates one reversal row.
- `prisma migrate diff` shows no drift on that index.

## Regression Coverage

The payroll suite documents the defect in the owner control for reverse. A real regression test is added with the migration.
