# BUG-3889 — The incident fingerprint includes the query string, so cache-busting parameters open a new incident per request

## Summary

The error log groups repeated failures into one incident by a fingerprint. The
fingerprint hashes the recorded request path, and that path includes the query
string. Any client that adds a cache-busting or variable query parameter
therefore opens a new incident for every request. Occurrence counts, "is this
recurring" links and the incident table are all wrong for those URLs.

## Expected Behavior

Two failures of the same endpoint with the same error code and message group
into one incident, whatever their query string, and the occurrence count rises.

## Actual Behavior

Each distinct query string produces its own incident, each with
`occurrenceCount = 1`.

## Reproduction

1. Request `GET /api/app-releases/feed/agent-desktop/latest.yml?noCache=a`
   without a token, then the same path with `?noCache=b`.
2. Open Platform admin, Monitoring, Error logs.
3. There are two incidents with one occurrence each, not one incident with two.

## Evidence

- `services/api/src/modules/error-logs/error-logs.service.ts:465-489`:
  `incidentFingerprint` hashes `sourceApp|errorCode|method|path|message`.
- `expected-protocol-outcome.ts` notes that `path` carries the query string.
- Production `ErrorLog`, read-only query on 2026-10-07:
  - `/api/app-releases/feed/agent-desktop/latest.yml`: 56 incidents, 56
    distinct paths, 1 distinct base path. Each is one occurrence, caused by
    electron-updater's `noCache` parameter.
  - `/api/agent/updates/latest.yml`: 83 incidents.
  - `/api/public/tenants/resolve`: 18 incidents, split by `?slug=` and `?host=`.
  - `/fetch`: 32 incidents.
  - At least 189 incidents in total, 2026-07-30 to 2026-10-07.

## Root Cause

The fingerprint input uses the full recorded URL rather than the route path.

## Impact

- The incident table is inflated, and real recurrence is hidden.
- `findRelatedOccurrences` cannot link the repeats.
- No data exposure. This affects monitoring accuracy only.

## Affected Areas

- `services/api/src/modules/error-logs/error-logs.service.ts`
- Platform admin, Monitoring: the Overview and Error logs tabs.

## Proposed Resolution

Strip the query string, and optionally normalise id-like path segments, before
computing `incidentFingerprint`. Keep the full path on the occurrence row for
diagnosis. Existing duplicate incidents are not merged retroactively. They can
be bulk-resolved under [[ITEM-0222]].

## Acceptance Criteria

- Two failures that differ only in query string produce one incident with two
  occurrences.
- The occurrence row still records the full path.
- A unit test on `incidentFingerprint` fails if the query string is
  reintroduced.
