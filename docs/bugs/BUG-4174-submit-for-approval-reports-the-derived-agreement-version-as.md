# BUG-4174 — Submit for approval reports the derived agreement version as a missing required field

## Summary

Submitting an agreement drafted from template 55b74891 v3 for approval failed
with "Agreement version is required." The agreement version is derived by the
platform and deliberately not editable, so the operator could not satisfy it.

## Expected Behavior

Approval derives the agreement version exactly as the signing freeze does and
asks only for values an operator can supply.

## Actual Behavior

The approval check validated required placeholders against stored values only;
the derived version is never stored, so it was always reported missing.

## Reproduction

1. Create an agreement from template 55b74891 v3 (its header uses the agreement version placeholder).
2. Fill every required field and press Submit for approval.
3. 400 VALIDATION_FAILED — "Agreement version is required."

## Evidence

Production error log admin_9d964ede (2026-10-12 21:12 UTC), POST
`/api/contracts/:id/submit-approval`, thrown by the placeholder validation
inside the contracts service's approval step. A read-only replay of that
agreement's stored values showed the version as its only missing value.

## Root Cause

The agreement version placeholder was introduced (BUG-4133) as a derived value
added to the document-fields view, the PDF preview and the send freeze, but not
to the approval check — the one remaining caller that validates required values.

## Impact

Every agreement whose document uses the agreement version — today all
agreements from template 55b74891 v3 — could not be submitted for approval.

## Affected Areas

Contracts module, approval submission.

## Proposed Resolution

Validate approval with the derived version, as the send freeze does.
