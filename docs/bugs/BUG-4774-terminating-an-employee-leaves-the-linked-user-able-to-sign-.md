# BUG-4774 — Terminating an employee leaves the linked user able to sign in

## Summary

`EmployeesService.terminate` set `employmentStatus=TERMINATED` and `terminationDate` and wrote an audit row, but did nothing to the linked `User` or its refresh tokens, so a terminated employee kept signing in. Found by the DP-MASTER WP-01 audit (DP-MASTER/WP-08, H02, S01).

## Expected Behavior

Ending employment ends system access: the linked user is disabled and every live session revoked when the termination takes effect; the tenant owner is never disabled.

## Actual Behavior

The user status stayed ACTIVE and refresh tokens stayed valid.

## Reproduction

1. Create an employee with a linked active user. 2. `POST /employees/:id/terminate`. 3. The user still signs in and existing sessions still refresh.

## Evidence

`services/api/src/modules/employees/employees.service.ts` `terminate` (before this change): only `employeesRepository.update` + `auditService.log`; no `user`/`refreshToken` write.

## Proposed Resolution

Immediate and past-dated exits: disable user + revoke sessions in one transaction (done, WP-08.S0). Future-dated exits: scheduled revocation at the effective date (WP-08.S0b, open).

## Acceptance Criteria
