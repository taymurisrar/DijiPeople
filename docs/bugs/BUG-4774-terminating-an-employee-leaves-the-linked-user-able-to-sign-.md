# BUG-4774 — Terminating an employee leaves the linked user able to sign in

## Summary

`EmployeesService.terminate` set `employmentStatus=TERMINATED` and `terminationDate` and wrote an audit row, but did nothing to the linked `User` or its refresh tokens, so a terminated employee kept signing in. Found by the DP-MASTER WP-01 audit (DP-MASTER/WP-08, H02, S01).

## Expected Behavior

Ending employment ends system access: the linked user is disabled and every live session revoked when the termination takes effect; the tenant owner is never disabled.

## Actual Behavior

The user status stayed ACTIVE and refresh tokens stayed valid.

## Reproduction

1. Create an employee with a linked active user. 2. `POST /employees/:id/terminate`. 3. The user still signs in and existing sessions still refresh.

## Evidence

`services/api/src/modules/employees/employees.service.ts` `terminate` (before this change): only `employeesRepository.update` + `auditService.log`; no `user`/`refreshToken` write.

## Root Cause

`terminate` never touched the linked `User` or its refresh tokens.

## Impact

Who is affected, how badly, and whether it is reachable in production.

## Affected Areas

Modules, endpoints, screens and consumers.

## Proposed Resolution

Immediate and past-dated exits: disable user + revoke sessions in one transaction (done, WP-08.S0). Future-dated exits: scheduled revocation at the effective date (WP-08.S0b, open).

## Acceptance Criteria

Immediate exit disables user and revokes sessions; future-dated exit leaves access and records `FUTURE_DATED_REVOCATION_PENDING`; owner untouched; audit snapshot carries `accessRevoked` and a note.

## Regression Coverage

REG-730. `services/api/test/employee-access-revocation.e2e-spec.ts` (11 tests against a real database and the real guard: immediate exit, idempotency, atomic rollback, future date + sweeper, concurrent rehire and reschedule, owner protection, disabled-user token recovery, no starvation). Scenario QA-AUTH-031.

## Resolution

One transaction under an employee row lock: status and date, user DISABLED, web and agent refresh tokens revoked, audit row. A future-dated exit is revoked by `AccessRevocationSweeperWorker` (ON by default, every 60 s); login, refresh and `/auth/me` refuse on the date itself. Branch `agent/dp-master-wp01-baseline`.
