# BUG-3224 — Deleting a document deletes nothing; the bytes stay in storage forever

## Summary

Deleting a document deletes nothing; the bytes stay in storage forever

Identified by the 2026-09-10 full technical audit as FILE-08 (confidence: FILE-08=CONFIRMED).

## Expected Behavior

A real delete (or a documented soft-delete window with a sweeper), so that "delete this passport scan" removes the passport scan.

## Actual Behavior

Archived documents' bytes persist indefinitely with a live, resolvable storageKey. There is no retention policy, no versioning policy and no sweep for Document, DocumentVersion, DocumentReference, EmployeeDocumentReference, DataJob import/export files, contract documents or support-case attachments.

## Reproduction

This is a code-review finding from a static technical audit, not a QA-run runtime reproduction. To confirm: open the file(s) cited in Evidence and trace the call path described in Actual Behavior.

## Evidence

**FILE-08** (services/api/src/modules/documents/documents.service.ts):

```
services/api/src/modules/documents/documents.service.ts:410-431
  async archive(currentUser, documentId) {
    ...
    await this.documentsRepository.archiveDocument(currentUser.tenantId, documentId, currentUser.userId);
```

DELETE /documents/:documentId maps to archive (documents.controller.ts:220-227). StorageService.deleteFile is called from only eight places — DLP retention, release publisher rollback, employee document replace/remove, report-artifact sweep, and tenant erasure — never from the documents module.

## Root Cause

Not established — the audit's analysis (see Evidence) identifies the mechanism but a full root-cause investigation has not been performed. See Actual Behavior for the closest available explanation.

## Impact

A tenant cannot honour a deletion request; storage grows without bound; and because FILE-03 lets a caller name a key directly, an "archived" document is still readable.

## Affected Areas

services/api/src/modules/documents

## Proposed Resolution

Add a documents retention sweeper mirroring report-artifact.service.ts:sweepExpired, and call storage.deleteFile from archive once a grace window elapses.
