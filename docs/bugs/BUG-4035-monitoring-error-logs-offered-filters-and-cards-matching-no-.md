# BUG-4035 — Monitoring error logs offered filters and cards matching no stored value, page-only export, a tenant-only diagnostics download, and Create support case sent the trace id so it always 404ed

## Summary

The Monitoring error-log console offered controls that did nothing useful: cards and filter options for values no row stores (`CRITICAL`, `WEB`, `staging`), an export of only the visible page, a diagnostics download calling a tenant endpoint that refuses platform users, free-text UUID filters, a view selector duplicating the filters — and "Create support case" sent the trace id where the API expects the incident row id, so it returned 404 every time.

## Expected Behavior

Every control on the console works against real captured data; anything without a real implementation is absent.

## Actual Behavior

Several controls filtered to nothing, downloaded partial data, or failed.

## Reproduction

1. Open Platform Admin → Monitoring → Error logs.
2. Choose source WEB or the CRITICAL card: no rows, though web failures exist.
3. Open an incident and choose Create support case: 404.

## Evidence

Stored values queried during the rebuild; `GET /platform/logs/events/facets` now returns the real distinct values.

## Root Cause

Filters were hardcoded rather than derived from data, and the support-case action passed the wrong identifier.

## Impact

Platform operators troubleshooting production failures.

## Affected Areas

`apps/admin/app/_components/monitoring/*`, `services/api/src/modules/platform-monitoring/*`.

## Proposed Resolution

Rebuild the console around real data: facet-driven filters, server-side metrics over the scope, a human-readable detail drawer with server-side re-sanitisation, and the correct incident id for support cases.

## Acceptance Criteria

- Filter options come from `/platform/logs/events/facets`.
- Metrics reflect the selected scope.
- Create support case succeeds.
- No secret or credential appears in the detail drawer.

## Regression Coverage

`services/api/src/modules/platform-monitoring/error-log-query.spec.ts` and `apps/admin/lib/error-log-console.spec.ts` (REG-666).

## Dependencies

None.

## Related Items

[[BUG-4032]].

## Resolution

Monitoring rebuilt; dead controls removed; support case sends the incident row id; tenantless incidents stored with the `platform` sentinel are grouped with "Platform (no tenant)". Branch `agent/admin-ux-cleanup`.

## QA Retest

Browser-verified on an isolated stack against a copy of the dev database (10,316 incidents): filters populated, drawer readable, no console errors. Scenario QA-MON-001.
