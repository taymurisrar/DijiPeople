# BUG-4057 — Account activation reports a password mismatch after autofill and has no reveal toggle

## Summary

On the account activation page a browser-autofilled password reported a mismatch with the confirmation field, and neither field had a show/hide toggle.

## Expected Behavior

Autofilled values are compared as the browser filled them, and each password field has an accessible reveal toggle.

## Actual Behavior

The form reported "Password confirmation does not match." on a mobile browser, and the person had no way to reveal either field to see why.

## Reproduction

1. Open an activation link in a browser with a password manager.
2. Autofill the password and confirmation.
3. Observe the mismatch error.

## Evidence

User report with a mobile screenshot. Diagnosed from code during SESSION-0121 against 4489a3c6. The exact trigger on the reporter's device was not reproduced.

## Root Cause

The check is client-side only: `activate-account-form.tsx` compares two `useState` strings. Both were raw `<input type="password">` elements with no `name` and no `autoComplete`. Without `autoComplete="new-password"`, browsers and password managers may fill a saved or generated password into only one field, or fill it without updating React state. A paste with trailing whitespace into one field mismatches too, and with no reveal toggle none of these can be seen. Which of these happened on the reporter's device is not established.

## Resolution

Commit 51c80beb:

- A shared `PasswordField` (`apps/web/app/components/ui/password-field.tsx`) has a `name`, an `autoComplete` prop and an accessible reveal toggle: a 44 px target, `aria-pressed`, and it never submits.
- Both activation fields use `new-password`.
- Submit compares the values read from FormData, so state lag after autofill cannot produce a false mismatch. The comparison is exact, with a specific message when only edge whitespace differs.
- The match state shows after the confirm field is blurred.
- `GET /auth/invitation-status` is now rate limited and returns the tenant password policy, which the form lists.
- The reset-password form reuses the field.
