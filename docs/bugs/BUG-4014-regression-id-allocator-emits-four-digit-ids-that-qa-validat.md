# BUG-4014 — Regression ID allocator emits four-digit IDs that QA validators truncate

## Summary

`allocate-id.mjs regression` emitted `REG-3546` through `REG-3548`, while the
backlog, QA, remediation and framework validators accept exactly three digits.

## Expected Behavior

The allocator and every consumer agree on the regression identifier format.

## Actual Behavior

The allocator reserves a four-digit identifier that consumers truncate to
`REG-354`, producing duplicate-id and wrong-bug errors.

## Reproduction

1. Run `node scripts/allocate-id.mjs regression --session SESSION-0119` after
   the cross-ref maximum has exceeded 999.
2. Add the returned `REG-3546` to a bug, scenario and regression entry.
3. Run `node scripts/rebuild-backlog.mjs` and `node scripts/rebuild-qa.mjs`.

## Evidence

`scripts/lib/id-allocator.mjs` can allocate the cross-ref maximum, while
`scripts/lib/backlog-records.mjs`, `scripts/lib/qa-records.mjs`,
`scripts/sync-remediation-inventory.mjs` and `scripts/validate-framework.mjs`
match `REG-\d{3}`. The rebuild reported `duplicate regression id REG-354`.

## Root Cause

The allocator uses a growing numeric namespace but four validator paths encode
the historic three-digit width as a maximum instead of a minimum.

## Impact

Engineering records cannot use centrally allocated regression IDs after 999.
This affects framework integrity and release evidence, not production runtime.

## Affected Areas

ID allocator, backlog rebuild, QA rebuild, remediation sync and framework validation.

## Proposed Resolution

Change consumers to accept `REG-\d{3,}` and add an allocator/consumer contract
test. Audit prefix matching so `REG-3546` cannot collide with `REG-354`.

## Acceptance Criteria

- A four-digit allocated regression ID rebuilds without truncation.
- Existing three-digit IDs remain valid.
- Prefix IDs remain distinct in every generated index.

## Regression Coverage

Add a framework test that allocates an ID above 999 and runs both record loaders.

## Dependencies

Deferred from TASK-0037 because changing the framework is outside the partner
release and requires a separate framework session and lease.
