# BUG-3906 — The Payslips screen was offered while the tenant was not entitled to it

## Summary

On 2026-09-24 the tenant web app loaded the Payslips screen. Its API call
`GET /api/payslips` was rejected with `TENANT_FEATURE_NOT_ENTITLED`, because the
tenant's plan did not include payslips. The navigation offered a screen that the
entitlement check then refused.

## Expected Behavior

Navigation hides, or marks as locked, any feature the tenant is not entitled to.
The API stays the authority.

## Actual Behavior

The screen was reachable, and its data call failed with 409/403.

## Reproduction

1. On a tenant whose plan does not include payslips, sign in as a user with the
   payslip permission.
2. Open Payslips from the navigation. The API refuses the call with
   `TENANT_FEATURE_NOT_ENTITLED`.

## Evidence

- Production `ErrorLog`, read-only query on 2026-10-07: 1 occurrence on
  2026-09-24, on one tenant (the demo tenant).
- The demo tenant has since moved to Enterprise, so it no longer reproduces
  there.

## Root Cause

Not established. The candidate is navigation gating on permissions only, without
entitlement, for Payslips.

## Impact

A confusing error for a user on a lower plan. No unauthorised access: the API
refuses the call.

## Affected Areas

- `apps/web` navigation and the payslips module.
- `services/api/src/modules/payslips` (the entitlement guard, which is correct)

## Proposed Resolution

Check whether navigation applies the tenant's entitlements to Payslips, and align
it with the other gated modules.

## Acceptance Criteria

- On a tenant without the payslips entitlement, Payslips is not offered, or is
  shown as locked.
