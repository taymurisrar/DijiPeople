# BUG-3895 — The admin notification bell keeps polling every five minutes after sign-out

## Summary

The notification bell in Platform admin polls
`GET /api/platform/events/notifications` every five minutes and never stops. A
401 counts as a silent failure, and the timer is rescheduled. One admin tab left
open after sign-out produced 155 failed requests in 13 days. [[BUG-2459]] fixed
the same defect in the tenant web app only.

## Expected Behavior

Polling stops when the session ends, which is the first 401, as it does in
`apps/web`.

## Actual Behavior

Polling continues every five minutes for as long as the tab is open.

## Reproduction

1. Sign in to Platform admin and leave a page open.
2. Sign out in another tab, or let the session expire.
3. Watch the network log. Every five minutes there is a 401 on
   `/api/platform/events/notifications`.

## Evidence

- `apps/admin/app/_components/notifications/notification-bell.tsx:94-97`:
  `setTimeout(tick, 5 * 60 * 1000)` is rescheduled unconditionally. `read()`
  treats `!response.ok` as a silent failure.
- Production `ErrorLog`, read-only query on 2026-10-07: 1 incident with 155
  occurrences on the notifications endpoint, plus 9 on `POST /api/auth/activity`,
  from 2026-09-24 to 2026-10-07, with no tenant. All are classified
  `NOT_AN_INCIDENT`.
- Context: session 401s overall are `SESSION_REVOKED` 3,360,
  `AUTH_TOKEN_MISSING` 2,282, `SESSION_EXPIRED` 1,335 and `AUTH_UNAUTHORIZED`
  898, about 280 of them in the last 14 days. Those rows are correctly kept out
  of the queue (triage id MON-12, accepted as noise). This bell, the agent update
  check ([[BUG-3891]]) and possibly [[BUG-3892]] drive most of the volume, and
  fixing them is how it falls.

## Root Cause

The [[BUG-2459]] fix was applied to the web bell and not ported to the admin
bell.

## Impact

Steady 401 noise in monitoring, and needless API load per abandoned tab. No
security impact.

## Affected Areas

- `apps/admin/app/_components/notifications/notification-bell.tsx`
- The admin activity heartbeat (`/auth/activity`).

## Proposed Resolution

Port the web fix: on 401, stop the timer and do not reschedule. Apply the same
rule to the activity heartbeat.

## Acceptance Criteria

- After a 401, the admin bell sends no further requests.
- A component test fails if the timer is rescheduled after a 401.
