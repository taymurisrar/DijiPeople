# BUG-4032 — Admin html/body overflow-x hidden disabled every position:sticky (command bar, agreement editor toolbar and Fields & Signatures panel scroll away)

## Summary

Platform Admin set `overflow-x: hidden` on both `html` and `body`. When both carry a non-visible overflow, `body` becomes a scroll container of its own (its `overflow-y` computes to `auto`) but never scrolls — the window does. Every `position: sticky` element in the console was therefore positioned against a box that never moves, and scrolled away with the page.

## Expected Behavior

Sticky chrome stays put while the page scrolls: the record command bar, the agreement editor toolbar, and the agreement editor's Fields & Signatures panel.

## Actual Behavior

All of them scrolled out of view. On a multi-page agreement the Fields & Signatures panel was unreachable from page two onwards without scrolling back to the top.

## Reproduction

1. Open any contract template in Platform Admin.
2. Scroll the document down.
3. The command bar, editor toolbar and Fields & Signatures panel all leave the viewport.

## Evidence

Computed styles on the template page: `HTML :: hidden/auto`, `BODY :: hidden/auto`. Panel `getBoundingClientRect().top` went from 736 to -536 after scrolling 1273px, despite `position: sticky; top: 163px`.

## Root Cause

`apps/admin/app/globals.css` declared `html, body { overflow-x: hidden }`. Per CSS overflow propagation this makes `body` a scroll container, which captures every sticky descendant.

## Impact

Every admin screen with sticky chrome; most visibly the agreement editor, whose field and signature controls are needed while editing deep in a long document. Production-reachable.

## Affected Areas

`apps/admin/app/globals.css`; record command bar (`module-action-bar.tsx`); agreement editor (`contract-document-editor.tsx`).

## Proposed Resolution

Use `overflow-x: clip`, which prevents horizontal page scroll without creating a scroll container.

## Acceptance Criteria

- Scrolling a long template keeps the command bar, editor toolbar and Fields & Signatures panel visible at 1280x720 and 1366x768.
- At the end of the document the panel shrinks to the space left instead of sliding under the toolbar.

## Regression Coverage

`apps/admin/lib/sticky-scroll-container.spec.ts` (REG-663) fails when either root element is given `overflow-x: hidden` again — mutation-tested.

## Dependencies

None.

## Related Items

[[BUG-4033]] · [[BUG-4034]] · [[BUG-4035]] — found in the same Platform Admin cleanup.

## Resolution

`globals.css` now uses `overflow-x: clip`. The agreement editor additionally caps its sticky rail to the room left before the end of the editor (`--contract-rail-room`), so the panel never slides under the sticky toolbar. Branch `agent/admin-ux-cleanup`.

## QA Retest

Browser-verified on an isolated stack: panel top stayed at 163px at 1366x768 and 1280x720, mid-document and at the end. Scenario QA-ADMINUX-001.
