# BUG-4438 — A recruiter cannot move a candidate between pipeline stages: recruitment.advance is granted to no role

## Summary

`PATCH /api/applications/:id/stage` demands the legacy permission `recruitment.advance`. No system role was ever granted it: the wiring invariant listed it as an admin-only permission, and `matrixPrivilegeToPermissionKey` maps `candidates:write` only to `recruitment.update`. A recruiter could create jobs, candidates, applications and evaluations but received 403 on every stage move, so the core act of the role (Screening -> Interview -> Offer) was impossible for everyone except the elevated-admin bypass.

## Expected Behavior

A recruiter, who holds `candidates:WRITE`, can advance an application through the tenant pipeline and reject it with a reason.

## Actual Behavior

403 `ACCESS_DENIED` on every stage move for the recruiter role. Production `RolePermission` has zero rows for `recruitment.advance` across all five tenants (read-only count, 2026-11-19).

## Reproduction

1. Sign in as a recruiter on a Growth tenant.
2. Create a job opening, a candidate and an application (all succeed).
3. `PATCH /api/applications/:id/stage {"stage":"SCREENING"}` -> 403.

## Evidence

Found by the new Growth workflow suite (e2e/tests/flow-m-growth-hiring-workflows.spec.ts, GM-R3). `services/api/src/common/constants/wiring-invariants.spec.ts` carried `recruitment.advance` in ADMIN_ONLY_PERMISSIONS with no decision recorded. Local and production RolePermission counts: advance = 0 for ceo, hr, manager, recruiter, system-admin.

## Root Cause

A permission was added to the catalog and to the route but never to a role grant; the invariant that should catch that was told to ignore it.

## Impact

Every recruitment-led customer (the ahk. enterprises demo profile) cannot run a hiring pipeline on the Growth plan.

## Affected Areas

recruitment module, roles/permissions bootstrap, Growth plan.

## Proposed Resolution

Grant `recruitment.advance` to recruiter, system-admin and global-admin in `SYSTEM_ROLE_MISC_PERMISSIONS`; remove it from the admin-only allow-list. The permission bootstrap re-syncs existing tenants' roles at API start. Regression: flow M GM-R3/GM-R5.
