# BUG-0534 — Plan form offered editable legacy price fields that bill nobody

## Summary

The plan record form carried a "Legacy pricing compatibility" section with three
editable fields — `currency`, `monthlyBasePrice`, `annualBasePrice` — and its own
description said what a customer is actually charged comes from the checkout
prices below. An editable money field that bills nobody is an invitation to set
a price that does nothing.

## Expected Behavior

The form offers the fields an operator should be setting. What a customer pays
is configured through `PlanPrice`, and the form should say so by not offering an
alternative.

## Actual Behavior

Three editable money fields, labelled "Legacy", positioned above the prices that
actually charge. Setting them has no effect on any customer, and nothing said so
at the moment of typing.

## Reproduction

1. Open a plan in Platform Admin, Pricing tab.
2. Set "Legacy flat monthly price" to any value and save.
3. Start a checkout for that plan.

The customer is charged the `PlanPrice` amount. The saved value is read by
nothing.

## Evidence

`apps/admin/lib/runtime/platform-module-registry.ts` at `99dc70a` — the
`legacy-pricing` section and its four field declarations.

The columns are documented as deprecated in `schema.prisma`: *"nothing may read
them to decide what a customer pays"*. `plan-change.service.ts:290` says the
same. This is [[BUG-0027]] read forwards: that bug was the money path reading
these columns, and the fix removed the read while leaving the invitation to
write.

## Root Cause

Removing the four declarations was not enough, and made it briefly worse.
`completeFormsFromSchema` adds every readable, non-sensitive, non-list,
non-relation column a form does not mention, so the deleted fields reappeared
under "Additional details" — stripped of the labels and descriptions that
explained them, and with `legacyPricingMigratedAt` newly writable.

The default is the right one: an undeclared field is more likely forgotten than
deliberately hidden. What was missing was a way to say "deliberately hidden".

## Impact

An operator could set a number believing it priced something. No customer was
mischarged — the money path stopped reading these columns at [[BUG-0027]].

## Affected Areas

`apps/admin` platform module registry, plan record form.

## Proposed Resolution

An explicit exclusion list honoured by `completeFormsFromSchema`. The columns
stay on the model: existing rows carry values, and dropping them is a
destructive migration with its own backfill question.

## Acceptance Criteria

- None of `currency`, `monthlyBasePrice`, `annualBasePrice`,
  `legacyPricingMigratedAt` appears on the plan form or in its list columns.
- Asserted against the **completed** form, not the declared one.
- No field writable that `UpdatePlanDto` does not accept.

## Regression Coverage

REG-202. `plan-record-form.spec.ts` — "does not offer the legacy price columns
checkout ignores" asserts absence from `detail.fields` after
`completeFormsFromSchema` has run, which is the only assertion that could have
caught the reappearance.

## Resolution

Fixed on `agent/plans-reset`. `FORM_EXCLUDED_FIELDS` in
`platform-module-registry.ts`, declared above `definitions` — that array is
evaluated at module scope, so a constant below it sits in its temporal dead zone
and every import of the file throws. This registry has now been broken that way
three times, and the constant carries the reason.
