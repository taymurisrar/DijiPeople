# BUG-4005 — Reason-prompted record commands (Suspend, Deactivate, Reject, lead Disqualify, contract stage-back) silently do nothing

## Summary

Every admin record command that asks for a reason did nothing when clicked. No prompt opened, no request was sent and no message appeared. This covers Suspend, Deactivate and Reject on partners, Disqualify on leads, and stage-back on contracts.

## Expected Behavior

Clicking the command opens the reason prompt. Confirming it runs the action and shows the result.

## Actual Behavior

`ModuleActionBar.execute` ran each command inside `startTransition(async () => …)`. React 19 holds back every state update made inside an async transition until the action resolves. A reason-prompted command awaits `useReasonPrompt`, and that prompt only appears through a state update. The two waited on each other, so nothing ever happened.

## Reproduction

1. Open an ACTIVE partner.
2. Choose More → Suspend.
3. Nothing happens. The partner stays ACTIVE, and the network tab shows no request.

## Evidence

TASK-0037 browser pass, 2026-10-08. After clicking, no dialog element appeared and no request was sent. The bug dates from when the file was created, because `startTransition(async` has been in `module-action-bar.tsx` since its first commit. It is therefore present in production.

## Root Cause

A React 19 async transition was used to show a busy state around actions that wait for user input.

## Impact

Operators could not suspend, deactivate or reject partners, disqualify leads, or send contracts back a stage from the record page.

## Affected Areas

Every runtime record page in apps/admin.

## Proposed Resolution

Run commands as a plain async task. The bar's `pendingKey` already provides the busy state.

## Acceptance Criteria

- Suspend opens the reason prompt.
- After confirming, the partner is SUSPENDED and the account is SUSPENDED.
- Reactivate returns the partner to ACTIVE.
- The command bar contains no transition wrapper.

## Regression Coverage

REG-657: `apps/admin/lib/runtime/action-bar-no-transition.spec.ts`.

## Dependencies

None.

## Related Items

[[BUG-3956]] added the reason prompts on partners.

## Resolution

Removed `useTransition` and `startTransition` from the command bar. Commands now run as `void (async () => …)()`, and the busy state comes from `pendingKey`.
