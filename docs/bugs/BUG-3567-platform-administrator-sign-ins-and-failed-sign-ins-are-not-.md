# BUG-3567 — Platform administrator sign-ins and failed sign-ins are not audited

## Summary

Tenant sign-ins write `AUTH_LOGIN_SUCCEEDED`/`AUTH_LOGIN_FAILED` audit events, but platform administrator sign-ins write none, successful or failed. There is no record of who signed in to the platform admin console or of password guessing against it.

## Expected Behavior

Every platform sign-in attempt, success or failure, writes a platform audit event with the MFA outcome and failure reason, never the attempted password.

## Actual Behavior

`AuthService.adminLogin` / `validatePlatformAdminCredentials` call no audit write.

## Reproduction

1. Sign in to the admin app with a wrong password, then the right one.
2. No PlatformAuditLog row is written for either.

## Evidence

- WP-07 report (TASK-0032-streams/t0032-wp-07-report.md, UNRESOLVED): no source exists for platform login activity.
- `services/api/src/modules/auth/auth.service.ts` `logTenantAuthEvent` is only called from tenant paths.

## Root Cause

Login auditing was implemented for tenant users only.

## Impact

The most privileged accounts are the least observable; brute force against the admin console leaves no audit trace (compounds BUG-3146).

## Affected Areas

auth module (platform login and MFA verify); operations dashboard sign-in metrics.

## Proposed Resolution

Audit platform sign-in success and failure through `AuditService` with `tenantId: 'platform'`. Assigned to TASK-0032 WP-03.

## Acceptance Criteria

Success and failure each write one platform audit row with actor (when known), result, failure reason and mfaResult.

## Regression Coverage

REG-543 (`services/api/src/modules/auth/platform-login-audit.spec.ts`).
Proven to fail against the pre-fix code by mutation: making
`logPlatformAuthEvent` return early fails 4 of the spec's 5 tests.

## Resolution

Fixed on `agent/pah-wp03-mfa` (TASK-0032 WP-03, commits `d19e62b6` for
failures and lock, `d67e7821` for success and MFA, `f8336e65` for the unknown-
address case and its spec, merged as `f5b4b9d1`): `logPlatformAuthEvent` now
writes `AUTH_LOGIN_SUCCEEDED` (actor, MFA result, session id, forwarded
IP/user agent) and `AUTH_LOGIN_FAILED` (wrong password, locked account,
unknown address, wrong MFA code — each with its `failureReason`) with
`tenantId: 'platform'`, using the same snapshot shape tenant sign-in rows
already use, and no row ever contains the attempted password.
