# BUG-4120 — A published plan could not be unpublished or archived, so the delete rule pointed at an action that did not exist

## Summary

The owner could not delete the production plan Enterprise+ and could not
unpublish it. The plan was inactive and never sold (no prices, subscriptions,
orders or references) but still PUBLISHED. The delete rule from BUG-4098
refuses a published plan and told the operator to "deactivate or archive it
first" — and nothing in Platform Admin could change a plan's publication:
the form shows it read-only and the governed actions (ITEM-0022) were never
built.

## Expected Behavior

A super admin can publish, unpublish and archive a plan through explicit,
audited actions, and then delete an unpublished, inactive, never-sold plan.

## Actual Behavior

No publication action existed; `UpdatePlanDto` does not accept
`publicationStatus`. A published plan stayed published and undeletable.

## Reproduction

1. Open Plans → Enterprise+ (published, inactive, custom-only, no prices).
2. Delete: refused, "Deactivate or archive it first".
3. There is no Archive or Unpublish command.

## Evidence

Read-only production query, 2026-10-12: `enterprise-plus`, isActive false,
publicationStatus PUBLISHED, salesModel CUSTOM_ONLY, 0 prices, 0
subscriptions, 0 orders, 0 plan changes, 0 references.

## Root Cause

BUG-4098 made deletion depend on a publication transition whose
implementation was still a backlog item, and nothing checked that the
refusal's advice was actionable.

## Impact

Any published plan could never be withdrawn from sale or removed from
Platform Admin. Reachable in production.

## Affected Areas

Plans record page; `/platform-runtime/plans/:id/actions/{publish,unpublish,archive}`.
Also the shared record action bar, whose confirmation said "permanently
deletes" for every destructive action, not only Delete.

## Proposed Resolution

Governed plan publication actions per EXECPLAN-0034, plus Unpublish.

## Acceptance Criteria

- Publish (DRAFT → PUBLISHED), Unpublish (PUBLISHED → DRAFT) and Archive
  (DRAFT/PUBLISHED → ARCHIVED) exist, are confirmed, audited
  (PLAN_PUBLISHED / PLAN_UNPUBLISHED / PLAN_ARCHIVED) and need the platform
  admin tier.
- Archived → Published is refused; publishing an inactive plan, or a priced
  sales model with no published price, is refused with the reason.
- An unpublished, inactive, never-sold plan can then be deleted.
- A non-delete confirmation states what that action does.

## Regression Coverage

REG-680 — `plan-publication.spec.ts`, `record-action-dispatch.spec.ts`,
`record-action-routing.spec.ts`.

## Resolution

Branch `agent/plan-publication-actions`: `PlanPublicationService` with a pure
transition rule, dispatched from `PlatformRuntimeService.execute` behind
module write and admin tier; Publish / Unpublish / Archive on the plan record,
shown by `publicationStatus`; the action bar now confirms any action that
declares a confirmTitle and uses that action's own wording, keeping the delete
wording for Delete only. Price-level publish/archive and price versioning from
EXECPLAN-0034 remain open under ITEM-0022.
