# BUG-3668 — Saving agreement document fields skips the shared immutability check

## Summary

`PATCH /contracts/:id/document-fields` (`ContractsService.saveDocumentFields`)
never called `assertAgreementEditable`, the shared rule every other agreement
edit uses. After execution it still returned 400, but only incidentally: the
frozen signing version has no editable placeholder left, so the call failed
with "No editable document fields were supplied."

## Expected Behavior

Field values on a sent, signed or executed agreement are refused by the same
immutability rule as every other edit, with the same message.

## Actual Behavior

The refusal depended on the frozen content. A version that still carried an
editable placeholder after sending would have been writable.

## Reproduction

1. Execute an agreement.
2. `PATCH /contracts/:id/document-fields` with any value.
3. Response: 400 "No editable document fields were supplied." — not the
   immutability refusal.

## Evidence

Found by the ITEM-0200 e2e suite (`services/api/test/contracts-agreements.e2e-spec.ts`),
which asserts the 400 and that the stored value is unchanged, and deliberately
does not pin the incidental message.

## Root Cause

`saveDocumentFields` validated keys against the current version's
placeholders but never checked the agreement's status (BUG-0011 is the same
class: one rule, one path that did not consult it).

## Impact

Low: no known version shape exposes it today. It removes a latent route
around the executed-agreement guarantee.

## Affected Areas

`services/api/src/modules/contracts/contracts.service.ts` (`saveDocumentFields`).

## Proposed Resolution

Call `assertAgreementEditable(contract.status)` before reading the fields.

## Acceptance Criteria

Saving a field on an executed agreement is refused by the immutability rule
and writes nothing; a draft still saves.

## Regression Coverage

REG-634 — `contracts.agreement-immutability.spec.ts` ("saveDocumentFields follows
the same immutability rule"), which fails without the guard.

## Dependencies

None.

## Resolution

Fixed on `agent/backlog-0200-e2e`: `saveDocumentFields` calls
`assertAgreementEditable` before anything else touches the fields.
