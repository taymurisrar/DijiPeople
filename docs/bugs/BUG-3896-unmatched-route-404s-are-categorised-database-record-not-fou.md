# BUG-3896 — Unmatched-route 404s are categorised DATABASE_RECORD_NOT_FOUND in the incident queue

## Summary

The API exception filter assigns `DATABASE_RECORD_NOT_FOUND` to every 404 that
has no explicit error code. That includes Nest's "Cannot GET /x" for routes that
do not exist. Scanner probes and route misses therefore appear in monitoring as
database errors, and filtering the queue by the database category returns mostly
noise.

## Expected Behavior

A request to a route that does not exist is categorised with a route-level code,
for example `ROUTE_NOT_FOUND`. `DATABASE_RECORD_NOT_FOUND` is reserved for a
missing record.

## Actual Behavior

Both cases are recorded as `DATABASE_RECORD_NOT_FOUND`.

## Reproduction

1. Request `GET /api/does-not-exist` against the API.
2. The error-log row and the response carry `errorCode: DATABASE_RECORD_NOT_FOUND`.

## Evidence

- `services/api/src/common/filters/http-exception.filter.ts:328-332`: the code
  ends with `if (statusCode === 404) return 'DATABASE_RECORD_NOT_FOUND'`.
- Production `ErrorLog`, read-only query on 2026-10-07: 4,834 occurrences
  categorised this way between 2026-07-29 and 2026-10-07. Of these, 1,789
  `NOT_AN_INCIDENT` incidents are scanner probes or route misses, all with no
  tenant.
- Context, accepted as noise under triage id MON-28: scanner traffic (`/.env*`,
  `/.git/config`, `*.php`, `wp-*`, `/fetch`, `/proxy`, `/api.zip`) is about
  4,800 occurrences, about 550 of them in the last 14 days. All of it returns
  404 and nothing is exposed, but each probe still writes rows. See
  [[BUG-3188]] on write amplification.

## Root Cause

The status-code fallback in the filter maps a bare 404 to a database code.

## Impact

Monitoring categories are misleading, and real missing-record errors are hard to
find. The response shape is unchanged, so there is no client impact beyond the
code string.

## Affected Areas

- `services/api/src/common/filters/http-exception.filter.ts`
- `services/api/src/common/errors/error-catalog.ts` (new code)
- Platform admin, Monitoring category filters.

## Proposed Resolution

Detect Nest's unmatched-route `NotFoundException` and map it to a new
`ROUTE_NOT_FOUND` catalog entry. Optionally, stop persisting unmatched-route
404s, which would also address the scanner volume.

## Acceptance Criteria

- An unmatched route yields `ROUTE_NOT_FOUND`.
- A service-thrown not-found without a code still yields
  `DATABASE_RECORD_NOT_FOUND`.
- A filter spec covers both cases.
