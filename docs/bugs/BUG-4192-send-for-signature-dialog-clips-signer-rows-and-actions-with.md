# BUG-4192 — Send-for-signature dialog clips signer rows and actions with more than two signers

## Summary

The admin "Send for e-signature" dialog grew with every signer row inside a
fixed, centred overlay with no height limit, so with three or more signers
its title and its Send button were pushed off screen with no way to scroll to
them. Each row also started with the party's name as the signer name, so an
organisation was recorded as the person who signed.

## Expected Behavior

The dialog is bounded by the viewport, scrolls internally, keeps its title and
actions visible, works at phone width, closes on Escape and focuses the first
field. A row starts with the agreement's named signatory where one exists.

## Actual Behavior

Clipped panel; recipients named "DijiPeople" and "DijiPeople Demo Company" on
`CON-20261012-E7421CC1` (production, read-only).

## Reproduction

1. Open an agreement with three signatory parties in Platform Admin.
2. Send for signature: the panel exceeds the viewport.

## Evidence

`apps/admin/app/_components/runtime/runtime-record-page.tsx`, the
signature-request dialog: `fixed inset-0 grid place-items-center` wrapping a
panel with no max height; recipient name initialised from the party's name.

## Root Cause

No max height or internal scroll on the panel; name prefilled from the party.

## Impact

Platform operators sending multi-party agreements. Production.

## Affected Areas

Platform Admin agreement record page.

## Proposed Resolution

Flex column panel bounded by the dynamic viewport height, scrolling body,
pinned header and footer; prefill from document fields.

## Acceptance Criteria

At 390×700 and 1280×720 with four signer rows: body scrolls, header top and
footer bottom inside the viewport, no horizontal page scroll.

## Regression Coverage

Layout verified by browser measurement (no admin component test harness
covers this dialog); REG-683.

## Dependencies

None.
