# BUG-4006 — Expected domain refusals on record actions open the technical error dialog because the adapter drops request headers

## Summary

When a business rule refuses a record action, the refusal opened the blocking global error dialog, complete with Technical details and Download log. This happened even though the action bar already showed the same message in red. An example is PARTNER_INVITATION_COOLDOWN (429) on Send onboarding link. The dialog made an expected business rule look like a system failure.

## Expected Behavior

Expected domain refusals (4xx with a catalog code) appear inline where the operator is working. Unexpected server failures (5xx) still raise the dialog, so the log can be downloaded.

## Actual Behavior

- The fetch interceptor raised the dialog for every failed `/api/` request unless it was marked as background.
- The runtime adapter merged headers with an object spread. Spreading a `Headers` instance yields `{}`, so a mark passed as `Headers` was silently dropped.

## Reproduction

Send an onboarding link twice within 60 seconds. The global error dialog opens over the inline notice.

## Evidence

TASK-0037 browser pass screenshots, taken before and after the fix.

## Root Cause

The admin app had no way to say "this caller reports the outcome itself" while still surfacing 5xx errors. Separately, the adapter's header merge lost any header passed as a `Headers` instance.

## Impact

A cosmetic problem, but it alarms operators and wraps normal outcomes in technical detail.

## Affected Areas

Admin record actions, quick-create panels and subgrid row commands.

## Proposed Resolution

Add a "reported" request mark. The dialog is suppressed only for 4xx responses on reported requests. Merge headers through `Headers`.

## Acceptance Criteria

- A reported 4xx shows no dialog.
- A reported 5xx still shows the dialog.
- Background requests are unchanged.
- The adapter keeps the mark and the JSON content type.

## Regression Coverage

## Resolution

- Added `reportedRequestInit` and `isReportedRequest`.
- `shouldRaiseErrorDialog` now takes `reported` and `status`.
- The runtime adapter (`executeRecordAction`), quick create and row commands send the reported mark.
- The adapter now merges headers through `Headers`.
