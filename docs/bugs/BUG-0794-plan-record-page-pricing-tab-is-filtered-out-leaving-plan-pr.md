# BUG-0794 — Plan record page Pricing tab is filtered out, leaving plan price configuration unreachable

## Summary

`RuntimeRecordPage` keeps a tab only if it has form fields, a related-records
panel, a timeline, or an explicit `hasRuntimePanel` allowance. `planForms()`
declares a `pricing` tab and assigns no fields to it, and no relationship targets
it — so the tab was filtered out of the bar while `PlanPriceManager` stayed
mounted behind `activeTab === "pricing"`, a value nothing could select.

The only remaining route to plan price configuration was
`/plans/<id>?workspace=legacy-commerce`, a query parameter nothing links to.

## Expected Behavior

The Plan record page shows a Pricing tab containing `PlanPriceManager`, where the
per-currency, per-cycle prices checkout charges are configured.

## Actual Behavior

No Pricing tab appears. The panel exists in the bundle and never renders.

## Reproduction

1. Open any plan in Platform Admin at `/plans/<id>`.
2. Read the tab bar: Overview, Entitlements, Publication, Subscriptions, Customers, Stripe, System.
3. There is no Pricing tab, and no other screen exposes `PlanPrice` rows.

## Evidence

- `apps/admin/app/_components/runtime/runtime-record-page.tsx:207-233` — the tab filter; `hasRuntimePanel` named `entitlements` for plans and not `pricing`.
- `apps/admin/app/_components/runtime/runtime-record-page.tsx:594` — the `PlanPriceManager` block, guarded on `activeTab === "pricing"`.
- `apps/admin/lib/runtime/platform-module-registry.ts` — `planForms()` lists `{ key: "pricing", label: "Pricing" }` in `tabs` and assigns zero fields to it.
- `apps/admin/app/(internal)/plans/[planId]/page.tsx:47` — the legacy screen is reachable only when `workspace === "legacy-commerce"`.

Present at production commit `35f263c`, so this shipped.

## Root Cause

A tab carrying only a bespoke panel is invisible to the filter, which measures
fields and relationships. The allowance list exists precisely for that case, and
`pricing` was omitted from it — the comment beside `entitlements` records the
identical defect being fixed for that tab and not generalised.

## Impact

Platform operators cannot configure the amounts checkout charges from the Plan
module. Reachable in production; the workaround is an undocumented query
parameter.

## Affected Areas

`apps/admin` plans record page; any future module mounting a panel on a
field-less tab.

## Proposed Resolution

Add `pricing` to the allowance, and derive the rule in a test so the next
omission fails in CI rather than in a browser.

## Acceptance Criteria

- The Pricing tab renders on a plan record page and shows `PlanPriceManager`.
- Every `activeTab` panel guard in the file lands on a reachable tab.

## Regression Coverage

`apps/admin/lib/runtime/runtime-record-panels.spec.ts` — parses the panel guards
out of `runtime-record-page.tsx` and asserts each is reachable. Mutation-tested:
restoring the single-tab allowance fails two cases.

## Dependencies

None.

`runtime-record-panels.spec.ts` derives the rule from the file. Commit
