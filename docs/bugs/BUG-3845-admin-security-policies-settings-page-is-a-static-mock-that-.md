# BUG-3845 — Admin Security policies settings page is a static mock that saves nothing

## Summary

Platform admin → Settings → Security → "Security policies"
(`/settings/security`) renders values such as a 15-minute session timeout and
a 7-day refresh token. It also shows toggles such as "Allow super admin
impersonation". None of these read or write anything. An operator who changes
a toggle believes they changed platform policy, and they have not.

## Expected Behavior

The page shows the platform's real authentication and access settings, and
saves them, or it does not exist.

## Actual Behavior

- The values are string literals.
- The toggles use `defaultChecked` and have no handler.
- The file contains no `fetch`, no API call and no submit.

## Reproduction

1. Open admin → Settings → Security → Security policies.
2. Flip "Allow super admin impersonation" and reload. The toggle reverts. No
   request was made.

## Evidence

`apps/admin/app/(internal)/settings/security/page.tsx` at `9714f85b`:

- lines 24-27 hold the `Field` values;
- lines 36-39 hold the `Toggle` elements;
- a grep for `fetch`, `onSubmit`, `onChange` and `apiRequest` returns 0 matches.

## Root Cause

A design placeholder that was never wired to an API. Several of the values it
shows are environment configuration, not stored settings. Whether any of them
should be editable at runtime is undecided.

## Impact

Platform operators, and nobody else. It misleads operators but grants and
removes nothing. The page was found while tracing [[BUG-3844]]: it was the place
an operator looking for MFA landed.

## Affected Areas

`apps/admin` → `/settings/security`.

## Proposed Resolution

This needs a product decision:

- Either make it a read-only view of the effective platform auth configuration.
- Or back it with real platform settings. That includes the deferred "require
  MFA for operators" policy (ADR-0021).
- Or remove the tile and the page.

## Acceptance Criteria

No control on the page claims a state it does not hold.

## Regression Coverage

None yet. It will be added with the fix.
