# BUG-3844 — Two-factor authentication cannot be found in the tenant web app or the platform admin app

## Summary

TOTP MFA has been live since TASK-0032 (ADR-0019) for both tenant users and
platform operators. The product owner could not find where to set it up in
either app. The feature works, but no route led to it.

## Expected Behavior

A user looking for two-factor authentication finds it from the places people
look: the account menu, and in admin also Settings → Security.

## Actual Behavior

- **Web.** The only enrolment card was the last element of My Profile, below
  the whole employee runtime form. Nothing linked to it. The account menu
  offered only My Profile and Sign out.
- **Admin.** Operator enrolment is on `/security`, which only the avatar menu
  linked to. Settings → Security listed "Security policies", a static page with
  no MFA on it (BUG-3845), and nothing else.
- **Tenant-wide policy.** "Require two-factor authentication" is under Settings
  → Security & Access → Password & Login Policies → Login Rules. A settings
  search for "two-factor" or "2fa" did not match it.

## Reproduction

1. Web: open the avatar menu. There is no Security or two-factor entry. Open My
   Profile; nothing about MFA is visible without scrolling past the employee
   form.
2. Admin: open Settings → Security. Neither tile leads to MFA.

## Evidence

- `apps/web/app/(authenticated)/my-profile/page.tsx` at `9714f85b`, lines 68
  and 154: `<MfaSettingsCard />` after `EmployeeRuntimeFormWrapper`.
- `apps/web/app/(authenticated)/_components/user-menu-dropdown.tsx` at
  `9714f85b`: a single My Profile link.
- `apps/admin/app/(internal)/settings/page.tsx` at `9714f85b`: the Security
  group has "Users & access" and "Security policies" only.
- `docs/architecture/mfa.md`, "Frontend surfaces", lists the same locations.

## Root Cause

TASK-0032 placed each surface where it belonged technically: the card on the
account the user owns, and the operator page beside password and sessions. It
added no entry point a person would look for.

## Impact

All tenant users and platform operators. Nobody could enrol in MFA unless they
already knew where the card was, which also undermines a tenant that turns on
"Require two-factor authentication".

## Affected Areas

The web account menu and My Profile; admin Settings; the web settings search.

## Proposed Resolution

Add a Security entry to the web account menu that deep-links to the card's
anchor on My Profile. Add a Two-factor authentication tile to admin Settings →
Security that opens `/security`. Add two-factor search keywords to the tenant
policy item.

## Acceptance Criteria

- Web: avatar menu → Security lands on the MFA card on My Profile, with or
  without a linked employee record.
- Admin: Settings → Security → Two-factor authentication opens `/security`.
- Web settings search for "two-factor" or "2fa" finds Password & Login
  Policies.

## Regression Coverage

## Dependencies

None.

## Related Items

[[BUG-3845]] is the admin Security policies page, which is a static mock.

## Resolution

- Web: added a Security link in the account menu to
  `/my-profile#security`. Both My Profile branches render the card inside the
  `security` anchor.
- Web: added the search keywords "two-factor", "2fa" and "authenticator".
- Admin: added a "Two-factor authentication" tile to Settings → Security.

There is still no platform-wide "require MFA for operators" policy. That is the
owner decision recorded in ADR-0021, not this defect.

Branch `agent/crm-plugin-alm-mfa-claims`.
