# BUG-3703 — Package export readiness could never report a missing dependency

## Summary

The Packages screen ran an export-readiness check before downloading, meant to name anything the package needed but did not carry. `getPackageComponents` returned `dependencies: []` for every component, so the check had nothing to compare and always reported ready.

## Expected Behavior

A package that needs a component it does not carry is flagged before it leaves.

## Actual Behavior

Before the fix: never flagged.

## Reproduction

Export a package whose field lives on a module owned by another package: readiness reported no gaps.

## Evidence

`services/api/src/modules/customization/customization.service.ts` `getPackageComponents` — `dependencies: []`.

## Root Cause

Dependencies were never computed for this path.

## Impact

Incomplete packages exported without warning.

## Affected Areas

Packages list export; export-readiness endpoint.

## Proposed Resolution

Done: superseded by release validation, which computes real dependencies (UNDECLARED_DEPENDENCY, UNPACKAGED_DEPENDENCY, MISSING_COMPONENT), and export now serves released versions only. The web banner that relied on the old check was removed.

## Acceptance Criteria

Releasing a package that needs an undeclared package's component is refused with the remedy.
