# BUG-0496 — The monitoring landing page showed real data an agent could not act on

## Summary

The monitoring landing page rendered four counters over the platform event
stream, a list of event codes by source, and ten recent events. Every figure was
real and none of it was actionable — while the endpoint that answers "which
customer is broken right now" was already built and never called from this page.

## Expected Behavior

The page a support agent opens when something is wrong tells them what needs a
person and lets them start on it.

## Actual Behavior

"Events (24h): 4,182", "Succeeded", "Pending", "Failed events". No incident, no
customer, no reference, nothing clickable, and no filter or sort of any kind.

## Reproduction

Open `/settings/monitoring` and try to find out which incidents are unassigned.

## Evidence

- `apps/admin/app/(internal)/settings/monitoring/page.tsx` — one call to
  `/platform/events/overview`.
- `services/api/src/modules/platform-monitoring` — `/platform/logs/events`
  returns items, metrics (`total`, `critical`, `open`, `resolved`) and accepts
  fifteen filters plus sorting. The page did not call it.

## Root Cause

The page was built from the data nearest to hand rather than from the question
its reader has. An event stream describes the platform's activity; a support
agent needs the platform's *failures*, attributed to customers, in priority
order — which is a different table entirely.

## Impact

Every support agent, on the screen they open when a customer reports a problem.

## Affected Areas

`apps/admin` — the monitoring overview.

## Proposed Resolution

Three bands, each answering one question in the order an agent asks it: is
anything on fire (four counts, each a link that applies its own filter); what
should I pick up (the recent queue, filterable and sortable in place, carrying
its filters into the full queue); is the platform itself healthy (the event
failure rate and its sources, reduced to the part that carries information).

The success count stops being a tile: nobody triages a success, it is the
denominator, and it now reads as one.

## Acceptance Criteria

- Every headline figure is a link that applies its own filter.
- Filters and sorting are available on the page.
- Filters carry across to the full queue.
- The page states that it shows a slice.
- No placeholder or static content.
