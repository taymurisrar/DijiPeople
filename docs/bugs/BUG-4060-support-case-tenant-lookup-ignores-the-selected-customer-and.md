# BUG-4060 — Support case Tenant lookup ignores the selected Customer and the API accepts mismatched pairs

## Summary

On a support case the Tenant lookup did not narrow to the selected Customer, and the API accepted a customer and tenant pair that did not belong together.

## Expected Behavior

The Tenant lookup lists only tenants of the selected Customer, and the API rejects a mismatched customer/tenant pair.

## Actual Behavior

Any tenant could be chosen for any customer and the pair was stored.

## Reproduction

1. Create a support case, choose Customer A.
2. Choose a tenant belonging to Customer B.
3. Observe the case saved with the mismatched pair; the same via the API.

## Evidence

Reproduced and diagnosed during SESSION-0121 (DP platform remediation) against 4489a3c6. The regression tests named in REG coverage pass with the fix; they were not mutation-tested against the pre-fix code.

## Root Cause

The admin lookup carried no customer filter, and support-cases create/update validated each id independently without checking that the tenant belongs to the customer (a cross-record integrity and cross-customer data exposure gap).

## Impact

Reachable in production through the normal user flow described above.

## Affected Areas

support-cases, apps/admin

## Proposed Resolution

Implemented; see Resolution.

## Acceptance Criteria

The expected behaviour above holds and the regression test passes.

## Regression Coverage

## Resolution

Commit 51c80beb: the lookup is filtered by customer, and the support-cases domain validates the pair on create and update; covered by the domain spec and the dp-remediation workflows e2e suite.
