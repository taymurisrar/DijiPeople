# BUG-3894 — The tenant error boundary shows the React digest as the error reference, which support cannot find and Download log 404s on

## Summary

When a tenant page crashes, the error boundary shows an "Error reference" for the
customer to give to support. That reference is React's `error.digest`. The error
log row it records uses a different id, `client_boundary_<hash>`. Support
therefore cannot find the reference in monitoring, and the boundary's
**Download log** button, which sends the digest as the trace id, gets 404 and
falls back to a local file.

## Expected Behavior

The reference shown to the user is the trace id of the persisted error-log row.
Searching monitoring for it finds the incident, and Download log returns it.

## Actual Behavior

The digest is shown and used for the download. The row is stored under
`client_boundary_...`, and the download 404s.

## Reproduction

1. Trigger a server-component failure on a tenant page. Before BUG-3883 was
   fixed, My Profile for an MFA-enrolled user did this.
2. Note the "Error reference" on the boundary.
3. Search Platform admin, Monitoring, Error logs for it. Nothing matches.
4. Select Download log. The request `GET /api/error-logs/<digest>/download`
   returns 404.

## Evidence

- `apps/web/app/(authenticated)/error.tsx:62`: `errorReference = error.digest ?? ...`.
- `error.tsx:63-65, 80`: the persisted trace id is
  `client_boundary_${stableErrorReference(...)}`.
- `error.tsx:199-201`: Download log passes the digest as `traceId`.
- Production `ErrorLog`, read-only query on 2026-10-07: one
  `GET /api/error-logs/<digest>/download` 404 at 10:08, on one tenant, in the
  same minute as the BUG-3883 crash.

## Root Cause

[[BUG-2013]] added the digest as a reference without aligning it with the id the
client reporter persists.

## Impact

Every customer-reported crash reference is unfindable by support, and Download
log never works from the boundary. This is a support-workflow failure. Nothing
is exposed.

## Affected Areas

- `apps/web/app/(authenticated)/error.tsx`
- Platform admin, Monitoring search.

## Proposed Resolution

Show and download by `clientTraceId`. Keep the digest in the row's details so a
server-side lookup is still possible.

## Acceptance Criteria

- The reference shown on the boundary matches the `traceId` of the persisted
  row.
- Download log from the boundary returns the log.
- A test asserts that the displayed reference equals the reported trace id.
