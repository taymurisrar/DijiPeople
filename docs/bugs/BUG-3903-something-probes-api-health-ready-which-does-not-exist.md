# BUG-3903 — Something probes /api/health/ready, which does not exist

## Summary

Something probes `GET /api/health/ready` on the production API and gets 404. The
API exposes only `GET /api/health`. Either a monitor or the host is configured
with a readiness path that does not exist, or a readiness route is missing.

## Expected Behavior

Every configured health probe targets a route that exists and reports
readiness.

## Actual Behavior

The probe returns 404 and writes an error-log row.

## Reproduction

1. `GET /api/health/ready` against the API.
2. The response is 404.

## Evidence

- Production `ErrorLog`, read-only query on 2026-10-07: 2 occurrences, on
  2026-09-25 and 2026-09-26, with no tenant.
- `services/api/src` exposes `@Get('health')` only.
- The source of the probe was not identified.

## Root Cause

Not established. Either a prober is misconfigured or a readiness endpoint is
missing.

## Impact

If a platform health check uses this path, it would always fail. Otherwise the
probe adds noise only.

## Affected Areas

- The API health endpoint.
- The Render or external monitor configuration.

## Proposed Resolution

Find the prober from the request's user agent and source. Then either point it at
`/api/health`, or add a readiness route as part of [[BUG-3198]], which makes the
health endpoint report real state.

## Acceptance Criteria

- No 404s on a health path from a configured monitor.
- If a readiness route is added, it reflects database reachability.
