# BUG-3701 — Platform-scope customization packages are not unique by key

## Summary

`CustomizationSolution.tenantId` is nullable and the package key is unique on `(tenantId, solutionKey)`. PostgreSQL treats NULLs as distinct, so two platform-scope packages (tenantId null) can share a key.

## Expected Behavior

A package key is unique within its scope.

## Actual Behavior

Platform-scope rows are not constrained.

## Reproduction

Insert two CustomizationSolution rows with tenantId null and the same solutionKey: both succeed.

## Evidence

`services/api/prisma/schema.prisma` model CustomizationSolution, `@@unique([tenantId, solutionKey])`.

## Root Cause

Nullable column in a composite unique.

## Impact

Latent: no code creates platform-scope packages today.

## Affected Areas

customization schema.

## Proposed Resolution

A partial unique index on solutionKey where tenantId is null, when platform-scope packages are introduced.

## Acceptance Criteria

A second platform-scope package with an existing key is refused.
