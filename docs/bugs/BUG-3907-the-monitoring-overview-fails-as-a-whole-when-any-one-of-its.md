# BUG-3907 — The monitoring overview fails as a whole when any one of its three endpoints fails

## Summary

The Monitoring overview page loads three endpoints with `Promise.all`:

- platform health
- the incident slice
- the 24-hour event overview

There is no per-panel fallback, so if any one of them fails, the whole page falls
into `error.tsx`. The screen operators use during an outage is the most likely
one to go blank during an outage.

## Expected Behavior

Each panel loads independently and shows its own error state. The other panels
still render.

## Actual Behavior

One failed request blanks the whole overview.

## Reproduction

1. Make `GET /platform/events/overview` fail, for example by blocking it in the
   browser or with a local fault.
2. Open Platform admin, Monitoring. The page shows the route error boundary
   instead of the health tiles and incidents.

## Evidence

- `apps/admin/app/(internal)/settings/monitoring/page.tsx:42-56`: `Promise.all`
  across the three calls.
- Not seen in production data. This is found by code reading.

## Root Cause

The three calls are fetched together with all-or-nothing semantics.

## Impact

Monitoring is lost exactly when one backing subsystem is degraded.

## Affected Areas

- `apps/admin/app/(internal)/settings/monitoring/page.tsx`
- `apps/admin/app/_components/monitoring/monitoring-overview.tsx`

## Proposed Resolution

Use `Promise.allSettled`, and pass each panel its result or a per-panel error
state.

## Acceptance Criteria

- With one endpoint failing, the other two panels render, and the failing panel
  shows an error state.
