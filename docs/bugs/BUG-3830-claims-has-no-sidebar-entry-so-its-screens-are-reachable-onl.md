# BUG-3830 — Claims has no sidebar entry, so its screens are reachable only by URL

## Summary

The tenant app has working Claims pages — the list and detail, and since
TASK-0036 the create/edit screens with line items, both admin (`/claims`) and
self-service (`/me/claims`) — but the sidebar catalog never had an entry for
them. Nobody could find them without typing the URL, so the owner, looking at
production after the TASK-0036 release, saw no change.

## Expected Behavior

A user who can read claims reaches them from the sidebar: the full list for
those who read all claims, their own claims for everyone else who may.

## Actual Behavior

No sidebar entry for claims, for any role.

## Reproduction

1. Sign in to production as the demo tenant owner.
2. The sidebar lists Overview … Onboarding, QA Assets, Settings — no Claims.
3. `/claims` typed directly opens a working page with a New claim button.

## Evidence

Production screenshot on 2026-09-27 after the TASK-0036 release: the sidebar
has no Claims entry while `/claims` renders. `dashboardNavItems` in
`apps/web/app/(authenticated)/_components/navigation.ts` had no `/claims` item,
and no other page linked to `/claims` or `/me/claims`.

## Root Cause

The claims pages were built without being registered in the sidebar catalog.

## Impact

Every tenant: claims could not be raised or reviewed through the UI without
knowing the URL. No data or security impact.

## Affected Areas

`apps/web` sidebar; the claims module's screens.

## Proposed Resolution

Add a Claims catalog entry that adapts to the user's scope.

## Acceptance Criteria

- `claims.read-all` holders and tenant administrators see Claims → `/claims`.
- `claims.read-own` holders and self-service users see My Claims → `/me/claims`.
- Users with neither see nothing.

## Regression Coverage

REG-643: `apps/web/app/(authenticated)/_components/navigation.spec.ts`.

## Dependencies

None.

## Related Items

[[TASK-0036-custom-fields-screens-for-api-only-modules-sort-and-filter-b]] shipped the create/edit screens this entry makes reachable.

## Resolution

A `/claims` entry in `dashboardNavItems` with a new optional `ownScope`
(href, label, permissions): the full list for `claims.read-all`, My Claims for
`claims.read-own` and self-service. Not plan-gated (no feature key sells
claims). Branch `agent/claims-navigation`.

## QA Retest

QA-SETTINGS-037 — navigation spec PASS (5 cases). Production, 2026-09-27, after release PR #92 (`cea41518`): the sidebar shows Claims between Reports & Analytics and Payroll, and it opens `/claims`.
