### One gate failed first and is worth recording

CI's **Lint** went red on `5933b60e`. Cause: the four workspaces were linted
before the three-fix commit, then the headcount work was added and pushed
without re-linting — two prettier errors. Fixed in `77abf947`.

The note in memory already said "lint after the *last* edit"; being right about
it did not prevent it. The correction is to run generators, lint, stage and
validate as a single block with no edits after it, rather than as a habit
applied by judgement.

### S4, the one that mattered

The same schedule that failed at 06:00 with `Missing email template variables:
tenantName.` ran at 09:00:20 and completed:

```
lastRunStatus            COMPLETED     (was FAILED)
lastFailureReason        null
consecutiveFailureCount  0             (reset)
nextRunAt                2026-09-01T09:00:00.000Z
```

With a single recipient, `COMPLETED` requires that recipient to have been sent —
`deliver()` throws when `sent === 0`. Whether the message arrived in the
recipient’s inbox is the one link in the chain this agent cannot observe.

### S5, stated rather than claimed

`BUG-2623` only fires for a caller at SELF, USER or TEAM access level who
belongs to at least one team. The only production account available here is the
tenant owner, who resolves to TENANT and therefore never takes that code path.
Verifying it in production would mean creating a scoped user and a team on a
live tenant, which is a larger and more invasive act than the fix.

A data-management export of the `employees` module was run in production as a smoke check and completed with 12 rows — that is the exact call site, so it proves the change caused no regression on the path that *is* reachable. It does not exercise the defect, because the account used resolves to TENANT.

It is covered by `rbac-query-scope.spec.ts` — seven cases, four of which fail
against the previous default — and by the full API suite passing with the
shared helper changed. That is the honest limit of what was checked here.
