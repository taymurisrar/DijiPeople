# ITEM-0247 — Custom conflict codes (WORK_BLOCKER_*, DAILY_UPDATE_*) reach clients as DATABASE_CONSTRAINT_FAILED because they are not in the error catalog

## Summary

The exception filter maps a thrown {code,message} to a catalogue ErrorCode and falls back to status-based codes for anything not in the catalogue, so every 409 with a module-specific code (for example WORK_BLOCKER_MAX_ESCALATION, DAILY_UPDATE_CHANGED) is rendered as DATABASE_CONSTRAINT_FAILED. The messages reach the user correctly; only the machine-readable code is lost. Found by the browser journeys.

## Why It Matters

Clients cannot branch on the specific conflict. The fix is catalogue entries (or letting the filter pass a well-formed module code through); it touches every module that throws custom codes, so it is deferred as its own change.
