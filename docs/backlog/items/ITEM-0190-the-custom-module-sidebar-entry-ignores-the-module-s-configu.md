# ITEM-0190 — The custom-module sidebar entry ignores the module's configured icon

## Summary

A published custom module's sidebar entry always uses the generic fallback icon
(`Briefcase`). The module's own `CustomizationTable.icon` is not mapped, so every
custom module looks the same in the sidebar.

## Why It Matters

Several custom modules side by side are distinguishable only by label. Minor,
but visible on every page of a tenant that uses custom modules.

## Evidence

- `apps/web/lib/runtime/custom-modules/custom-module-navigation.ts` builds the
  entry with the fallback icon.
- `docs/tasks/TASK-0031-streams/WP-02-report.md`, "Residual risks and open
  items": "Sidebar icon is the generic fallback (`Briefcase`);
  `CustomizationTable.icon` is not mapped."

## Proposed Approach

Return the module's icon in `GET /metadata/custom-modules` and map it onto the
sidebar's existing icon set, falling back to the current icon for an unknown
value. No ExecPlan needed.

## Acceptance Criteria

- A custom module with a configured icon shows that icon in the sidebar and in
  the Sidebar Designer.
- An unknown or empty icon shows the current fallback.
