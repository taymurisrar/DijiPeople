# ITEM-0205 — Before promoting TASK-0032: review agreements signed with a fabricated date and partners that fail the new type policy

## Summary

Two data checks the owner must run against production before (or when)
TASK-0032 is promoted to `main` — neither could be run from a throwaway
database.

1. **Agreements signed with a fabricated date.** Before BUG-3581, sending an
   agreement whose template had a signature-date line required typing a date
   into the document fields, and that date was frozen into the signed version.
   Executed agreements from that period keep it — by design, since signed
   versions are immutable — so they print a date nobody signed on.
2. **Partners that fail the new type policy.** BUG-3549/BUG-3550 made
   partner create and update enforce type-required fields (a COMPANY needs a
   company name, an INDIVIDUAL a first and last name) and duplicate checks on
   email, tax id and company name. An existing partner that violates either
   will be refused on its next edit until its data is corrected.

## Why It Matters

(1) is a legal-document accuracy question for real, signed agreements. (2)
turns into an operator unable to save a partner, with no warning beforehand.

## Evidence

- BUG-3581 and TASK-0032 WP-11 report, UNRESOLVED
  (`docs/tasks/TASK-0032-streams/t0032-wp-11-report.md`).
- TASK-0032 WP-04 report, RISK_AREAS #1 and UNRESOLVED
  (`docs/tasks/TASK-0032-streams/t0032-wp-04-report.md`).

## Proposed Approach

Read-only production queries: executed agreements whose frozen version carried
a stored manual `signature.*.date` value; partners with a missing type-required
field; partners sharing a normalised email, tax id or company name. Decide per
agreement whether to amend or annotate; correct or merge partner data before
operators meet the refusal.

## Acceptance Criteria

- Both query results are recorded with a decision for each affected record.
- No production partner fails the type policy or duplicate check at promotion.

## Dependencies

Owner access to production (read-only). Nothing in this item changes data
without the owner.

[[BUG-3581]], [[BUG-3549]], [[BUG-3550]], [[TASK-0032]], [[partners]], [[contracts-and-agreements]]

## Resolution

Run read-only against production on 2026-09-26, before the release merge
(owner-approved; `SET default_transaction_read_only = on`):

- Executed agreements: 4 `FULLY_EXECUTED`, 5 `DRAFT`. Every stored
  `signature.*` value (one agreement, five keys) has `source: signature` —
  written by the signing flow, none entered by hand. No agreement carries a
  fabricated signature date.
- Partners: 2 (both COMPANY). None misses a type-required field; no duplicate
  email, normalised tax id or company name.

Nothing needed correcting. TASK-0032 was released at `b586ac0a` (PR #81).
