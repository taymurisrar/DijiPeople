# ITEM-0110 — Attendance entry appears to create Timesheet drafts on a tenant without the Timesheets entitlement

## Summary

A draft Timesheet appeared on the demo tenant immediately after 60 manual
attendance entries were created, and nothing in the run created a timesheet
explicitly. Timesheets is **not** part of the Starter entitlement this tenant is
on. If attendance entry does auto-generate timesheet drafts, then a module the
customer has not bought is accruing records — which may be entirely intended, and
may be exactly how the two modules are designed to interoperate. The trigger was
not established, so this is recorded as a question, not a finding.

## Why It Matters

Two things hinge on the answer, and neither is urgent.

If the generation is intended, the packaging question is real but small: an
unentitled module holding records is untidy rather than harmful, and it becomes
moot the moment entitlement enforcement lands (BUG-1952) and someone has to
decide what an existing tenant with data in an unentitled module sees.

If it is *not* intended, then something is writing timesheet rows nobody asked
for, and that is worth knowing before the volume grows.

Either way the first step is investigation, not work — which is why this is
deferred rather than ready.

## Evidence

Observed 2026-08-29 on `https://dijipeople-demo.ws.dijipeople.com`, tenant
`DijiPeople Demo` (Starter plan; Timesheets **not** entitled), against production
API `949f461c`.

The dashboard's Recent changes list showed:

```
TYPE Timesheet   LABEL DRAFT   DATE 2026-08-29T00:37:42.741Z
```

logged immediately after 60 manual attendance entries were created for six
employees across ten working days (2026-08-16 to 27, Fridays and Saturdays
excluded). No timesheet was created explicitly at any point in the run.

**What is not established:** that attendance entry is the trigger. The
correlation is in time only. No code path was traced, and no controlled probe
(create one attendance entry, check for a timesheet) was run. Treat the causal
claim as unverified.

The raw enum label and unformatted timestamp visible in the quoted row are
separate defects — BUG-2009 and BUG-2010.

## Proposed Approach

1. Run the controlled probe first: create a single manual attendance entry on a
   tenant with no timesheets and check whether a draft appears. That is minutes
   of work and settles whether there is anything here at all.
2. If it reproduces, find the generation path in
   `services/api/src/modules/attendance` or `time-payroll` and establish whether
   it is deliberate.
3. Then decide the packaging question: should a tenant without the Timesheets
   entitlement accrue timesheet records? The answer should be made once, as part
   of the entitlement enforcement design in BUG-1952, rather than as a local
   special case here.

## Acceptance Criteria

- Whether attendance entry generates timesheet drafts is established, one way or
  the other, and written down.
- If it does, the intended behaviour for an unentitled tenant is decided and
  recorded — as part of BUG-1952's enforcement design if that has landed.
- If it does not, this record is closed as not reproducible and the actual source
  of the draft timesheet is named.

## Dependencies

BUG-1952 owns the general question of what an unentitled module may do. This
record should not invent a separate answer.
