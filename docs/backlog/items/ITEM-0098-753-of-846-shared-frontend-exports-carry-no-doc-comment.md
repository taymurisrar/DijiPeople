# ITEM-0098 — 753 of 846 shared frontend exports carry no doc-comment

## Summary

`scripts/generate-component-index.mjs` harvests the shared frontend kits into
`.agent/context/component-index.md` from the doc-comments above their exports.
It found 93 documented exports out of 846 across `apps/admin/app/_components`,
`apps/admin/lib/runtime`, `apps/web/app/components`, `apps/web/lib/runtime` and
`packages/ui/src`. The other 753 contribute a name and nothing else, so the
generator omits them rather than padding the index with identifiers.

This is not a defect in the generator. It is a measurement of how much of the
shared UI carries stated rationale, taken for the first time.

## Why It Matters

The index is what a UI/UX or Frontend agent retrieves before changing a screen.
An export that is absent from it is an export whose behaviour an agent will
infer from its name and its implementation — which is exactly the reading that
produces "the component looks correct" conclusions about screens that do not
work, the failure `.agent/agents/ui-ux.md` Stage 2 exists to prevent.

The cost is not uniform, which is why this is P2 and not P1: the exports that
matter most are disproportionately the ones already documented. `ProDataTable`,
`ModuleActionBar`, `RecordStatusGroup` and the tenant panels all carry
rationale. The tail is largely small presentational pieces where the name
genuinely is the documentation.

## Evidence

```
$ node scripts/generate-component-index.mjs
Wrote .agent/context/component-index.md — 93 documented export(s), 753 undocumented omitted.
```

Per kit, at `2d609724`:

| Kit | Documented | Undocumented |
|---|---|---|
| `apps/admin` | 57 | 240 |
| `apps/web` | 36 | 510 |
| `packages/ui` | 0 | 3 |

`apps/web` is the weaker of the two despite being the larger kit, and
`lib/runtime` is the bulk of it — the metadata-driven registries that
`AGENTS.md` names as the default way to build a tenant module.

`ModuleActionBar` was itself undocumented until this task added the comment;
that is how the gap was noticed. It is the most-imported component in the admin
runtime kit (8 importers) and the one the command bar's whole contract runs
through.

## Proposed Approach

No ExecPlan needed. This is incremental and should stay incremental:

- **Document on touch.** Any task that changes one of these exports adds the
  doc-comment as part of the change. The Reviewer can see the index diff.
- **Do not bulk-author.** A sweep that writes 753 comments in one pass produces
  restatements of the function signature, which is worse than silence: it makes
  the index look complete while carrying no information.
- If a deliberate pass is wanted, take `apps/web/lib/runtime` first and only the
  exports with more than three importers.

## Acceptance Criteria

- The documented ratio reported by `generate-component-index.mjs` rises without
  any entry whose summary merely restates its own name or signature.
- No entry is added to the index by hand — the generator remains the only
  writer of `.agent/context/component-index.md`.
