# ITEM-0210 — Decide when PKR checkout moves to Safepay and what happens to existing PKR Stripe subscribers

## Summary

PKR routes to Safepay only when `SAFEPAY_ENABLED=true`; it ships `false`, so PKR stays on Stripe exactly as today. Existing PKR Stripe subscriptions keep renewing through Stripe after the switch — only new checkouts move.

## Why It Matters

Production already sells PKR through Stripe. Switching is a commercial decision (fees, settlement account, which customers move) and must not happen as a deploy side effect.

## Evidence

`resolvePaymentProvider` in `services/api/src/modules/billing/providers/payment-provider.resolver.ts`; `render.yaml` `SAFEPAY_ENABLED: "false"`.

## Proposed Approach

Owner decides the cut-over date and whether existing PKR Stripe subscribers are migrated at renewal or left on Stripe. Migration of existing subscribers would need its own ExecPlan.

## Acceptance Criteria

- A recorded decision (ADR) on cut-over and existing subscribers.
- `SAFEPAY_ENABLED` set accordingly in each environment.
