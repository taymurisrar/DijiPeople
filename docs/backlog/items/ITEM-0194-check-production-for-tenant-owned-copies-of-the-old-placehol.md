# ITEM-0194 — Check production for tenant-owned copies of the old placeholder email templates after release

## Summary

[[BUG-3500]] replaced the placeholder bodies of the system email templates with
authored copy. A tenant that cloned one of those templates before the fix owns a
copy of the placeholder, and that copy may be ACTIVE. Per ADR-0015 the seed never
changes tenant-owned rows: `verifySystemEmailTemplates` only warns. Once sink
providers are retired, such a copy would send placeholder text to real inboxes
for that tenant.

## Why It Matters

This is the go-live defect BUG-3500 was filed for, surviving in any tenant that
had cloned a template. It cannot be fixed by the seed without overwriting a
tenant's own data, so it needs a production check and an owner decision per row.

## Evidence

- `services/api/prisma/seed-config.ts` — `verifySystemEmailTemplates` warns, and
  changes nothing, for tenant-owned rows with placeholder wording.
- `docs/tasks/TASK-0031-streams/WP-04-report.md`, "Residual risks and
  follow-ups": "Existing tenant clones of placeholders."
- The orchestrator ledger for TASK-0031 records this as a production check.

## Proposed Approach

Run a read-only query on production for `EmailTemplate` rows with a tenant owner
whose HTML or text body contains the placeholder sentence, grouped by tenant and
status. Report every row found to the owner, who decides per row (archive,
replace with the new default, or leave). No automatic change.

## Acceptance Criteria

- The production query has been run and its result (count per tenant and status,
  no content) is recorded on this item.
- Zero rows: the item is closed as DONE.
- Rows found: the owner's decision is recorded and applied, and no ACTIVE
  tenant-owned template contains placeholder wording.

## Dependencies

None remaining.

## Related Items

[[BUG-3500]] placeholder template copy. [[BUG-3501]] sink provider retirement.
Decision: ADR-0015.

## Resolution

Done: the TASK-0031 coordinator ran the read-only production check on 2026-09-13
and found 0 tenant-owned ACTIVE email templates containing placeholder copy, so
no owner decision is needed and nothing was changed.

The check ran before the TASK-0031 release rather than after it. That does not
weaken the result: the release does not create tenant-owned templates (the seed
only writes system rows and archives legacy per-tenant auth rows), and a tenant
Customize made after the release copies the new authored copy, not the
placeholder.
