# ITEM-0082 — Contract phase: drop the inert Plan.isPublic column

## Summary

[[BUG-0223]] removed every read of `Plan.isPublic`; publication is now the only
gate on whether a plan can be bought. The column is still in `schema.prisma`,
reading `true` for all three production plans and nothing reads it.

## Why It Matters

Low, and deliberately so. An inert column is not dangerous — it is a
misleading one. The next person to read the schema sees a boolean that looks
like a gate, and the failure mode is somebody wiring it back up in good faith,
which is exactly what REG-225 now refuses.

## Proposed Approach

Expand/backfill/contract, per `PLANS.md`. Expand and backfill are already done —
`publicationStatus` exists, is populated, and is authoritative. What remains is
the contract phase alone:

1. Confirm no read has returned, with `REG-225` and a repository grep.
2. Drop the column in its own migration, in a release that carries no other
   schema change.
3. Remove it from `seed-config` and `commercial-bootstrap.ts`, which still
   write it.

## Acceptance Criteria

- `Plan.isPublic` is gone from `schema.prisma` and from every seed.
- The API response field `isPublic` still exists and is still derived from
  publication — it is a public contract the landing site consumes, and this item
  must not remove it.

## Dependencies

Deferred until a release that is otherwise free of schema changes. There is no
urgency and a dropped column cannot be rolled back without a restore.

columns, and the two should ship together.
