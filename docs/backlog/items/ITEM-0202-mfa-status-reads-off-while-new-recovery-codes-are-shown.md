# ITEM-0202 — MFA status reads Off while new recovery codes are shown

## Summary

Immediately after a tenant or platform user completed MFA setup and was shown
their ten new recovery codes, both the web and admin security screens still
read the user's MFA status as "Off" rather than "On" — the status readout had
not caught up with the enrolment that had, in fact, just completed.

## Why It Matters

Right after enrolling, a user looking for confirmation that MFA actually took
effect saw the opposite of what just happened — an unsettling, trust-eroding
moment for a security feature specifically, even though the enrolment itself
was correct and durable (this is a read/display defect, not an enrolment
defect).

## Evidence

`docs/tasks/TASK-0032-streams/QA-summary.md` — "MFA status read Off while new
recovery codes were shown (web and admin) | LOW | Fixed". Found during
TASK-0032 WP-09 live QA of the MFA enrolment journey (ITEM-0197) on both
`apps/web` (My Profile) and `apps/admin` (`/security`).

## Proposed Approach

Fix the security screen's status readout so it reflects MFA as enabled as soon
as setup is confirmed, consistent with the recovery codes already being shown
as the enrolment's completion step. No ExecPlan needed — a display-state fix
on both frontends, no schema or contract change.

## Acceptance Criteria

- Immediately after confirming MFA setup and viewing the ten recovery codes,
  the security screen's MFA status reads "On" on both `apps/web` and
  `apps/admin`.

## Dependencies

None — built on the MFA feature ([[ITEM-0197]]) this task introduced.

## Resolution

Fixed by commit `38065748` (`fix(web,admin): MFA status reads On while the new

read the MFA status as enabled as soon as setup is confirmed.
