# ITEM-0246 — Regression id allocator is inflated by validate-framework probes and cannot hand out 3-digit REG ids

## Summary

The reservation ledger (`<git-common-dir>/dijipeople/id-reservations.json`) holds ~dozens of `REG-42xx` rows written by `validate-framework` "allocation probe" runs, so `allocate-id regression` returns REG-4276 or higher while the register (`docs/qa/regressions/index.md`) is at REG-730 with 3-digit ids. Ids above 999 are rejected downstream (REG-4276 was read as REG-427 and failed QA validation).

## Why It Matters

Anyone who follows the allocator ends up hand-picking the next register number, which is the collision the allocator exists to prevent. BUG-4774 / REG-730 was numbered by hand for this reason and is not in the ledger.

## Evidence

ledger rows of kind "regression" with note "validate-framework allocation probe"; `scripts/lib/id-allocator.mjs` `regression.width: 3`; DP-MASTER session 2026-11-25.

## Proposed Approach

Run the probe against a throwaway ledger (or release the probe reservations), cap regression ids to the register width, and record REG-730 in the ledger. Small; no ExecPlan.

## Acceptance Criteria

`allocate-id regression` returns the next free 3-digit id; a validate-framework run leaves the ledger unchanged.
