# ITEM-0248 — No seeded role holds both customization.packages.manage and work-profiles.manage, so adding work components to a package works only for elevated roles

## Summary

Adding work components to a package needs customization.packages.manage and work-profiles.manage (units/profiles) or work-queues.manage (queues). No seeded role holds both pairs: the CEO has the first, HR the second. Elevated roles (global/system admin) are unaffected. The refusal shows correctly in the dialog.

## Why It Matters

Decide which role owns work-component packaging (a customizer with work permissions, or HR with package permission) before the first customer package is shipped; no right was widened here.

Operational readers and managers keep their employees-based access unchanged.
