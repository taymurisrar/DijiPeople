# ITEM-0250 — Work routes have no plan entitlement gate; no work-management feature key exists

## Summary

`/work-items`, `/work-duties`, `/work-decisions`, `/work-meetings`, `/work-blockers` and `/work-queues` carry no `@RequireEntitlement`, no `EntitlementGuard` entry, and no work-management feature key exists in `tenant-features.ts` (only `/projects` is gated, key `projects`). Under ENFORCE a tenant whose plan sells none of this is still served on every work route.

## Why It Matters

Whether work management is core (every plan) or a sellable feature is a pricing and entitlement decision, which belongs to the owner. Until it is made, plan toggling cannot be tested for these routes and nothing stops a plan from receiving the feature unpaid.

## Evidence

`services/api/test/entitlement-enforce.e2e-spec.ts` pins the current ungated behaviour on purpose (adding a gate fails that test deliberately). Measured 2026-11-28.

## Proposed Approach

Owner decides: core on all plans (record it and keep the test), or a new feature key gating the routes and the package component types, with seed-config plan features and the pricing page updated together.

## Acceptance Criteria

- The decision is recorded as an ADR.
- If gated: the key exists, every work route enforces it, plan and override toggling are tested, and seed-config and plans agree.
