# ITEM-0214 — Flipping SAFEPAY_ENABLED while a PKR Stripe checkout is open can let one order be paid twice

## Summary

If `SAFEPAY_ENABLED` is switched on while a public PKR order already holds an open Stripe checkout session, a resubmission gives the same order a Safepay checkout too; paying both would confirm one and leave the second payment unmatched.

## Why It Matters

A double charge in a narrow window around the cut-over. The Safepay side would surface as `BILLING_PAYMENT_UNMATCHED`; the Stripe side would not.

## Evidence

`createPublicSubscriptionCheckout` in `services/api/src/modules/billing/services/billing.service.ts`; `ManagedCheckoutService.startOrderCheckout`.

## Proposed Approach

When an order already has a Stripe session, keep it on Stripe regardless of the flag; or expire open Stripe sessions at cut-over.

## Acceptance Criteria

- An order never holds open checkouts at two providers.
