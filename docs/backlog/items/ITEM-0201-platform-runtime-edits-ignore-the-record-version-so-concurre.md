# ITEM-0201 — Platform runtime edits ignore the record version, so concurrent edits silently overwrite each other

## Summary

The admin runtime adapter sends a `version` with every update, but `PlatformRuntimeService.update` never compares it with the stored record, so two operators editing the same record concurrently overwrite each other without a conflict.

## Why It Matters

Lost updates on commercial records (customers, contracts, leads) are silent. The owner's brief asks for stale-update handling where the architecture supports it.

## Evidence

WP-08 live CRUD harness, 2026-09-25, finding 5: a stale-version PATCH succeeded on five modules; no call site in `update()` reads `body.version`.

## Proposed Approach

Compare the submitted version (the record's `updatedAt`) with the stored one inside the update transaction and return 409 with a clear "changed by someone else" message; the admin runtime record page offers reload. Needs a per-module decision on which models carry a usable version.

## Acceptance Criteria

A stale PATCH returns 409 on every runtime module that exposes edit; the UI shows the conflict.

## Dependencies

None. Deferred out of TASK-0032 because it changes every runtime module's update contract; not required by any defect found.
