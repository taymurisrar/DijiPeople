# ITEM-0216 — Connection references for customization packages

## Summary

A package should be able to declare that it needs a connection (Microsoft Graph, Oracle, SMTP, webhook) by logical reference, with each environment binding its own credentials, never exporting them.

## Why It Matters

Integration-heavy packages cannot move between environments without re-keying credentials by hand.

## Evidence

Owner decision D-2 (2026-09-26): deferred until an integration consumes one. EXECPLAN-0052 §11 built environment variables, which cover URLs and single secrets.

## Proposed Approach

A `connectionReference` component type with a per-environment binding to an existing integration record, following the environment-variable split (definition travels, binding stays).

## Acceptance Criteria

An imported package that needs a connection is blocked until the target binds one; nothing secret is in the artifact.

## Dependencies

The first integration that consumes a package-declared connection.
