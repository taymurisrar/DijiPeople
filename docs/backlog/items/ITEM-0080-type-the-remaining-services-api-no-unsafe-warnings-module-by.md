## Why It Matters

The rule fires where a value's type does not promise anything, which is where the
compiler has stopped helping. That is not a style complaint — it is a report of
where a rename, a schema change or a wrong field name will compile and fail at
runtime instead.

The leave module proved the point in the most direct way available (see below).

## The worked example, and the method

`leave.service.ts` (93) and `leave.repository.ts` (21) were the largest
concentration before this pass. They held eight `(this.prisma as any)` casts,
written when `LeavePolicyAssignment` did not yet exist in the schema and left
behind after it did.

Removing the casts took the module to **zero** warnings — and the compiler
immediately reported **four real type errors** the casts had been hiding:

1. `createLeavePolicyAssignment(data: Record<string, unknown>)` — any shape at
   all could be handed to `prisma.create`.
2. and 3. `string | null` from a row against `string | undefined` from a DTO,
   in the two helpers that validate an assignment's scope. The code always
   treated both as "not set"; only the types disagreed.
4. `.filter(Boolean)` — which removes nulls at runtime and leaves them in the
   type, so every read in the comparator below it was on a possibly-null value.

None of those were found by reading. They were found by deleting a cast.

**The method, therefore:**

1. Find the `any` at its **source** — usually a cast on the Prisma client, an
   untyped repository parameter, or a `Record<string, unknown>` standing in for a
   Prisma input type.
2. Replace it with the real type (`Prisma.<Model>UncheckedCreateInput` and
   friends).
3. Fix what the compiler then reports. That is the yield.
4. Re-run the module's tests, lower the CI ratchet, commit per module.

Do **not** add casts to silence a warning. A cast moves the problem and loses the
four errors above.

## Proposed Approach

By module, largest first, one commit each: payroll-operations, platform-runtime,
prisma.service, then the spec files — which are lower risk and mostly want a
typed test-double rather than `as any`.

`prisma.service.ts` (33) is worth taking early despite its size: it is where the
untyped client originates, so typing it may reduce several dependents at once.

## Acceptance Criteria

- `--max-warnings` in `.github/workflows/ci.yml` is lowered every time a module
  lands, and never raised.
- No warning is silenced with an `eslint-disable`, a rule change, or a new cast.
- Every type error the removal surfaces is fixed, not suppressed — and any that
  turns out to be a defect gets its own bug record, as [[BUG-0668]] and
  [[BUG-0669]] did.
