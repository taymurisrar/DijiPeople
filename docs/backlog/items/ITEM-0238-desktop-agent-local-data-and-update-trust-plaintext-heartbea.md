# ITEM-0238 — Desktop agent local data and update trust: plaintext heartbeat queue, unsigned builds

## Summary

Two desktop agent weaknesses found while reviewing the agent for SESSION-0137, both by reading source; neither has been exercised on a device.

1. **The offline heartbeat queue is plaintext on disk.** `src/main/offline-queue.ts` writes `heartbeat-queue.json` in the Electron `userData` directory as plain JSON. A heartbeat carries `windowTitle` when window-title tracking is on (`src/main/types.ts`), which can contain document names, email subjects or similar. The refresh token is handled properly (OS credential vault through `keytar`), the queue is not. The queue is size-bounded and its events are normalised, which limits volume but not sensitivity.
2. **Builds are unsigned today**, so the Windows publisher cannot be verified by the user or by SmartScreen, and `electron-updater` has no publisher signature to check. Integrity then rests on the update feed's file hashes over HTTPS. `allowDowngrade` is already `false`, which protects against rollback to an older build. Signing is a drop-in once a certificate exists (`electron-builder.yml`; see [[ITEM-0026]]).

## Why It Matters

The agent runs on employees' own machines. Another local user or malware reading the userData directory sees the queued window titles. An unsigned installer trains users to click through a warning and gives an attacker who can alter the feed or a download a path that no signature would catch.

## Evidence

`apps/agent-desktop/src/main/offline-queue.ts` (`writeFile(..., "utf8")` to `userData/heartbeat-queue.json`); `src/main/secure-store.ts` (keytar for the refresh token only); `src/main/update-manager.ts` (`allowDowngrade = false`, `autoDownload = true`); `electron-builder.yml` comment block on signing. No device run.

## Proposed Approach

Needs a plan and a Windows device. For the queue: encrypt at rest with Electron `safeStorage` (DPAPI on Windows), keeping a migration path for an existing plaintext file, and decide whether window titles should be queued at all when the device is offline. For updates: obtain a signing certificate (a commercial decision), then enable publisher verification in the updater. Both belong in the same release as [[ITEM-0234]] and [[ITEM-0235]].

## Acceptance Criteria

- The heartbeat queue file is not readable as JSON by a process outside the agent, shown on a Windows device.
- An existing plaintext queue is migrated or discarded without losing queued events silently.
- A signed installer reports a verified publisher, and the updater refuses an update that is not signed by it.
