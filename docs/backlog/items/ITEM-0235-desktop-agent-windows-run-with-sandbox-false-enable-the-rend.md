# ITEM-0235 — Desktop agent windows run with sandbox:false; enable the renderer sandbox

## Summary

All three `BrowserWindow`s in `apps/agent-desktop/src/main/main.ts` (lines 132, 455, 500) set `sandbox: false`, alongside `contextIsolation: true` and `nodeIntegration: false`. The renderer therefore runs unsandboxed. Enabling the sandbox is current Electron guidance and limits what a renderer compromise could reach.

## Why It Matters

Today the windows load only bundled local pages, so there is no remote content to exploit and the risk is low. But a defect in the preload or a future change that loads remote content would land in an unsandboxed renderer on an employee's machine. Several Electron advisories (the ones in ITEM-0234) are sandbox-related and are mitigated when the sandbox is on.

## Evidence

`apps/agent-desktop/src/main/main.ts` lines 130–132, 453–455, 498–500. `preload.ts` must be checked for any Node API beyond what a sandboxed preload may require.

## Proposed Approach

Enable `sandbox: true` per window, confirm `preload.ts` only uses `contextBridge` and `ipcRenderer`, and verify login, permissions and location windows on a real device. Do it together with [[ITEM-0234]].

## Acceptance Criteria

- All three windows set `sandbox: true`.
- `preload.ts` loads and exposes its bridge in a sandboxed renderer on Windows.
- Login, device-permission and location windows work on a real device.

## Dependencies

None hard; best with [[ITEM-0234]].
