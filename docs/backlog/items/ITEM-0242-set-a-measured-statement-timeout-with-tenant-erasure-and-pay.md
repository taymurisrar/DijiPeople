# ITEM-0242 — Set a measured statement_timeout with tenant-erasure and payroll exemptions, and report worker lastTickAt in readiness

## Summary

BUG-3195 and BUG-3198 were closed with deliberate residuals. The pool now bounds its connect wait (`pool-config.ts`) and `GET /api/health/ready` probes the database, but (1) no `statement_timeout` is set by default, so a single runaway query can still hold a connection until Postgres or the network ends it, and (2) readiness does not report each worker's `lastTickAt`, so a stalled outbox or report scheduler is still invisible.

## Why It Matters

A runaway query is the remaining way one slow operation can exhaust the pool. The audit (RES-01) said to set the timeout only after measuring, because a blanket value would fail long operations that currently succeed slowly. A silent worker stall is undetectable from the health surface.

## Evidence

- `services/api/src/common/prisma/pool-config.ts` — `statement_timeout` only applies when `DATABASE_STATEMENT_TIMEOUT_MS` is set; `pool-config.spec.ts` asserts it is never defaulted.
- `services/api/src/common/health/readiness.ts` — the report carries only a `database` check.
- Audit RES-01 and RES-04 in `docs/engineering/audits/2026-09-10-full-technical-audit/raw/RES.md`.

## Proposed Approach

Measure the p99 duration of statements in production, choose a default, and apply it per connection. Exempt the tenant erasure (about 120 s transaction) and the payroll calculation explicitly, for example through a separate pool or `SET LOCAL statement_timeout` inside those transactions. Add per-worker `lastTickAt` to the readiness report. Needs an owner decision on the value and a measurement window; not an ExecPlan unless the exemptions need a second pool.

## Acceptance Criteria

- A documented default `statement_timeout` is in effect in production and a spec proves the two exempted operations are not subject to it.
- `/api/health/ready` reports `lastTickAt` for each enabled worker and answers 503 when one is stale beyond a multiple of its poll interval.

## Dependencies

Production statement-duration measurements.
