# ITEM-0187 — Custom-module list views filter only the loaded page and the data API has no filtering or search

## Summary

Published custom modules now render with the standard runtime list page
([[BUG-3494]]). A published view's filters are applied in the browser to the
page of records already loaded, because `GET /data/<key>` accepts no filter or
search. A view such as "Active QA Assets" therefore shows only the matching rows
of the current page, and the page total ignores the filter. Search has nothing
to search on the server.

## Why It Matters

Once a custom module holds more than one page of records, a filtered view is
wrong: records that match are missing, and the count misleads. This is the same
single-page-then-filter-in-the-browser defect class REG-470 fixed for lookups.

## Evidence

- `apps/web/app/components/runtime/standard-module-list-page.tsx` filters
  records client-side for custom-module specs.
- `services/api/src/modules/data/custom-data.service.ts` and
  `services/api/src/modules/data/data.controller.ts` — the custom-record list
  takes paging but no filter or search parameters.
- `apps/web/lib/runtime/custom-modules/custom-module-runtime.ts` builds views
  from `filtersJson` and `sortingJson` for the client.
- `docs/tasks/TASK-0031-streams/WP-02-report.md`, "Residual risks and open
  items".

## Proposed Approach

Add server-side filtering, sorting and search to the custom-record list, driven
by the published view definition and bounded to published columns, keep every
query tenant-scoped from `request.user`, and have the runtime page send the view
and search to the API instead of filtering in the browser. Likely an ExecPlan
under `PLANS.md`, because it defines a query contract over tenant-defined
columns.

## Acceptance Criteria

- A view filter returns every matching record across all pages, with a correct
  total.
- Search on a custom-module list returns matches beyond the first page.
- The filter and search accept only published columns; anything else is 400.
- A DB-backed spec proves tenant scoping of the filtered query.
