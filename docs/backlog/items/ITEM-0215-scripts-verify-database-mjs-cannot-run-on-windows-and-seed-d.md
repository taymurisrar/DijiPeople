# ITEM-0215 — scripts/verify-database.mjs cannot run on Windows and seed:demo runs out of memory at the default heap

## Summary

The documented local recipe for the database e2e suites
(`docs/development/database-e2e-reproduction.md`) fails on Windows at
`node scripts/verify-database.mjs` → "Prisma generate": it calls
`execFileSync('npm', …)` without a shell, which Windows cannot spawn. Separately,
`npm --workspace api run seed:demo` runs out of memory under ts-node at the
default Node heap.

## Why It Matters

Every developer and agent on Windows falls back to running the steps by hand,
and the demo seed needs `NODE_OPTIONS=--max-old-space-size=8192`. CI (Linux)
is unaffected.

## Evidence

ITEM-0200 subagent run, 2026-09-26: `verify-database.mjs` failed at Prisma
generate; its steps were run manually (migrate deploy, seed:config,
seed:verify, seed:demo with an 8 GB heap, seed:admin).

## Proposed Approach

Spawn npm through its CLI script beside the running Node (the
`npmCliPath` pattern in `scripts/check-production-advisories.mjs`), and give
`seed:demo` an explicit heap in its npm script or the recipe.

## Acceptance Criteria

`node scripts/verify-database.mjs` completes on Windows; the recipe's seed
steps run without a manual heap flag.

## Dependencies

None.
