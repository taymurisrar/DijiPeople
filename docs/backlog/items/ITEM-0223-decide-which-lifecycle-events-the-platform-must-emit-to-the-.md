# ITEM-0223 — Decide which lifecycle events the platform must emit to the Events stream

## Summary

The Events tab in Platform admin, Monitoring, and the overview's 24-hour event
context, are almost empty. Either very little has happened, or lifecycle
emission is incomplete. The product needs to decide which lifecycle events the
platform must emit, so that the stream can be trusted to be empty when nothing
happened.

## Why It Matters

An empty event stream reads as "all quiet" whether or not anything happened.
Operators cannot tell those two cases apart, so the tab has no diagnostic value.

## Evidence

Production, read-only query on 2026-10-07:

- `PlatformEvent`: 138 rows ever, 4 in the last 14 days, and 0 `FAILED` in the
  last 14 days.
- No event from the landing site since 2026-09-04.
- Historical failures: `STRIPE_WEBHOOK_PROCESSED` `FAILED` 24 times between
  08-24 and 08-30, and `TENANT_ERASURE_FAILED` twice on 08-15.
- `OutboxEvent`: 30 rows, all `PROCESSED`. The last one is from 2026-08-30.

## Proposed Approach

List the lifecycle transitions that matter to operations: signup, checkout,
provisioning, subscription changes, payment failures, erasure, release publish,
and so on. Mark each as required or optional. Then audit which ones the code
emits today. Missing required emissions become bugs. This needs a short decision
record, not an ExecPlan.

## Acceptance Criteria

- A decided list of required platform lifecycle events exists, as an ADR or in
  this item.
- Each required event is confirmed emitted, or has a bug record.
