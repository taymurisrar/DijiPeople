# ITEM-0249 — API production build needs more than 3 GB V8 heap; Render build headroom unverified

## Summary

`nest build` of the API fails with a V8 heap out-of-memory below about 4 GB: 1.5, 2 and 3 GB all failed, 4 GB passed (the Node 22 default on a 31 GB machine). CI needed `NODE_OPTIONS=--max-old-space-size=6144` earlier in this programme. `render.yaml` sets no NODE_OPTIONS for the API build, and the Render build machine memory is not recorded in the repo, so a production deploy of the current tree is not known to build.

## Why It Matters

A build that dies on Render leaves production on the previous release with no code path to ship a fix, including a hotfix. The headroom shrinks with every module added.

## Evidence

`docs/programs/dp-master/evidence/api-build-memory.md` (measured 2026-11-28, Node 22.23.4, other node processes were running so peak RSS is unreliable; the OOM outcomes are not). CI: Build job raised via NODE_OPTIONS in `.github/workflows/ci.yml`.

## Proposed Approach

Check the live Render build instance memory and the last successful production build log; then either set NODE_OPTIONS in the Render buildCommand (registered per the env-variable rules) or reduce type-check cost (project references / split the build). `check-env-registered` pins the API build script, so do not edit the script itself.

## Acceptance Criteria

- A production-equivalent build of the release candidate succeeds on the Render build instance, evidenced by its build log.
- The heap setting, if any, is in `render.yaml` and `docs/environment-variables.md`.
