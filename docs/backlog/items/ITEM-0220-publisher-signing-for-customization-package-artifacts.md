# ITEM-0220 — Publisher signing for customization package artifacts

## Summary

Artifacts carry sha256 checksums, which prove integrity only. Publisher trust needs signatures: the manifest reserves `signature`, and format 1 refuses a signed artifact rather than pretending to verify it.

## Why It Matters

A marketplace, or packages from third parties, need to prove who published them.

## Evidence

`services/api/src/modules/customization/package-artifact.ts` — `signature: null`, and the parser refuses a non-null one.

## Proposed Approach

Sign the contentChecksum with a publisher key; register publisher public keys per tenant or platform; a new format version.

## Acceptance Criteria

A tampered or unsigned package from a trusted publisher is refused; the UI distinguishes "integrity verified" from "trusted publisher".

## Dependencies

Publisher key management.
