# ITEM-0189 — Custom-module lookup fields that target system entities have no options source

## Summary

Custom modules can now carry Reference (lookup) fields, since [[BUG-3492]] was
fixed, and render in the runtime, since [[BUG-3494]]. When a Reference field
targets a system entity such as Employees, the runtime form receives the target
but no options source, so the lookup control cannot list or search the records
it should offer.

## Why It Matters

A lookup to Employees is the most common field a custom module needs ("Assigned
Employee"). Without options it cannot be filled, which blocks the main use of
custom modules the two fixes above unblocked.

## Evidence

- `apps/web/lib/runtime/custom-modules/custom-module-runtime.ts` maps field types
  and targets for the runtime spec without an options source for system-entity
  targets.
- `docs/tasks/TASK-0031-streams/WP-02-report.md`, "Residual risks and open
  items": "Lookup fields to system entities get a target but no options source."

## Proposed Approach

Resolve a Reference field's target to the existing entity lookup source the
standard runtime already uses (the searchable, paged lookup that REG-470 wired),
keeping the target entity's own permissions and tenant scope. No new endpoint if
the existing lookup route covers the target entities. No ExecPlan needed.

## Acceptance Criteria

- A custom-module Reference field targeting Employees lists and searches
  employees the user may read, across more than one page.
- The saved value displays the employee's name on the record and in the list.
- A user without read access to the target entity gets no options, not an error
  modal.
