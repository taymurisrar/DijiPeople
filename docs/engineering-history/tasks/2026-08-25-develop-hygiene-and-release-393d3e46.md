## The primary checkout, and why nothing was discarded

`develop` in the user's checkout was **41 commits behind** and could not
fast-forward: two files were uncommitted there, and `origin/develop` had moved
past one of them.

- `apps/landing/next-env.d.ts` — generated by `next dev`, which rewrites the
  import paths that `next build` writes differently. The file's own text says it
  should not be edited, and no incoming commit touched it, so it never blocked
  anything.
- `services/api/prisma/seed-legal.ts` — the actual blocker. It carried a shorter
  header comment than `develop` does, and `2852855e` had moved past it. It
  **looked** superseded, but it matched no commit on any branch, so that was an
  inference and not a fact.

Both were committed to `preserve/primary-dirty-2026-08-25` and pushed **before**
anything else touched the checkout. Discarding them would have been the
convenient reading of an inference; the framework's own precedent is the
`preserve/*` branches that already exist for exactly this.
