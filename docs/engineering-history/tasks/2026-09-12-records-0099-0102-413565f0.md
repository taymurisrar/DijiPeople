## Conflict Resolutions

- **Generated indexes, every time: take ours, then regenerate.** The alternative,
  hand-merging the hunks, produces an index that matches neither branch and fails
  its own check on the next run.
- **The regression register: stop merging it textually.** Take our copy verbatim,
  read the incoming branch's copy with `git show`, and append only whole blocks
  we do not already hold — keyed on id as well as body, so a stale copy of an
  existing entry is not mistaken for a new one. Continuing to resolve its markers
  had already cost one entry's body; the append approach cost nothing after it
  was adopted.
- **Regression-id collisions: the earlier-merged claimant keeps the id**, and the
  incoming entries renumber onto free ids with every citing record repointed.
  Keeping the already-merged ids meant commit messages already on the branch
  stayed true.
- **ADR and ExecPlan collisions: renumber by ownership, never by guess.** 47
  references across 21 files were repointed by working out which stream owned
  each citing record. An automated rewrite would have picked one decision for a
  bare `ADR-0009` that could have meant any of three.
- **The two-halves bug records: merge both accounts into one.** Taking either side
  would have published a record wrong about the state of its own fix. BUG-3331's
  stitched text then claimed FIXED while its prose said "not done"; the backlog
  validator refused it, and it was rewritten rather than reworded around.
- **The shared-runtime invariant: fix the code, not the test.** Sent back to the
  employee stream, which moved the component behind the shared folder
  convention the file already used for documents, and moved the routes behind
  the data adapter. Weakening the spec would have let the shared renderer grow an
  undeclared dependency on one module.
